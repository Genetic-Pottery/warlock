These CONTENTS constitute the entirety of `thread.rs`, a Rust source file implementing warlock's chat conversation model for its TUI panel. It opens with an extensive module-level doc comment explaining the conceptual design: the panel has three cards (ledger/account, file/document, thread/conversation), and this file implements the third — the conversation between the reader and the model. It explains that a conversation is an ordered list of "entries," most of which are "turns" (one per typed message, holding the message, observed work, and the answer) with the rest being "notes" (single lines warlock says itself). Key design points documented: the module is plain data with no clock of its own (all timing driven by an injected `Instant`); turns share clock semantics with the account's `Log` type; work lines are constrained to tool name/detail, "thinking," or "writing" with no tool results, reasoning, or partial answers exposed; a pact/run belongs to the account card, not this one; notes are unclocked, single-line, and don't affect turn state; synthesized instructions (e.g., `/brief`) are shown as turns using the command text rather than the full generated prompt (though this feature isn't yet implemented, only allowed for); a turn's cost is heard and discarded (unlike the account, which totals costs); and a turn ends via either an answer or an `Ending` value (never an error).

The code itself defines:

1. **`Ending`** enum — five variants (`Cancelled`, `NoModel`, `Failed`, `TimedOut`, `NothingSaid`, `Broke`) representing ways a turn can end without an answer, each with doc comments explaining rationale. Implements `.line()` producing exactly one human-readable line per variant (with a doctest example), used both inline in the thread and in a footer elsewhere.

2. **`ending_for`** — a free function mapping `warlock_engine::agent::Error` variants to `Ending` variants, noting the source enum is `#[non_exhaustive]` so unknown variants fall through to `Ending::Broke`.

3. **`Turn`** struct — private fields `message`, `log` (a `Log`), `answer` (`Option<String>`), `ending` (`Option<Ending>`). Public accessors `message()`, `answer()`, `ending()`, `started()`, `is_closed()`. Private helpers: `line_count()`, `rows(now)` (yields message lines, then log rows, then answer lines), `freeze(at)`, `live()` (returns `Some` only if not closed), `word(ending, at)` (closes the turn with one line, used by both explicit endings and the empty-answer case).

4. **`Entry`** private enum — `Turn(Turn)` or `Note { text, at }`, unifying turns and notes into one ordered sequence. Has `at()`, `line_count()`, `rows(now)` (boxed iterator), `turn()`, `turn_mut()`.

5. **`Thread`** struct — the main public type, wrapping `entries: Vec<Entry>`. Public API: `new()`, `ask(message, at)` (freezes prior turn, opens new one), `note(text, at)` (flattens to one line, doesn't touch turn state), `record(activity, at)` (routes `Activity` variants to log entries or drops cost), `answer(answer, at)` (closes turn, or ends with `NothingSaid` if blank), `end(ending, at)`, `turns()` (filters out notes), `is_empty()`, `started()`, `in_flight()` (newest turn if still open), `line_count()`, `lines(now)`, `window(offset, height, now)`. Private helpers: `last_turn()`, `last_turn_mut()`, `freeze_last(at)`, `live()`. Includes a doctest demonstrating basic usage.

6. Two free helper functions: `broken(text)` (splits text into display lines, guaranteeing at least one empty-string row for empty text) and `one_line(text)` (collapses whitespace runs into a single-line string, used for flattening notes and stderr).

7. A large `#[cfg(test)] mod tests` block containing ~25 unit tests plus helper functions (`at`, `tool`, `said`, `work`). Tests verify: empty conversation behavior; full turn rendering (question/work/answer); the "waiting" placeholder before any activity; live-clock ticking vs. freezing on answer; per-turn clock resets; collapsing of repeated "thinking" activity into one line unless interrupted; bare tool names without details; that cost activity is heard but never drawn (compared directly against the account card's money-drawing behavior); that no tool result or model reasoning ever reaches a work line; that answers are stored whole/unwrapped but still split into rows by embedded newlines; cancellation behavior; each `Ending` variant's exact wording; empty-answer handling as `NothingSaid`; first-ending-wins/no-further-mutation-after-close semantics; that nothing can be filed before the first question; multi-line messages; `window()` behavior including out-of-range requests; that a pact/run happening concurrently via `Account` is entirely invisible to `Thread`; note placement between turns (including window-slicing across notes); notes as one unclocked non-turn row (including flattening of multi-line notes); notes not opening/closing/freezing a turn; and mapping of every `agent::Error` variant to the correct `Ending` via `ending_for`.
