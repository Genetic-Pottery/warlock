This is the entirety of a Rust source file that translates raw keyboard and mouse events into the application's intentions, plus an extensive test suite for that translation.

The file opens with a module-level doc comment explaining the overall design: pure translation functions with no terminal interaction, split between the older keyboard/mouse pair (`action_for`, `mouse_action`) and a newer function (`press_for`) that additionally handles windows drawn over the frame (a quit confirmation, a scope prompt, a write prompt, and a composer for chat input).

**Imports**: from `ratatui::crossterm::event` (`KeyCode`, `KeyEvent`, `KeyEventKind`, `KeyModifiers`, `MouseButton`, `MouseEvent`, `MouseEventKind`), `ratatui::layout::Size`, and from `warlock_tui`: `Answered`, `App`, `Composed`, `Composer`, `Edited`, `Focus`, `Hit`, `QuitConfirm`, `ScopePrompt`, `answer_for`, `compose_for`, `edit_for`, `hit_test`.

**Public-in-crate (`pub(crate)`) enum `Action`**: variants `Quit`, `CancelPact`, `ToggleFocus`, `SelectPrevious`, `SelectNext`, `SelectPageUp`, `SelectPageDown`, `SelectFirst`, `SelectLast`, `ToggleCollapsed`, `TogglePactedOnly`, `ToggleFiles`, `TogglePact`, `Refresh`, `OpenScope`, `ViewFile`, `EditFile`, `SwapCard`, `ToggleMouseCapture`. Each has a substantial doc comment explaining its rationale and interaction rules (e.g. mid-run refusal behavior, mnemonic key bindings).

**Function `pub(crate) fn action_for(key: KeyEvent, in_flight: bool) -> Option<Action>`**: pure translation of a key press into an `Action`, given whether a pact run is in flight. Filters to `KeyEventKind::Press` only. Handles Ctrl-C → `Quit`, Esc → `CancelPact` if in_flight else `Quit`, `q` → `Quit`, `Tab` → `ToggleFocus`, `BackTab` → `SwapCard`, arrows/`j`/`k` → select prev/next, PageUp/PageDown, `g`/`G` → first/last, space → `ToggleCollapsed`, `o` → `TogglePactedOnly`, `f` → `ToggleFiles`, `p` → `TogglePact`, `r` → `Refresh`, `s` → `OpenScope`, `v` → `ViewFile`, `e` → `EditFile`, `m` → `ToggleMouseCapture`.

**Enum `pub(crate) enum Pressed`**: variants `Leave`, `CancelTurn`, `Confirm(QuitConfirm)`, `Scope(Edited)`, `Write(Edited)`, `Compose(Composed)`, `Act(Action)`, `Nothing`. Represents what a keystroke resolves to after passing through the gate logic (quit confirmation, scope prompt, write prompt, composer).

**Private function `fn is_ctrl_c(key: KeyEvent) -> bool`**: checks for Ctrl-C.

**Private function `fn is_tab(key: KeyEvent) -> bool`**: checks for Tab code regardless of event kind.

**Function `pub(crate) fn press_for(key: KeyEvent, confirm: QuitConfirm, prompt: &ScopePrompt, write: &ScopePrompt, composer: Option<&Composer>, in_flight: bool, answered: bool) -> Pressed`**: the main gate function, with a long doc comment describing its precedence order (Ctrl-C first, then quit question, then scope prompt, then write prompt, then composer, then ordinary keys via `action_for`). Implementation checks `is_ctrl_c` first, then `confirm.highlighted()` (routes to `answer_for`, mapping `Answered::Open`, `Answered::Close`, `Answered::Leave`), then `prompt.field()` (routes to `edit_for`, wrapped as `Pressed::Scope`), then `write.field()` (routes to `edit_for`, wrapped as `Pressed::Write`), then `composer` if present and key is not Tab (checks `draft.is_muted()` → `Pressed::Nothing`, else routes to `compose_for` wrapped as `Pressed::Compose`), finally falls through to `action_for`, converting `Action::Quit` into `Pressed::Confirm(QuitConfirm::open())` when not in flight, or `Pressed::Leave` when in flight, and wrapping other actions as `Pressed::Act`.

**Constant `const WHEEL_NOTCH: usize = 3`**: private, number of rows/lines one wheel notch moves.

**Enum `pub(crate) enum MouseAction`**: variants `SelectNextBy(usize)`, `SelectPreviousBy(usize)`, `ScrollPanelDown(usize)`, `ScrollPanelUp(usize)`, `SelectRow(usize)`, `ToggleCollapsed`, `Focus(Focus)`.

**Function `pub(crate) fn mouse_action(mouse: MouseEvent, size: Size, app: &App, confirm: QuitConfirm, prompt: &ScopePrompt, write: &ScopePrompt, composer: Option<&Composer>) -> Option<MouseAction>`**: returns `None` if any of confirm/prompt/write is open; otherwise computes `header` via `app.run_header()`, does `hit_test(mouse.column, mouse.row, size, composer, header.as_ref())`, then dispatches on `mouse.kind`: `ScrollDown`/`ScrollUp` go through private helper `wheel`, `Down(MouseButton::Left)` goes through private helper `click`, everything else returns `None`.

**Private function `fn wheel(hit: Hit, tree: MouseAction, panel: MouseAction) -> Option<MouseAction>`**: matches `Hit::TreeHeader | Hit::TreeRow{..} | Hit::TreeBelowRows` → `tree`; `Hit::PanelHeader | Hit::PanelLine{..}` → `panel`; `Hit::Composer | Hit::Footer | Hit::Border | Hit::Offscreen` → `None`.

**Private function `fn click(hit: Hit, app: &App) -> Option<MouseAction>`**: for `Hit::TreeRow{offset}`, computes `index` via `app.scroll_offset()` + offset, compares to `app.rows().len()` and `app.selected()`, returning `Focus(Focus::Tree)`, `ToggleCollapsed`, or `SelectRow(index)` accordingly; `Hit::TreeHeader | Hit::TreeBelowRows` → `Focus(Focus::Tree)`; `Hit::PanelHeader | Hit::PanelLine{..}` → `Focus(Focus::Panel)`; `Hit::Composer` → `Focus(Focus::Composer)`; `Hit::Footer | Hit::Border | Hit::Offscreen` → `None`.

**Test module `#[cfg(test)] mod tests`**: extensive unit tests for `action_for`, organized around each keybinding (quit, esc-cancels-pact, focus toggle, movement keys, collapse, filters, pact/refresh/scope/view/edit keys, swap card, mouse toggle), verifying press-only semantics (ignoring releases/repeats), case-sensitivity, and non-interference between bindings.

Within `tests`, a nested private module **`mod gate`** tests `press_for` (aliased as `gate_for` in some helper contexts) in depth: helper functions `press_for` (wraps `gate_for` fixing write prompt closed), constants `SIZE`, `DIRECTORY`, `INERT` (list of 19 key codes swallowed by open windows), enum `Round` (`Stayed`, `Left`), helper functions `press`, `ctrl_c`, `app_on_screen`, `app_in_use`, `round`, `offered`, `round_under`, `round_composing`, `round_running` (the last five simulating the event loop's key-handling arms, panicking on keys that should never reach the app from behind a window). Tests cover: quit confirmation gating, Ctrl-C behavior (leave vs cancel-turn), scope prompt precedence, ordering among Ctrl-C/question/prompt/composer/keys, releases/repeats being inert.

Nested further inside `gate`: **`mod writing`** tests the write prompt specifically (constants `PROPOSED`, `HEADING`, helper functions `open`, `field`, `asked`), verifying it behaves like the scope prompt, respects precedence when both prompts are open, and resumes normal key meaning once closed.

Also nested in `gate`: **`mod composing`** tests the composer's key handling (constant `TYPED`, helper functions `app_composing`, `types`, `acts`), verifying letters like `p`, `r`, `s`, `v`, `e`, `f`, `g`, `G`, `j`, `k` type into the draft while composing and act as commands otherwise, that Tab and Ctrl-C bypass muting, that a muted composer swallows all other keys, that Esc hands keyboard back without cancelling a run, and that draft state survives focus cycling and run completion.

Finally, a separate top-level nested module **`mod pointer`** (sibling to `gate`, inside `tests`) tests `mouse_action` and its integration into a simulated event loop round. It defines constants (`SIZE`, `IN_TREE`, `IN_PANEL`, `FIRST_TREE_ROW`, `FIRST_PANEL_LINE`, `TREE_HEADER`, `FOOTER`), helper functions `viewport`, `wheel_down`, `wheel_up`, `left_click`, `event`, `rows`, `app_on_screen`, `asks`, `round`, `round_under`. Tests cover wheel scrolling of tree vs panel based on pointer position (not focus), clamping at list ends, left-click selecting/focusing/toggling collapse on second click, clicks on footer/borders doing nothing, non-relevant mouse event kinds being dropped, and the pointer being inert while any of the three windows (confirmation, scope prompt, write prompt) is open.
