This is the sole part of `app.rs`, the front-end state module of Warlock's TUI crate. It has two sections: an extensive set of doc comments and implementation (roughly the first half) and a large `#[cfg(test)] mod tests` block (the remainder).

**Core purpose:** `App` holds everything the TUI needs between keystrokes, flattening the engine's tree walk into a linear list of `Row`s for screen drawing, since the renderer draws a list but the engine models a tree.

**Key types defined:**
- `Row` — one flattened row: depth, path, optional document, `NodeState`, child count, and flags for whether it's a file, is itself the directory's own `WARLOCK.md` document, is excluded by `.warlockignore`, and its own scope label. Built via `Row::new`/`Row::file` plus builder methods (`with_child_count`, `with_ignored`, `with_document_row`, `with_scope`).
- `PactToggle` — what a pact-key press asks a caller to carry out (path + whether now pacted).
- `Run` (enum: `Pact`/`Refresh`) and `InFlight` — describes a background pact/refresh run's progress (directory, position, high-water "reached" mark, total, kind).
- `RunHeader` — a read-only snapshot of `InFlight` spelled out for the panel header.
- `Summarising` — tracks a chunked summarization pass over one large file inside a running pact.
- `Focus` (enum: `Tree`/`Panel`/`Composer`) — which of three screen areas keystrokes drive, with `next()`, `drives_the_tree()`, `drives_the_panel()`.
- `Sigils` (enum: `Nothing`/`Held(Vec<String>)`/`Unknown`) and `Chrome` — the header line's machine-held-sigils state and the tree-identity header text; explicitly *not* part of `App` since they're resolved once per session.
- `App` itself — nine fields split conceptually into tree-related state (`all_rows`, `rows`, `collapsible`, `counts`, `selected`, `scroll_offset`) and three grouped structs: `Viewpoint` (collapsed set, pacted-only flag, show-files flag, viewport height, focus — all reader-chosen view state that survives reloads), `Status` (message, in-flight run, summarising, pact-refused flag, mouse-captured — short-lived per-keystroke/per-run state), and `Panel` (three `Card<T>` slots — account, thread, document — each with its own scroll offset/follow flag, plus panel height/width and which card is `Showing`).
- `Card<T>`, `Shown` trait, and `Showing` enum — generic windowing logic for the panel's three cards (account/thread/document), each independently scrollable and independently able to "follow" its newest line.

**Major behaviors implemented on `App`:** building from a `Tree` or bare `Row`s (`from_tree`, `from_rows`, `with_collapsed`, `with_counts`); message and pact-progress state management; account/thread/document lifecycle (`start_account`, `write_run`, `show_document`, `refill_document`, `start_turn`, `record_turn`, `answer_turn`, `end_turn`, `swap_card`); panel geometry and scrolling; row-collapse and pacted-only/show-files view filters (`toggle_collapsed`, `toggle_pacted_only`, `toggle_files`) all funneling through a central `reflow()`; selection/scrolling movement methods (`select_next`, `select_page_up`, `select_row`, wheel-style `select_next_by`, etc.) that respect `Focus`; pact/refresh/scope/view key handlers (`toggle_pact`, `refresh`, `scope_target`, `view_target`) each refusing certain row types with specific worded messages; `set_subtree_state` for repainting a pacted subtree (including its file rows) while respecting `.warlockignore` exclusion rules differently for pacting vs. unpacting; `insert_file_row` for splicing in a newly-written document row mid-pact-run without a full tree reload; and free functions `reseat_on` (rebuilds an `App` on a freshly reloaded `Tree` while preserving all reader-chosen view state) plus pure helper functions (`walk_of`, `node_rows`, `paint_subtree`, `moves_with_subtree`, `in_subtree`, `drawn_rows`, `pacted_rows`, `index_for`, `scroll_offset_for`, `panel_offset_for`, `file_row_position`) and numerous private message-wording functions (e.g., `pacting_message`, `already_fresh_message`, `ignored_row_message`, `cut_at_cap_message`).

**Test module:** an extensive suite (the majority of this file's line count) covering flattening, selection/scrolling arithmetic, collapse/expand, the pacted-only and show-files filters, pact/unpact/refresh/scope/view key refusals and effects, `.warlockignore` interactions, scopes, focus cycling, panel windowing/following for all three cards, thread/conversation turns, run-in-flight progress and summarizing lines, re-seating onto a reloaded tree, and mid-run file-row insertion — using shared fixtures (`fixture::tree()`, hand-built `Tree`/`Row` lists) rather than real I/O.
