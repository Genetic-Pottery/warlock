This is a Rust source module implementing `Account`, the data model behind a terminal panel that narrates what a "subtree pact" (a background AI run over a set of directories) has been doing, presented as an ordered, appendable ledger rather than a live terminal stream.

**Module-level doc comment** explains the design rationale: the account is an ordered list of `Section`s (one per directory reached), each holding an ordered list of lines (one per observed activity). It is plain data with no terminal, channel, or clock access of its own — all time is supplied by callers as `Instant` values, never read internally (this is emphasized as what makes the module deterministically testable). Key design points documented: each section's clock resets to `0:00` when it opens; the newest line's clock is a *live* function of a caller-supplied `now` until a newer line arrives, at which point it freezes at that arrival instant; an empty section shows a synthesized (not stored) `waiting` placeholder line; the module deliberately excludes file contents, model prose, tool results, thoughts, tokens, cache stats, turn counts, API durations, and truncation (the last being the drawing layer's job).

**Constants**: `THINKING = "thinking"`, `WAITING = "waiting"`, `WRITING = "writing"` — the literal words used for these activity states.

**`Entry` struct** (private): one line's arrival `Instant` and its `String` text.

**`Outcome` enum**: how a directory's pass ended — `Wrote { document: PathBuf, bytes: u64 }`, `Refused { reason: String }`, or `Cancelled` (carries nothing). Has a `line(&self, cost: Option<f64>) -> String` method producing the closing line text, e.g. `"wrote {doc} — {bytes} bytes, {cost}"`, `"refused — {reason}"`, or `"cancelled — {cost}"`, using helper functions `spend`/`money` to render cost, distinguishing "no cost reported" from an actual zero.

**`Section` struct**: holds `directory: PathBuf`, `started: Instant`, `entries: Vec<Entry>`, `cost: Option<f64>` (accumulated, `None` if never reported), `closed: Option<Instant>`, and `has_outcome: bool`. Public accessors: `directory()`, `cost()`, `is_closed()`. Private methods: `line_count()` (entries or 1 for waiting, plus heading), `shown_at(index, now)` and `clock(index, now)` (the tick/freeze logic), `freeze(at)` (idempotent via `get_or_insert`), `extend_or_open(text, at)` (dedups consecutive identical lines like repeated "thinking" reports into one continuing line), and `word(outcome, at)` (appends the outcome line, dated at the section's freeze time or `at`, and freezes; no-ops if already has an outcome).

**`Line` enum**: the flat drawable row type — `Directory { path }`, `Clocked { clock: String, text: String }`, `Summary { text: String }`. Flat rather than nested for easy scroll-offset arithmetic.

**`Account` struct**: the top-level object with `started: Instant`, `sections: Vec<Section>`, `summary: Option<String>`. Includes a doctest example showing basic usage (`Account::new`, `open_section`, `record`, `lines`).

Public API methods:
- `new(at)` — empty account.
- `open_section(directory, at)` — freezes prior live section, pushes a fresh one.
- `record(activity: &Activity, at)` — routes `Activity::Cost` into section's accumulated cost (no line), `Thinking`/`Writing` into `extend_or_open`, `Tool { name, detail }` into a new entry formatted as `"{name} {detail}"` or bare `name`. No-ops if no live/open section.
- `close_section(outcome, at)` — words the newest section.
- `close_open_sections(at, outcome: impl FnMut(&Section) -> Outcome)` — words every section still lacking an outcome, skipping already-worded ones, calling the closure only for those needing one.
- `finish(at)` — freezes trailing live section, builds the summary line: `"pact finished — {n} directories, {clock}, {money}"`, appending `"(incomplete: {n} passes reported no cost)"` when any section never reported cost. Uses `plural()` helper.
- `sections()` — accessor.
- `open_section_started()` — returns `Some(Instant)` of the last section only if it's not yet closed, else `None`.
- `line_count()` — total drawable rows.
- `lines(now)` / `window(offset, height, now)` — full or sliced row rendering, via private `rows(now)` iterator that synthesizes the `waiting` line for empty sections, maps entries to `Clocked` lines, and appends the `Summary` line if present.
- Private `spent()` (sums known costs, folding from positive zero to avoid `-0.0`) and `unpriced()` (count of sections with no cost).

**Free functions**: `clock(Duration) -> String` (formats as `m:ss`, unpadded minutes, truncated not rounded), `money(f64) -> String` (`$X.XX`), `spend(Option<f64>) -> String` ("no cost reported" or `money`), `plural(count, one, many) -> String` (English singular/plural noun selection, e.g. "1 directory" vs "9 directories").

**Test module** (`#[cfg(test)] mod tests`): extensive unit tests using a deterministic `Instant`-based `at(base, seconds)` helper and a `said(account, now) -> Vec<String>` helper that renders lines as plain strings. Tests cover: empty account draws nothing; each section restarts its clock at zero; waiting-line ticking and replacement by first real activity; deduplication of repeated thinking/writing reports into one line, including re-opening after an interruption; the toolless-pass thinking→writing pattern; waiting lines freezing with their section; live newest-line ticking against varying `now`; a line freezing at the instant the next line arrives; a closed section never ticking again; `finish` freezing the still-live section; tool activity formatting with/without detail; cost recording producing no line and just accumulating; nothing being recorded when there's no live section (before first open or after close); outcome line wording for `Wrote` (with and without cost), `Refused`, `Cancelled`; summary line wording for multiple directories (plural), one directory (singular), and cost completeness/incompleteness (plural/singular pass wording); `close_open_sections` behavior — wording multiple stale sections dated at their own freeze times, and skipping sections that already have an outcome (with an `asked` tracking vector to confirm the closure isn't called for those); windowed row retrieval (`window` matching `lines`, mid-slice, past-the-end handling); `clock()` formatting edge cases (padding, minute overflow past 60, rounding-down of sub-second amounts); a `now` before the account's start reading as zero rather than panicking (via `saturating_duration_since`); and behavior of `open_section_started()` across opening, recording, closing, section handover, and `finish`.
