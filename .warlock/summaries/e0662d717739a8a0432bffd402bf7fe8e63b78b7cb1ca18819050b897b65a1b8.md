This is the sole part of `app.rs`, the front-end state module for Warlock's TUI. It defines the in-memory model that sits between the engine's tree and the terminal renderer, plus an extensive test suite. Key contents:

**Core data model**
- `Row`: a flattened representation of one line of the tree (path, document, `NodeState`, child count, whether it's a file, whether it's the directory's own `WARLOCK.md`, whether `.warlockignore` excludes it, and its own scope label), with builder methods (`new`, `file`, `with_child_count`, `with_ignored`, `with_document_row`, `with_scope`).
- `PactToggle`: what a pact-key press asks a caller to do (path + whether now pacted).
- `Run`/`InFlight`/`RunHeader`: represent a pact or refresh running in the background, its progress, and how the panel header states it.
- `Summarising`: an in-progress chunked summarization pass over one large file.
- `Focus` enum (`Tree`, `Panel`, `Composer`) governing what movement keys act on, with `next`, `drives_the_tree`, `drives_the_panel`.
- `Sigils`/`Chrome`: machine-held sigils and the read-only header line (repo-relative root path + sigils text), deliberately kept outside `App` since they never change during a session.
- `App` struct itself: flattened `all_rows`/`rows`, `collapsible` set, `StateCounts` tally, `selected`/`scroll_offset`, and three sub-groups: `Viewpoint` (collapsed set, pacted-only/show-files flags, viewport height, focus), `Status` (message, in-flight run, summarizing, refusal flag, mouse capture), and `Panel` (three `Card<T>` slots — account, thread/conversation, document — each with its own scroll window/follow flag, plus which is `Showing`).
- `Card<T>`/`Shown` trait/`Showing` enum: generic windowing logic over three different content types (`Account`, `Thread`, `Vec<Line>`), each implementing `line_count`/`window` via word-wrap (`rows_of`).

**`App` impl (large)**: constructors (`from_tree`, `from_rows`, `with_collapsed`, `with_counts`); message/status setters; pact/refresh progress tracking (`set_pact_in_flight`, `set_run_in_flight`, `set_pact_summarising`, `clear_pact_in_flight`, `set_pact_refused`, `pact_line`, `run_header`); panel card management (`start_account`, `write_run`, `show_document`, `refill_document`, `start_turn`, `record_turn`, `answer_turn`, `end_turn`, `swap_card`, `restore_from`); viewport/panel sizing; movement methods (`select_previous/next/page_up/page_down/first/last`, `select_row`, `select_next_by`/`select_previous_by`, `scroll_panel_down/up`) all funneling through a shared `movement`/`scroll_panel_to` helper; view toggles (`toggle_collapsed`, `toggle_pacted_only`, `toggle_files`, `toggle_pact`, `refresh`, `scope_target`, `view_target`); state-painting (`set_subtree_state`, `insert_file_row`).

**Free functions**: `reseat_on` (rebuilds an `App` on a freshly reloaded `Tree` while preserving view state by path rather than index), `walk_of`, `node_rows`, `paint_subtree`, `moves_with_subtree`, `in_subtree`, `drawn_rows`, `pacted_rows`, `index_for`, `scroll_offset_for`, `panel_offset_for`, `file_row_position`, and a large collection of `*_message` functions producing exact user-facing footer strings for refusals/status (e.g. `left_on_disk_message`, `pacting_message`, `unpacted_message`, `file_row_message`, `ignored_row_message`, `cut_at_cap_message`, `no_document_message`, etc.), plus `count_mut`.

**Tests module** (very large, majority of the byte count): exhaustive unit tests covering flattening, collapsing/expanding, pacted-only filtering, file-toggle, pact/refresh/scope/view key refusals and effects, scrolling/paging arithmetic for both tree and panel, focus cycling and composer visibility rules, panel card independence (account/thread/document each keeping separate windows and follow flags), run-in-flight/summarizing footer wording, reseat-on-reload behavior (including document/account/thread survival and selection-by-path fallback to nearest ancestor), and file-row insertion (`insert_file_row`) ordering/placement semantics. Test helper fixtures build small hand-constructed `Tree`/`Row` structures and rely on a `fixture` module (referenced but not defined in this excerpt) for a shared sample tree.
