This is the complete contents of a Rust source file (`writing.rs`) implementing the `/write` command's path proposal and file-writing logic for a TUI tool called warlock, along with its extensive test suites. It is presented as one part covering the whole file.

**Module-level doc comments** open the file, explaining the design in prose: the module has two halves — proposing a path (never fails, never writes) and actually writing the file (the one destructive/creative operation in the tool). Key concepts documented: reply unwrapping happens before title extraction; slugs are folded titles capped at ~60 chars; numbering scans all digit runs in a directory's filenames (not just warlock's own naming shape); paths resolve against the repository root; only two transformations are applied to written text (unfencing and trailing-newline normalization); missing template sections cause refusal; existing paths are refused rather than overwritten; and successful/failed writes produce specific conversation/footer lines.

**Constants** (all private, `pub(crate)` or module-private):

**Public/crate functions:**
- `proposed_path(repo_root: &Path, directory: &str, reply: &str) -> String` (`pub(crate)`) — builds the proposed relative path.
- `write_opened(repo_root: &Path, directory: &str, reply: &str) -> ScopePrompt` (`pub(crate)`) — opens the write prompt over a reply.
- `write_edit(app: &mut App, manifest: &Manifest, repo_root: &Path, prompt: &ScopePrompt, edited: Edited, now: Instant) -> ScopePrompt` (`pub(crate)`) — handles keystrokes in the write prompt.
- `write_submit(app: &mut App, manifest: &Manifest, repo_root: &Path, field: &ScopeField, now: Instant) -> ScopePrompt` (`pub(crate)`) — the Enter handler; validates path, reads the document off the conversation, checks template shape via `missing_sections`, writes via `put`, and reports lines via `app.note`.
- `unfenced(reply: &str) -> &str` (`pub(crate)`) — strips a whole-document code fence if present.
- `slug_of(document: &str) -> String` (`pub(crate)`) — derives filename slug from first `# ` heading.

**Test modules** (all `#[cfg(test)]`):
1. `mod tests` — tests `proposed_path`, `slug_of`, `unfenced`, `next_number`, using helpers `a_repo`, `holding`, `docs_holding`, `titled`, and constant `DOCS = "docs"`. Covers slugging rules, colon handling, heading detection, capping, fence unwrapping, numbering rules (digit runs anywhere, empty/absent dirs, directories counted as names, overflow past 99, oversized digit runs ignored), and confirms `proposed_path` writes nothing.
2. `mod writes` — tests `write_submit` end-to-end against a real filesystem, with helpers `a_repo`, `now`, `app_answering`, `field`, `entry`, `pacts`, `notes`, `everything_under`, `document_of`, `shapeless`, constants `BRIEF`, `LAST_KEY`, `WHOLE`. Covers writing+staling lines, size formatting, verbatim writing minus fence/newline handling, exclusivity of written artifacts, parent directory creation, refusal on existing path/directory, stale-line ancestor selection, root-level file staling, empty field refusal, path traversal refusal, missing-section refusal (single and multiple), shape read from repo's own template, unreadable shape refusal, disk-failure handling, and no-answer-on-conversation handling.
   - Nested `mod rounds` — drives `write_opened`/`write_edit` through simulated keystrokes (`edit_for`, `KeyCode` presses), using imports from `warlock_tui` (`Mode`, `edit_for`) and `warlock_engine::DEFAULT_BRIEF_DIRECTORY`. Tests: window opens with proposed path, full path-editing-then-write round, Esc leaves everything untouched, a refused path can be corrected and retried, and submitting with no open window is a no-op.
   - Nested `mod whole` — full integration test from composer input through worker thread to file-on-disk, using `warlock_tui::{Composed, Composer, Line, Mode, ScopePrompt, edit_for, Converses}`, `crate::chatting::Chat`, `crate::stubs::Saying`. Defines `AT_MOST` (5s timeout), `DOCUMENT`, `PROPOSED` constants, and helper `rounds_until_answered`. Single test `a_write_typed_at_the_composer_ends_as_a_document_on_disk` drives `/write` from typed composer input to a written, verified document and stale-pact note, asserting nothing else is written to the repo.
