This is a Rust source file implementing the input layer of a terminal UI application (warlock), translating raw keyboard and mouse events into abstract application intentions, with no terminal I/O performed directly. It has three main sections: doc-comment preamble, production code, and a large test module.

**Module-level doc comment**: Explains the file's purpose — two pure translation functions, one per input device, that convert raw events into named `Action`/`MouseAction` values without touching the terminal, keeping the event loop in `main.rs` a simple list of consequences.

**Imports**: Crossterm event types (`KeyCode`, `KeyEvent`, `KeyEventKind`, `KeyModifiers`, `MouseButton`, `MouseEvent`, `MouseEventKind`), ratatui's `Size`, and `warlock_tui` types (`App`, `Focus`, `Hit`, `hit_test`).

**`Action` enum** (`pub(crate)`): Represents keyboard-driven intents — `Quit`, `CancelPact`, `ToggleFocus`, `SelectPrevious`, `SelectNext`, `SelectPageUp`, `SelectPageDown`, `SelectFirst`, `SelectLast`, `ToggleCollapsed`, `TogglePactedOnly`, `ToggleFiles`, `TogglePact`, `ToggleMouseCapture`. Each variant has explanatory doc comments describing its rationale and UX reasoning (e.g., why Esc's meaning depends on whether a "pact" is in flight, why mouse capture toggling is separate from app state).

**`action_for(key: KeyEvent, in_flight: bool) -> Option<Action>`**: The pure key-to-action mapping function. Ignores anything but `KeyEventKind::Press` (to avoid double-firing on releases/repeats). Maps Ctrl-C and `q`/plain Esc to `Quit`; Esc while `in_flight` to `CancelPact`; Tab to `ToggleFocus`; arrow keys/`k`/`j` to selection movement; PageUp/PageDown to paging; `g`/`G` to first/last selection; Space to `ToggleCollapsed`; `o` to `TogglePactedOnly`; `f` to `ToggleFiles`; `p` to `TogglePact`; `m` to `ToggleMouseCapture`; everything else yields `None`. Extensive doc comments justify each binding's mnemonic and case-sensitivity choices.

**`WHEEL_NOTCH` constant**: `usize = 3`, the number of rows/lines one mouse wheel notch moves in either pane.

**`MouseAction` enum** (`pub(crate)`): Mouse-driven intents — `SelectNextBy(usize)`, `SelectPreviousBy(usize)`, `ScrollPanelDown(usize)`, `ScrollPanelUp(usize)`, `SelectRow(usize)`, `ToggleCollapsed`, `Focus(Focus)`. Doc comments note there is deliberately no hover/drag/other-button variant.

**`mouse_action(mouse: MouseEvent, size: Size, app: &App) -> Option<MouseAction>`**: Pure mapping from a mouse event (plus current terminal size and app state) to a `MouseAction`. Uses `hit_test` to locate the click/scroll within panes. Handles `ScrollDown`/`ScrollUp` via the `wheel` helper (scrolls whichever pane the pointer is over, regardless of focus) and `Down(MouseButton::Left)` via the `click` helper; all other event kinds return `None`.

**`wheel(hit: Hit, tree: MouseAction, panel: MouseAction) -> Option<MouseAction>`**: Helper mapping a `Hit` variant to the tree or panel action; header/rows/below-rows go to tree, panel lines go to panel; footer/border/offscreen return `None`.

**`click(hit: Hit, app: &App) -> Option<MouseAction>`**: Helper for left-click handling. On a `TreeRow`, computes the absolute row index via `app.scroll_offset()` plus the row offset; if past the end of `app.rows()`, just focuses the tree; if it's the already-selected row, returns `ToggleCollapsed`; otherwise returns `SelectRow(index)`. Tree header/below-rows focus the tree; panel lines focus the panel; footer/border/offscreen return `None`.

**Test module (`#[cfg(test)] mod tests`)**: Very large, split into:
- A `press(code)` helper building a plain `KeyEvent`.
- Numerous unit tests for `action_for`: quitting via `q`/Esc, Esc canceling a pact vs. quitting via `q`/Ctrl-C, verifying Esc is the only key whose meaning changes mid-pact, Ctrl-C handling with/without shift/caps-lock artifacts, Tab focus toggling (including during a pact, and ignoring releases/repeats), verifying Tab is the only focus-toggling key, arrow/`k`/`j` movement, PageUp/PageDown, `g`/`G` first/last (including shift-reported uppercase G), release/repeat suppression for movement keys, Space collapse toggling (including release/repeat suppression and exclusivity), `o` pacted-only filter (same pattern), `f` files toggle (same pattern), `p` pact toggle (release/repeat suppression), `m` mouse capture toggle (works regardless of `in_flight`, doesn't overlap with other actions, exclusivity, release/repeat suppression), and generic tests that unmapped keys and releases/repeats yield `None`.
- A nested `mod pointer` submodule testing `mouse_action` and a `round()` helper that mimics the event loop's dispatch of `MouseAction` onto an `App`. It defines a fixed 80x24 `SIZE`, column/row constants (`IN_TREE`, `IN_PANEL`, `FIRST_TREE_ROW`, `FIRST_PANEL_LINE`, `TREE_HEADER`, `FOOTER`), a `viewport()` helper, event-builder helpers (`wheel_down`, `wheel_up`, `left_click`, `event`), a `rows()` helper building 25 test rows (a root plus 24 directories each with one file child, files initially hidden), and `app_on_screen()` constructing an `App` sized to the test terminal. Tests cover: the assumed screen layout dimensions; wheel scrolling over the tree moving selection by 3 (including over the header); that three wheel notches equal three keypresses and clamp at both ends; wheel scrolling over the panel; that the wheel affects whichever pane the pointer is over independent of focus; that scrolling over the footer or borders does nothing; that clicking a tree row selects it and takes focus; that click row index accounts for scroll offset; that a second click on a selected directory row toggles collapse (open/close/open cycle) while a file row's second click does nothing; that clicking in the panel or on the tree header only changes focus; that clicking below the last row still focuses the tree without altering selection or rows; that clicking the footer or a border does nothing; and that all other mouse event kinds (hover, drag, button-up, right/middle buttons, horizontal scroll) are read and dropped everywhere tested.
