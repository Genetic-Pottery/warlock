This file implements the front-end application state (`App`) for a terminal UI referred to as "warlock," modeling a tree of pacted/unpacted/stale/fresh directories flattened into displayable rows, along with an extensive test suite.

It opens with a module-level doc comment laying out the design: the app flattens a tree into a list of `Row`s for display, keeps the full walk (`all_rows`) separate from the currently drawn subset (`rows`) so that collapsing, a "pacted-only" filter, and a "show files" toggle can all be implemented as reversible re-flattening operations rather than tree mutations; selection is tracked by node path rather than row index so it survives tree reloads; scroll offsets are tracked separately for a tree pane and a panel pane; transient status (last keystroke's message, in-flight pact/refresh operation) is kept apart from longer-lived state; and pointer-driven operations are tracked separately from keyboard-driven ones since they address rows differently (directly by row/pane vs. by relative direction).

Imports come from `std` (borrow, collections::BTreeSet, mem, path, time::Instant), from `warlock_engine` (IntoDocument, NodeState, StateCounts, Tree, to_manifest_path), and from a local `crate::account::{Account, Line}`.

**Core types defined:**

- `Row`: one flattened display line — depth, path, optional document path, `NodeState`, child count, file/ignored flags, optional scope string — with constructors `Row::new`/`Row::file` and builders `with_child_count`/`with_ignored`/`with_scope`, plus accessors `has_children`/`is_file`/`is_ignored`.
- `PactToggle`: a path plus a `pacted: bool`, handed back from a pact-toggle keypress so the caller (not `App`) performs filesystem work.
- `Run`: enum distinguishing `Pact` vs `Refresh` operations in flight.
- `InFlight` (private): tracks the directory currently being worked — path, one-based position, total count, and `Run` kind.
- `Summarising` (private): tracks a sub-pass summarizing one oversized file — path, one-based part, total parts.
- `Focus`: enum `Tree`/`Panel` indicating which pane keyboard movement drives, with `other()` and `drives_the_tree()`.
- `Sigils`: enum `Nothing`/`Held(Vec<String>)`/`Unknown` representing configured sigils, with a `held()` constructor folding empty vectors into `Nothing` and a `line()` method producing header text like `holding \`sigil1\`, \`sigil2\`` or `holding unknown`.
- `Chrome`: fixed session-level display facts (header line, `Sigils`) that never change during a run, kept outside `App` itself, with `Chrome::of(repo_root, root)` (computing a relative path header, blank if root equals repo_root), `with_sigils`, and `header()`/`sigils()` accessors.

**`App` struct**: nine fields — `all_rows`, `rows`, `collapsible` (BTreeSet of paths with visible children), `counts` (StateCounts tally), `selected`, `scroll_offset`, and three grouped sub-structs by lifetime across reloads:
- `Viewpoint` (private): `collapsed` (BTreeSet), `pacted_only`, `show_files`, `viewport_height`, `focus` — view choices that survive reloads.
- `Status` (private): `message`, `in_flight`, `summarising`, `pact_refused`, `mouse_captured` — short-lived footer state.
- `Panel` (private): `account`, `height`, `offset`, `follows` — the longest-lived group, surviving even rollback.

**`impl App` methods** include: `from_tree`, `from_rows`, `with_collapsed`, `with_counts`, message accessors/setters (`message`/`set_message`), in-flight/summarising/refusal setters and queries (`set_pact_in_flight`, `set_run_in_flight`, `set_pact_summarising`, `clear_pact_in_flight`, `set_pact_refused`, `is_pacting`, `is_in_flight`, `in_flight_covers`), `pact_line` (builds the footer progress string, e.g. `"pacting <path> (n/total)"`, combining verb, directory label, fraction, summarising clause, and "already running" suffix), account management (`start_account`, `has_account`, `account`/`account_mut`), `restore_from` (rolls back everything except the panel), panel accessors (`panel_height`/`set_panel_height`, `panel_follows`, `panel_scroll_offset`, `panel_lines`, `panel_lines_below`, `account_line_count`), row/view accessors (`rows()`, `collapsed()`, `is_collapsed`, `can_collapse`, `pacted_only()`/`toggle_pacted_only`, `show_files()`/`toggle_files`, `counts()`, `is_empty`, `selected()`, `selected_row()`, `scroll_offset()`, `viewport_height()`/`set_viewport_height`, `mouse_captured()`/`set_mouse_captured`, `focus()`/`toggle_focus`/`set_focus`), and movement methods: `select_previous`, `select_next`, `select_page_up`, `select_page_down`, `select_first`, `select_last`, `select_row` (pointer-driven, direct index, ignores focus), `select_next_by`/`select_previous_by` (pointer wheel over the tree), `scroll_panel_down`/`scroll_panel_up` (pointer wheel over the panel), plus private helpers `movement` (dispatches keyboard movement to tree or panel based on focus), `scroll_panel_to` (clamps panel offset and recomputes `follows`), `page`/`panel_page` (window-scroll step sizes, defaulting to 1 row when unmeasured), and `rescroll` (re-derives `scroll_offset`).

`reflow` rebuilds the drawn `rows` from `all_rows` by applying, in order, the file-visibility filter, the pacted-only filter, and the collapsed-set filter, then re-anchors selection by path (falling back to the nearest surviving ancestor, or row 0). `moved` and `forget_last_keystroke` clear the footer message/refusal flag after each keystroke. `label_for` renders a path relative to the tree root for footer messages.

Tree-mutating command methods, each heavily documented: `toggle_collapsed` (hides/reveals a node's descendants, refusing no-op rows, moving selection onto the collapsed ancestor); `toggle_pact` (pacts/un-pacts the selected subtree, refusing file rows and `.warlockignore`-excluded rows, returning `Option<PactToggle>`); `refresh` (hands back the path to refresh, refusing file rows, unpacted rows, and already-fresh rows with distinct messages); `scope_target` (similar gating for the scope key, refusing file rows and unpacted rows, leaving messages untouched on success); `set_subtree_state` (repaints a whole subtree's state across both row lists, keeping `counts` in sync via `count_mut`, skipping ignored rows when moving into a pacted state but not when un-pacting); `insert_file_row` (splices a new file row, e.g. for a just-written `WARLOCK.md`, into the correct sorted position in both row lists without a full reload, adjusting selection/scroll as needed).

Free functions following the `impl App` block: `file_row_position` (binary-search-like insertion point); `reseat_on` (rebuilds an `App` from a freshly reloaded `Tree` while preserving all view state — selection by path, collapsed set, filters, scroll, panel/account, message — via field-by-field destructuring of the old `App`); `walk_of` (flattens a `Tree` into `Row`s, carrying ignore flags and scopes); `node_rows` and `pacted_rows` (filter helpers, the latter using a single reverse pass tracking an ancestor-depth requirement); `paint_subtree`/`moves_with_subtree`/`in_subtree` (subtree state-painting honoring the rule that ignored rows never move into a pacted state but do move into unpacted); `drawn_rows` (single forward pass computing both the collapsed-filtered row list and the `collapsible` path set); `index_for` (path-or-nearest-ancestor lookup); `scroll_offset_for` and `panel_offset_for` (pure minimum-movement/following scroll math for the tree window and account panel respectively). Then a series of documented message-formatting functions: `left_on_disk_message`, `pacting_message`, `refreshing_message`, `already_fresh_message`, `unpacted_message`, `unpacted_scope_message`, `summarising_message`, `already_running_message`, `file_row_message`, `ignored_row_message`, and `count_mut` (maps `NodeState` to the corresponding `StateCounts` field).

**Test module** (`#[cfg(test)] mod tests`): fixtures and helpers include `MANY`/`WINDOW` constants, a `Movement` function-pointer type alias, synthetic row builders (`three_rows`, `rooted_rows`, `many_rows`), `tally` (independently recomputes counts for cross-checking), `scrolled_to`, `drawn`, `states`, expected-row-list fixtures (`whole_fixture`, `pacted_fixture`, `whole_fixture_with_files`), app-building/selection helpers (`app_selecting`, `app_with_files_selecting`, `select`), `selection_is_on_screen`, and further re-seat/insertion fixtures: `tree_without_the_tui_crate` (fixture tree with one directory removed, for testing disappearance on re-seat), `selected_path`, `tree_listing`/`list_file` (build "ground truth" trees with a file spliced into a directory's listing, mirroring how the loader would produce it), and `app_with_files`.
