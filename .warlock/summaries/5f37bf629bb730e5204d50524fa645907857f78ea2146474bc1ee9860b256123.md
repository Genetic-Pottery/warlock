This file implements "pacting": turning a directory, or a whole subtree of directories, into an AI-model-generated `WARLOCK.md` document, and recording that as manifest state. It is organised as a long module-level doc comment, the implementation proper, and a large `#[cfg(test)]` test module that makes up roughly the back half of the file.

The doc comment lays out the design: `pact_directory` handles one directory (gather request, describe oversized content, fit to budget, run one agent pass, write the document, recording nothing), while `pact_subtree` walks a whole subtree children-first, writes documents for every directory, then hashes and grants manifest entries in a second phase, so partial failures leave directories pacted-but-ungranted rather than corrupt. A request gathered for a directory consists of its own files plus each immediate child's `WARLOCK.md`, walked with the same `ignore`-crate rules used elsewhere (no symlink following, `.warlock/` pruned, sorted relative forward-slash paths). Two budget caps constrain requests — a per-file cap and a whole-request cap — and an over-cap file is never truncated, only demoted through a three-rung ladder: sent whole, then summarised (name, size, prose), then listed as name and size only; neither cap can fail a pact, only generate reported problems. Oversized files are summarised by chunking on UTF-8 line boundaries and map-reducing the chunks through the agent, subject to a chunk-count ceiling and a minimum summary length, with distinct failure causes for non-text content, too many chunks, or an unsummarisable result. A persistent, never-evicted, safe-to-miss cache under `.warlock/summaries/`, keyed by a blake3 hash of file bytes alone (never path, name, or mtime), avoids re-summarising unchanged content. The whole-request cap is enforced by a three-pass demotion ladder that always terminates. Agent responses are accepted verbatim via atomic write (temp file plus rename) or refused — on agent error or on trimmed length under a minimum, with no phrase-list heuristics, length only. `pactable_directories` gives the ordered list, children before parents, that subtree pacting covers. Cancellation is exposed through an `Observer` trait, checked between directories only (never mid-pass), with a no-op default implementation and a separate per-chunk progress callback. `unpact_subtree` purely removes manifest entries for a directory and its descendants, never touching files on disk.

The code begins with imports and a block of precisely documented constants: the manifest directory name, the summary cache subdirectory and file extension, a versioned cache-key context string, the document filename, the root module marker, walk depth, the per-file and whole-request byte caps, the minimum document length, the chunk byte cap, the chunk-count ceiling, and the minimum summary length. Three full prompt strings follow: the directory-level document prompt, and the map/reduce prompts used for summarising oversized files, each with notes on their invocation assumptions (e.g. a chunk summary must never name the file, since cache entries are keyed by content only).

The implementation itself comprises: `pact_subtree` (two-phase write-then-grant, sharing one timestamp across all entries in a run, returning manifest, failures, and problems); a `rewrite` helper merging new entries into an existing manifest; `unpact_subtree` and an `at_or_below` segment-wise path-prefix helper (root treated as ancestor of everything); `pact_directory`, delegating to a private `pact_directory_watched` that gathers a request, summarises and demotes it to budget, runs one agent pass, checks the trimmed length, and atomically writes the document; `pactable_directories`, walking and collecting directories bottom-up; `gather_request`, building the file and child-document lists and calling `trim_to_budget`; `trim_to_budget`, demoting the largest files first (ties broken by path) until under the request cap; `summarise_over_cap`, running the cache/summarise pipeline on each too-large file; `demote_to_budget` and its three rung helpers — shrinking whole files to summaries where smaller, promoting previously-cliffed files back up if they now fit, and finally listing anything still over budget as name and size only, with care never to regress a file back to full bytes once cliffed; and a `report` helper enforcing one problem per file.

A `Summarising` struct bundles the borrowed context (root, agent, observer, directory) needed across the summarisation helpers; its `summary_of` method is the single place summaries are produced — checking the content-keyed cache first, returning a hit silently, and on a miss calling `summarise_file` and best-effort writing the result back (write failures ignored). `chunk_utf8` splits bytes into UTF-8-valid, newline-terminated chunks near the chunk cap, allowing a single overlong line to become its own chunk, validating UTF-8 once up front, and guaranteeing exact reassembly. `summarise_file` is the map-reduce driver: it fails fast on non-text or too-many-chunks before running any pass, otherwise runs one map pass per chunk (announcing each via the observer) and, for more than one chunk, a final reduce pass; a single chunk's map answer is returned directly. `summarising_pass` runs one agent pass and converts an agent error or too-short answer into the unsummarised failure. `map_request` and `reduce_request` build agent requests embedding the map/reduce prompts and part-numbering, always as request text rather than as files, so a fragment is never mistaken for a whole file. Five cache functions manage the on-disk summary cache under `.warlock/summaries/`: computing the content-hash key, locating the cache directory and file name, reading a cached entry (returning `None`, never erroring, on any failure or blank content), and writing one via the same temp-file-then-rename idiom used for manifest saves.

A `Found` struct and `walk` function gather a directory's own files and its immediate children's documents one level deep, under the same ignore rules used throughout. Small helpers compute relative forward-slash paths, saturating byte counts, how many budget bytes one file spends (sent bytes, summary length, or zero if merely listed), and total carried bytes. The `Observer` trait defines `starting` (once per directory, before its pass, may cancel), `summarising` (announcement-only, before every real summarising pass, counting passes not chunks), and `documented` (announcement-only, once a directory and everything beneath it is written); it is explicitly not `Send`/`Sync`/`'static` and never interrupts a pass in flight. `Pacting` (`Continue`/`Stop`) and a no-op `Unwatched` implementation follow.

Result and error vocabulary: `PactedSubtree` (manifest, failures, problems), `Pacted` (document path, problems), `Gathered` (request, problems), `Problem` (path plus cause); the `Omission` enum enumerates why a file's content didn't make it into a request (too large, over budget, unreadable, not text, too many chunks, unsummarised), each with a one-line human explanation; `Refusal` enumerates why a directory pass produced no document (agent transport error, or too-short answer); `Error` enumerates a directory-level pact failure (walk, path, refused, write), each carrying its directory and unified by a `directory()` accessor; `Failure` enumerates a subtree-level failure per directory (no document written, document written but unrecordable, or hashed-and-granted failure), likewise with a `directory()` accessor.
