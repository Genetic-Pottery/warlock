This file implements loading of a filesystem directory tree into the crate's `Tree` data structure, along with supporting tests. Structurally it consists of: a large module-level doc comment, the core loading logic, supporting types, and an extensive test suite.

The module doc comment explains the design rationale: `load_tree` builds a `Tree` rooted at whatever working directory it's given, while finding the repository's manifest by walking upward to the nearest ancestor containing `.git/`. It defines what constitutes a "node" (every directory reached by the walk, documented or not, via presence of a `WARLOCK.md`), how files are attached to their containing directory node (`Node::files`, in sorted order, including the `WARLOCK.md` itself), and how traversal skipping works (via the `ignore` crate, honoring `.gitignore`, hidden files, `.git/`, plus an unconditional `.warlock/` prune, no symlink following, deterministic name ordering). A dedicated subsection explains why `.warlockignore` does NOT prune directories from this particular walk — excluded directories still appear as rows/nodes/files but are flagged via `Node::ignored`, so the UI can show them as gray/excluded rather than silently vanishing. It also explains state determination: presence in the manifest, then hashing via `subtree_hash`, colored by `decide_state`; hash failures are non-fatal, producing `NodeState::PactedStale` plus a recorded `Problem`.

Constants defined: `GIT_DIR` (".git"), `MANIFEST_DIR` (".warlock"), `DOCUMENT_FILE` ("WARLOCK.md").

Main public function `load_tree(working_dir)`: resolves working_dir to absolute path, finds repo root, loads manifest (treating "not found" as an empty manifest, other errors as fatal `Error::Manifest`), builds a `Builder` struct with the walked directories map, manifest, and repo root, then recursively builds the `Node` tree and collects `problems` into a `Loaded { tree, problems }` return value. Includes a doctest example demonstrating usage.

`Loaded` struct: holds `tree: Tree` and `problems: Vec<Problem>`.

`Problem` struct: records a node `path` and a `cause: HashError` for nodes whose hash failed; implements `Display` and `std::error::Error`.

`repository_root(start)` function: public helper finding nearest ancestor (inclusive) containing a `.git` directory (must be a directory, not a file, to exclude worktrees/submodules).

`walk(root)` function: performs a single `ignore`-crate walk collecting a `BTreeMap<PathBuf, Directory>`, recording per-directory `has_document` and collected child `files`, then sorts files and calls `mark_excluded`.

`builder(root)` function: constructs the shared `WalkBuilder` configuration (no symlink following, git not required, filters out `.warlock` directory by name).

`mark_excluded(root, directories)` function: runs a second walk with `.warlockignore` registered as a custom ignore file (via `ignores::FILENAME`/`ignores::is_ignored`) to determine which directories are excluded by repository rules, handling the special case where the root itself is excluded (marks everything), otherwise diffing the second walk's kept directories against the full directory set to mark `ignored` flags.

`Directory` struct (private): `has_document: bool`, `files: Vec<PathBuf>`, `ignored: bool` — per-directory walk findings.

`Builder` struct (private): holds `directories` map, `repo_root`, `manifest`; implements:
- `node(dir, problems)`: recursively constructs a `Node` with children, document, files, ignored flag, and computed state.
- `children_of(dir)`: iterator over immediate child directories using BTreeMap ordering properties.
- `state_of(dir, problems)`: looks up manifest entry by converting dir to a manifest-relative path (`to_manifest_path`); if no entry, `Unpacted`; otherwise computes `subtree_hash`, calling `decide_state` on success or pushing a `Problem` and returning `PactedStale` on failure.

`absolute(path)` function: lexically resolves a path to an absolute, normalized form (without touching disk/symlinks), resolving `.` and `..` components manually; wraps IO errors as `Error::Io`.

`Error` enum (`#[non_exhaustive]`): variants `NoRepositoryRoot { start }`, `Io { path, source }`, `Manifest { source: ManifestError }`, `Walk { source: ignore::Error }`; implements `Display` and `std::error::Error` (with `source()`).

Test module (`#[cfg(test)] mod tests`): extensive, covering essentially every behavior described in the doc comments. Includes helper functions: `fixture` (creates `.git`/`.warlock` plus specified dirs/documents), `git_only_fixture` (cold-open repo with only `.git`, no `.warlock`), `tree_of` (loads and asserts no problems), `pact` (writes manifest entries without grants, via `Manifest::with_entries`/`PactEntry`), `write_file`, `hand_write_manifest` (writes a manifest TOML by hand including a `granted_hash`, since nothing in the crate can produce a real grant), `file_names`, `relative_paths`, `states`, and `excluding_fixture` (sets up a `.warlockignore` excluding `notes/` directories).

Individual tests verify: documented vs undocumented directories are both nodes; plain `README.md` is just a listed file, not a document, and is hashed like any file; full walk reaches every directory even with no documents anywhere; tree rooting at a subdirectory with manifest found above it; empty/missing manifest yields fully unpacted tree; cold-open repository (no `.warlock/` at all) loads unpacted; first pact creates `.warlock/` directory; ignored/`.git`/`.warlock` directories are skipped from the walk; `.warlockignore`-excluded directories are kept as rows but marked `ignored`, including nested descendants, and when the load is rooted at an excluded directory itself; edits/adds/deletes inside excluded content don't change colors while edits to covered content do; no-rules repo marks nothing ignored; file listing order and attribution (document included, sorted, per-directory not inherited); files obey same ignore rules as directories; deep nesting depth; manifest entry colors exactly its own node and not children; hand-written matching grant state is fresh until changed below it; unreadable file (unix-only) produces one `PactedStale` node plus a `Problem` without failing the whole load, while other nodes color normally; unpacted nodes are never hashed so unreadable files under them cause no problem; symlinked directory cycles (unix-only) don't cause infinite loops and aren't followed/listed; a synthetic cargo-workspace-shaped repo loads correctly with ignored content excluded; directory entirely outside any repository produces `NoRepositoryRoot` error without touching disk; corrupt manifest produces `Error::Manifest`; and `Display` text correctness for error variants.
