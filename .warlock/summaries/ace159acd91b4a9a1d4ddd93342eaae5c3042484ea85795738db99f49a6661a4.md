This is the entirety (and only part) of `pact.rs`, the module implementing warlock's pacting operations — the machinery that turns a directory into a `WARLOCK.md` and turns a subtree of documents into manifest entries.

The file opens with an extensive module-level doc comment explaining the design in prose before any code: three layered operations — `pact_directory` (one directory: gather, fit to budget, run one model pass, write the document), `pact_subtree` (every directory under a selection, children-first, then hash-and-grant as a second phase), and `refresh_subtree` (same machinery as `pact_subtree` but restricted to directories `decide_state` calls stale). It explains that `describe_and_grant` is the shared core of the two subtree operations, that context-fitting is deferred to the `fitting` module, that `.warlockignore` exclusions are honored by every walk, that responses are written verbatim with a two-phase write/hash-grant split (to avoid granting a parent before children's documents exist), that hashing failures after a pass are recorded differently from hashing failures during staleness-checking, that an `Observer` trait lets a caller watch and cancel between directories (never mid-pass), and that `unpact_subtree` reverses pacting by manifest edit only, deliberately never touching files on disk, taking scopes down with the dropped entries.

Constants and the prompt: `MANIFEST_DIR` (`.warlock`), `DOCUMENT_FILE` (`WARLOCK.md`), `MINIMUM_DOCUMENT_BYTES` (200, the sole rejection threshold, deliberately no phrase-based heuristic), and `PROMPT` — the full, long, fixed instruction text given to the model pass, covering: writing both file-by-file coverage and cross-file behavior, verifying claims against files rather than an old document, refusing unverifiable "nothing does X" claims, refusing to guess at listed-only files, handling summarized/elided files, and refusing to write about warlock's own scope/pact bookkeeping while still describing scope/pact *code* normally as ordinary subject matter.

Core public functions, each with long doc comments and embedded doctest examples:
- `pact_subtree` — walks `pactable_directories`, calls `describe_and_grant`, then `rewrite`s the manifest; returns `PactedSubtree { manifest, failures, problems }`; saves nothing itself.
- `refresh_subtree` — filters `pactable_directories` down to those failing `is_fresh`, then runs the same `describe_and_grant`/`rewrite` pipeline, but calls `rewrite` with an empty covered list so skipped entries survive untouched.
- `is_fresh` (private) — checks a directory's manifest entry against its current `subtree_hash` via `decide_state`.
- `pact_directory` (public) / `pact_directory_watched` (private) — the single-directory pass: calls `fit` to build a request, runs the agent, checks response length against `MINIMUM_DOCUMENT_BYTES`, writes atomically via a hidden temp file and rename, returns `Pacted { document, problems }`.
- `pactable_directories` (crate-private) — walks a directory with the `ignore` crate (respecting `.gitignore`, `.warlockignore`, pruning `.warlock/`), returns directories deepest-first via reverse path sort.
- `unpact_subtree` — drops manifest entries at/below a directory (segment-wise match via `at_or_below`), touching no files; brings scopes down with dropped entries.
- `closed_scopes_at_or_below` — reports (without refusing) which scopes at/below a directory an operator's held sigils don't open, for callers to check before un-pacting.
- `view_file` — reads a file for human viewing, capped at `PER_FILE_BYTE_CAP`, never splitting a UTF-8 character, returning `Viewed { text, cut }`.
- `stamped`/`STAMP` — prepends a fixed, dateless "this is a map not a spec" banner to every written document, idempotently.

Supporting private types: `Described` (phase outputs: outcomes/failures/problems), `Outcome`/`Grant` (what one directory's run earned, with `apply`/`into_entry` methods that can only touch run-owned fields, never a hand-set scope), `describe_and_grant` (the two-phase engine shared by pact and refresh), `rewrite` (merges outcomes into a manifest preserving order/untouched entries), `at_or_below` (segment-wise path prefix test), `read_capped`.

Public trait/enum for progress: `Observer` (`starting` — the only question, returns `Pacting::Continue`/`Stop`; `summarising`, `requesting`, `documented` — announcements with no-op defaults), `Pacting`, `Unwatched` (a do-nothing/never-cancel observer).

Public result/error types: `PactedSubtree`, `Pacted`, `Viewed`, `Unviewable` (`Unreadable`/`NotText`), `Refusal` (`Agent`/`TooShort`), `Error` (`Walk`/`Path`/`Refused`/`Write`, all naming a directory via `Error::directory()`), `Failure` (`Document`/`Record`/`Hash`, all naming a directory via `Failure::directory()`) — each with `Display`/`std::error::Error` impls.

The remainder (the large majority of the file by byte count) is a `#[cfg(test)] mod tests` block containing dozens of unit tests and extensive fixture/fake infrastructure (`Canned`, `Fails`, `Counting`, `FailsFor`, `FailsEveryMap`, `Watching`, `Overheard`/`Overhearing` observer-logging pair, plus helpers like `document()`, `written()`, `write()`, `filler()`, `share()`, `not_text()`, `multibyte_text()`, `text_of_chunks()`, `project()`/`repository()` fixture builders, `snapshot()`, `scopes()`/`with_scopes()`). These tests verify: prompt content/wording invariants (coverage-first, silence-isn't-evidence, no first-person bookkeeping commentary, settling disagreements), verbatim/atomic document writing and stamping, rejection thresholds, the byte-cap/summarization ladder (per-file cap, request cap, chunking, caching under `.warlock/summaries/`), directory ordering (children-before-parents), the two-phase write-then-hash-grant behavior and partial-completion/ungranted-entry semantics, cancellation via `Observer::Stop`, `.warlockignore` exclusion behavior, manifest rewrite/replace-in-place semantics with exact expected TOML byte comparisons, un-pacting (entry removal, document files always preserved on disk, segment-wise descendant matching, scope-dropping), `closed_scopes_at_or_below` behavior, and `view_file`'s cap/cut/UTF-8-boundary/error behavior.
