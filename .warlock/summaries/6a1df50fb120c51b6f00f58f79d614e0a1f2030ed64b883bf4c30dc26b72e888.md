This is the sole part of a Rust source file (`claude.rs`) implementing the transport layer that runs the `claude` CLI as a child process on behalf of a documentation-generation tool called warlock. It begins with an extensive module-level doc comment explaining the design philosophy: this module is the only place in the crate that spawns processes, translating either an engine-built `Request` (a model "pass" over a directory) or a typed chat message (a "turn") into a child-process invocation, and reading back its output as an `agent::Response`/`agent::Error`. The header explains two agent kinds — `ClaudeAgent` (passes, no tools, read-only info baked into the request) and `ChatAgent` (conversational turns, read-only tools `Read`/`Grep`/`Glob`, tied to a persistent CLI session) — and describes five engineering problems solved by the code: pipe deadlock avoidance via dedicated reader threads for stdout/stderr, writing stdin then closing it for EOF, a polling waiter thread against a `Mutex<Child>` so a call can be cancelled/killed, a `Cancel` handle for external cancellation, and an `Activities` port for streaming progress (tool calls, thinking, writing progress, cost) to a listener without leaking model prose/thoughts.

The body then defines: imports; constants (`INVOCATION_TIMEOUT` = 5 min, `PROGRAM` = "claude", `ARGS` for print/stream-json mode, `MODEL`/`CONTEXT_TOKENS`/`EFFORT` for passes, `BRIEF_EFFORT`/`BRIEF_MODEL` for a higher-effort "brief" chat register, `SYSTEM_PROMPT`/`NO_TOOLS` for passes, `CHAT_TOOLS`/`CHAT_SYSTEM_PROMPT` for turns, and several long instruction strings `BRIEF_ARTIFACT`/`BRIEF_ARGUMENT`/`CHAT_INSTRUCTION`/`WRITE_INSTRUCTION` plus the `brief_instruction()` function that composes a "/brief" mode-entry message from a template); environment-variable override helpers (`MODEL_VAR`, `EFFORT_VAR`, `or_default`, `overridden`); a `render()` function that serializes an `agent::Request` (prompt, directory name, previous document, files in four possible states — full, elided-tests, summarized, omitted — and child documents) into the single text blob sent on stdin, with a `CONTENT_GUARD` separating instructions from content; `default_args()`/`chat_args()` builders; a `Session` struct managing the `--session-id`/`--resume` CLI session-continuity logic with atomic claim tracking, and a `session_id()` function hand-rolling a UUID-shaped identifier from hashing (no `uuid` crate); `POLL_INTERVAL`; the `Cancel` struct/`State` (atomic flag + registered child, with `register`/`finished`/`cancel` methods); the `Activity` enum (`Tool`, `Thinking`, `Writing{bytes}`, `Cost{usd}`) and `Activities` port (closure-based sink, clonable, `none()` default); a `Wired`/`Converses` trait pair defining the seam abstraction; the `ClaudeAgent` struct (program/args/timeout/cancel/activities fields, builder methods, `spawn`/`spawn_error`, and its `Agent` trait impl calling `invoke`); the `ChatAgent` struct (adds `session: Option<Session>`, `at_effort`/`at_model`/`replacing` for mode-switching, `turn()`, `spawn()` claiming the session, `spawn_error`); the core `invoke()` function orchestrating spawn/write/read/wait/cancel/timeout logic and `judge()` for turning exit status + captured stdout/stderr into a `Result`; a `cancelled()` helper; an internal `stream` module doing pure JSON-line parsing of the `stream-json` CLI output format (`read_line`, `read_activities`, `read_block_start`, `read_text_delta`, `read_block`, `read_detail`, `read_result`, with a `DETAILS` table mapping tool names to their one displayed argument); `read()` (threaded incremental stdout reader accumulating a running byte count per text stretch and reporting via `Activities`), `drain()` (whole-buffer stderr reader), `collect()`, `watch()` (polling waiter thread), `kill_and_reap()`, and `lock()` (poison-tolerant mutex lock); and finally `Wired`/`Converses` trait impls for `ClaudeAgent`/`ChatAgent`.

The remainder (the bulk of the file by line count) is a `#[cfg(test)]` module containing extensive unit tests: pure-logic tests for argument construction, `render()`'s handling of file states/previous documents/child documents, override resolution, session-id uniqueness/shape, brief/chat/write instruction content, and the `stream` module's JSON parsing (tool details, thinking, text deltas/openings, garbage lines, cost/result lines, multi-block messages). A nested `#[cfg(unix)]` module (further nested `turns` submodule for `ChatAgent`) contains process-level integration tests using `/bin/sh` stand-ins to exercise real pipes: clean runs, streaming activity delivery during execution, garbage-tolerant parsing, large payloads not leaking through the port, thoughts/tool results being suppressed, working-directory correctness, non-zero exit/stderr capture, empty-output detection, timeout-and-kill-and-reap behavior (with Linux-only zombie-reaping checks via `/proc`), cross-thread cancellation (including a case where a forked survivor process still holds pipes open), and verifying that attaching/not attaching an `Activities` listener never changes run outcomes. A final top-level test confirms failures return quickly rather than waiting out the full timeout.
