This is the implementation and test suite for the "scope" feature of warlock's TUI: the logic behind pressing `s` to open a scope-editing prompt over a directory row, editing text in that prompt, and pressing Enter to write a scope label into `.warlock/pacts.toml`.

Structure:

1. **Module-level doc comment** explaining the design philosophy: this module (unlike `pacting`, which runs model passes as background worker threads with channels and progress reporting) does everything synchronously on the event loop's own thread, because writing one string into one manifest entry needs no thread, no cancellation, and no reload of the tree (a scope doesn't change any directory's freshness state). It also explains that a successful write produces no message (only the `(scope)` label, drawn elsewhere, communicates success — deliberately, to avoid inventing throwaway text), that Esc/typing leave the app's message line untouched, that scope validity is judged solely by `validate_scope` (from `warlock_engine`) after this module lower-cases the typed text for case-insensitive folding, and that an empty submitted field clears the scope (not an error) while an invalid string reopens the prompt with the same text and a refusal reason attached rather than closing.

2. **Imports**: `warlock_engine` types (`Manifest`, `PactEntry`, `to_manifest_path`, `validate_scope`) and `warlock_tui` types (`App`, `Edited`, `ScopeField`, `ScopePrompt`), plus a local `Error` type.

3. **`scope_press`** — decides what pressing the scope key does. If a run (pact/refresh) is in flight, it refuses via `app.set_pact_refused()` and returns `ScopePrompt::Closed`, mirroring how a second pact-key press is refused. Otherwise it asks `app.scope_target()` for the selected directory (row-level refusals are handled and messaged there, not here); resolves that directory to a manifest-relative path via `to_manifest_path` (failure produces an `Error::Manifest` message and closes); looks up the entry's current scope (or empty string if none/absent); and returns an opened `ScopePrompt` pre-filled with that value.

4. **`scope_edit`** — dispatches an `Edited` value (from `warlock_tui::edit_for`) coming from a keystroke inside the open prompt: `Open(field)` just updates the prompt state (typing), `Close` discards it (Esc), and `Submit` calls `scope_submit` on the current field (or closes if somehow there's no field, an unreachable path in practice).

5. **`scope_submit`** — the actual write path for Enter. Lower-cases the typed text; empty text means clear the scope (`None`), non-empty text is validated via `validate_scope`, and a validation failure reopens the prompt with the offending field marked "refused" with the rule's message, writing nothing. If validation passes (or text was empty), it looks up the directory's manifest entry; if the entry no longer exists (e.g., manifest hand-edited elsewhere) it sets a message (`no_pact_message`) and closes without writing. Otherwise it builds a new manifest via `with_scope_on`, attempts `next.save(repo_root)`, and on failure sets an error message and closes without mutating the held manifest; on success it replaces `*manifest` and closes the prompt.

6. **`with_scope_on`** — private helper that rebuilds a `Manifest` by cloning all entries unchanged except the target module, which gets `.with_scope(...)` or `.without_scope()` applied, preserving entry order and other fields (document, grant hash/timestamp).

7. **`no_pact_message`** — formats the footer message for when the manifest lacks an entry for the target directory, suggesting the user press `p` to pact it first.

8. **Test module** (`#[cfg(test)]`) — extensive tests exercising the whole pipeline against real temporary-directory repositories (no mocked terminal/network/`claude`). It sets up helper fixtures: constants for a grant hash/timestamp and a "last key" message sentinel; `a_repo()` for a fresh tempdir; `tree()` building a fixed 4-node directory tree (root pacted-stale, `crates` unpacted, `crates/engine` pacted-fresh with scope "data-plane", `crates/tui` pacted-stale with no scope) with row-index constants; `app_on()` building an `App` from that tree with a given row selected and a preset message; `entry()`/`pacts()` building matching manifest fixtures; `scope_on()`, `saved()`, `field()`, `refusal()`, `press()` as further helpers.

Tests cover: opening the prompt pre-filled with the current scope on a pacted row without side effects; Esc closing cleanly and preserving the message line; opening on empty field for unscoped or manifest-missing entries; the field tracking the manifest rather than the row; refusing to open (and just messaging) while a run is in flight, including repeated presses being idempotent; refusing when the directory can't be spelled relative to the repo root; Enter setting a scope while preserving document/grant/hash/timestamp and entry order; Enter with empty text clearing a scope while keeping the grant; confirming no run-state/message/account side effects from set/clear; refusing invalid input (spaces, commas) while leaving the prompt open with the refusal text intact and nothing written or mutated; case-folding before validation and storage; handling save failures (e.g., `.warlock` blocked by a file) by messaging and leaving the manifest untouched; handling a missing manifest entry at submit time; confirming the write lands only at `.warlock/pacts.toml` with no leftover temp files; confirming plain typing/Esc do nothing to disk; confirming submit with no open window is a no-op; an end-to-end key-by-key simulation typing "webx", backspacing to "web", and pressing Enter, verifying no run-state pollution; and fixing/resubmitting previously refused text without reopening the window.
