This file implements pacting: the operation of running a model over a directory (or a whole subtree of directories) to produce or refresh its `WARLOCK.md` document, plus the manifest bookkeeping, budget/summarisation machinery, and observer/cancellation plumbing that support it, followed by an extensive test suite.

The file opens with a long module-level doc comment laying out the whole design before any code appears. It describes three stacked operations: `pact_directory` (gather a directory's context, fit it to a byte budget, run one agent pass, write the resulting document — no manifest/hash/grant recorded), `pact_subtree` (a children-first pass over every pactable directory in a tree, followed by a separate hash/grant phase), and `refresh_subtree` (the same as `pact_subtree` but restricted to directories that `decide_state` finds non-fresh). It explains that `describe_and_grant` is the shared core of the two subtree operations, differing only in which directories they're given and how leftover manifest entries are treated (dropped vs. carried through unchanged). It documents what context is gathered for a directory (its own files, including any existing `WARLOCK.md`, plus each immediate child's `WARLOCK.md`, not deeper), using the same `ignore`-crate walk semantics as loading and hashing (no symlink following, `.warlock/` pruned, `.warlockignore` honored), and notes that changes to `.warlockignore` legitimately restale affected directories. It lays out two byte caps (`PER_FILE_BYTE_CAP`, `REQUEST_BYTE_CAP`) and a philosophy that exceeding budget is never fatal: oversized files are demoted through a three-rung ladder — sent whole, summarised, or listed by name and size — rather than truncated. Summarisation is explained as splitting an oversized file into newline-bounded chunks (capped by `CHUNK_BYTE_CAP` and `CHUNK_COUNT_CEILING`), mapping a prompt over each chunk and reducing the results into one prose account, cached content-addressably (by blake3 hash of the file's bytes) under `.warlock/summaries/`, committed to the repo and never evicted; the cache is documented as invisible to hashing/staleness and path/root-independent. Three ways summarisation can decline (non-text content, too many chunks, unusable/too-short output) are described, each falling back to name+size with a disclosed `Problem`. The whole-request budget is met via a demotion ladder (`demote_to_budget`) rather than a single cliff. Accepted agent answers are written verbatim to `WARLOCK.md` atomically (temp file plus rename); answers are rejected if the agent errored or the answer falls under `MINIMUM_DOCUMENT_BYTES`. `pactable_directories` is described as the source of a subtree's directory list, walked children-before-parents. The two-phase design of `pact_subtree` (write everything, then hash everything) is explained as necessary because a single-pass write/hash/grant loop would invalidate a parent's hash when a child is written afterward; partial completion leaves undocumented directories with no entry and their ancestors with an entry but no grant (stale). Hash failures during the grant phase are distinguished from staleness checks during refresh (the latter isn't a failure, just triggers redescription). An `Observer` mechanism is documented: it is offered progress before each directory and may request a stop, checked only between directories, plus a separate `summarising` callback for per-file summarisation passes; cancellation is not a failure, just a smaller completed subtree, and the grant phase only processes what the write phase actually produced. Finally, `unpact_subtree` is documented as a pure manifest edit that removes entries (and their scopes) for a directory and everything below it without touching any files on disk — the only operation that can lose a scope, since ordinary pact runs never do.

After the doc comment, the file's actual contents follow in this order:

**Imports and constants.** Standard library collections/path/fmt imports, the `ignore` crate's `WalkBuilder`, and crate-internal items (`Agent`, `AgentRequest`, `Manifest`, `PactEntry`, `decide_state`, `subtree_hash`, `to_manifest_path`, etc.). A documented block of constants fixes the concrete numbers used throughout: `MANIFEST_DIR = ".warlock"`, `SUMMARY_DIR = "summaries"`, `SUMMARY_EXTENSION = "md"`, `SUMMARY_KEY_CONTEXT` (a versioned domain-separation string for the cache key), `DOCUMENT_FILE = "WARLOCK.md"`, `WALK_DEPTH = 2`, `PER_FILE_BYTE_CAP = 128 KiB`, `REQUEST_BYTE_CAP = 256 KiB`, `MINIMUM_DOCUMENT_BYTES = 200`, `CHUNK_BYTE_CAP = 96 KiB`, `CHUNK_COUNT_CEILING = 32`, `MINIMUM_SUMMARY_BYTES = 80`, each with rationale.

**Prompts.** Three literal prompt strings sent to the agent: `PROMPT` (the main directory-documentation instruction, with commentary on the "headless, one invocation per directory" design), `MAP_PROMPT` (per-chunk summarisation instruction, forbidding naming the file since summaries are keyed by content bytes alone), and `REDUCE_PROMPT` (combining per-chunk accounts into one file account, with the same naming prohibition and a warning against quoting parts as if they were the file).

**Public subtree operations.** `pact_subtree` walks `pactable_directories`, calls `describe_and_grant`, and returns a `PactedSubtree` via a `rewrite` helper; documented as failing only with `Error::Walk`, otherwise handling partial/cancelled runs without error. `refresh_subtree` filters `pactable_directories` to stale ones only (via a private `is_fresh` helper comparing manifest entries and current `subtree_hash` against `decide_state`, treating unspellable paths or hash failures as not fresh) before the same `describe_and_grant`/`rewrite` sequence, passing an empty covered list so untouched entries are preserved.

**Core algorithm internals.** A private `Described` struct bundles outcomes, failures, and problems. Private `Outcome` (module, document, optional `Grant`) and `Grant` (hash plus timestamp) structs, with `Outcome::apply` (overwriting only run-owned fields on an existing `PactEntry`) and `Outcome::into_entry` (building a fresh entry). `describe_and_grant` implements the two-phase algorithm: phase one loops over directories calling `pact_directory_watched`, checking the observer for cancellation and collecting documents/undocumented directories/failures; phase two computes one shared `granted_at` timestamp and, per directory, builds an `Outcome` with a grant (via `subtree_hash`) unless that directory or a descendant failed to be documented. `rewrite` merges outcomes into an existing `Manifest`, touching only run-owned fields, preserving entry order, dropping entries for covered-but-unearned directories, and appending new entries at the end.

**Un-pacting.** `unpact_subtree` drops manifest entries at or below a selected directory without touching any files, and a private `at_or_below` helper does segment-wise (not naive string) prefix matching on manifest module paths, treating the root module as above everything.

**Single-directory pacting.** The public `pact_directory` is a thin wrapper delegating to `pact_directory_watched` with a no-op `Unwatched` observer. `pact_directory_watched` calls `gather_request`, then `summarise_over_cap`, then `demote_to_budget`, runs the agent, validates response length, and writes the document atomically via temp file and rename, mapping failures onto `Error::Refused`/`Error::Write`.

**Directory walking and request gathering.** `pactable_directories` checks `.warlockignore` on the root, walks with the same `ignore`-based rules as elsewhere, collects directories into a `BTreeSet`, and returns them in reverse sorted-path order (children before parents). `gather_request` builds an `AgentRequest` for one directory: reads child documents (reporting unreadable ones as `Problem`s with `Omission::Unreadable`), reads each own file whole if within `PER_FILE_BYTE_CAP` or else omits it (`Omission::TooLarge`), then calls `trim_to_budget`. `trim_to_budget` demotes the largest whole files to name+size (ties by path) until under `REQUEST_BYTE_CAP`, reporting each as `Omission::OverBudget`; it never needs to consider a "summarised" state since it runs before summarisation exists.

**Summarisation-under-budget.** `summarise_over_cap` handles files flagged `TooLarge`: it reads their bytes, consults the content-hash-keyed summary cache, runs a map-reduce pass over cache misses, replaces or removes `Problem` entries accordingly, and reports progress to the `Observer`. `demote_to_budget` is a three-rung algorithm fitting a request under `REQUEST_BYTE_CAP`: demote whole files to summaries (largest first, via `demote_whole_files`), lift previously-cliffed `OverBudget` files back up as summaries if room remains (`lift_from_the_cliff`), then list anything still over budget as name+size (`list_over_budget`); a `report` helper enforces one problem per file. A `Summarising<'a>` struct (borrowing directory, root, agent, observer) exposes `summary_of`, the single place a file's cached-or-fresh summary is produced.

**Pure helpers.** `chunk_utf8` splits UTF-8 text into newline-bounded chunks under `CHUNK_BYTE_CAP`, allowing an oversized single line to form its own oversized chunk. `summarise_file` runs the map-reduce over chunks via the `Agent`, announcing each pass to the `Observer`, capped by `CHUNK_COUNT_CEILING`. `summarising_pass` runs one agent call, trims the answer, and enforces `MINIMUM_SUMMARY_BYTES`. `map_request`/`reduce_request` build the corresponding prompts. Five cache functions follow: `summary_key` (blake3 digest of file bytes only, independent of path or name), `summary_dir`, `summary_file_name`, `cached_summary` (treats any read failure or blank content as a miss), and `cache_summary` (atomic temp-file-then-rename write, ignoring errors). `walk`/`Found` perform one filesystem walk gathering a directory's own files and immediate children's documents. `relative` converts a path to a manifest-relative string. `byte_count` does a saturating usize-to-u64 conversion. `file_bytes` computes one file's budget cost (full bytes, summary length, or zero if listed). `carried_bytes` totals budget usage across files and child documents.

**Trait and support types.** The `Observer` trait defines `starting` (asks whether to continue or stop per directory, returning `Pacting`), `summarising` (announces a summarisation pass, no-op by default), and `documented` (announces a finished directory, no-op by default), each documented regarding ordering guarantees and cancellability. `Pacting` (`Continue`/`Stop`) and `Unwatched` (a no-op `Observer`) follow. Result and error types close out the non-test code: `PactedSubtree` (manifest plus failures and problems), `Pacted` (a directory's document path plus problems), `Gathered` (request plus problems), `Problem` (path plus `Omission` cause, with `Display`/`Error` impls), `Omission` (`TooLarge`, `OverBudget`, `Unreadable`, `NotText`, `TooManyChunks`, `Unsummarised`, each with `Display`/`Error` impls), `Refusal` (`Agent`, `TooShort`), `Error` (`Walk`, `Path`, `Refused`, `Write`, with a `directory()` accessor), and `Failure` (`Document`, `Record`, `Hash`, with a `directory()` accessor) — covering every way a directory-level or subtree-level pact can fail short of success.

**Test module.** The remainder of the file is a large `#[cfg(test)] mod tests`, covering essentially every behavior documented above. It includes fake `Agent` implementations (`Canned`, always-fails `Fails`, scripted `Counting`, per-directory-failing `FailsFor`, map-pass-failing `FailsEveryMap`, prompt-logging `Overheard`) and fake/logging `Observer` implementations (`Watching`, which records calls and can stop after N directories; `Overhearing`, which logs summarising/starting calls into a shared `Told` log), plus numerous fixture builders (`repository`, `project`, `fat_directory`, `refreshable`, `pacted`, `with_scopes`) and helper functions for constructing requests, files, accounts, and manifests, and for inspecting gathered requests, cache entries, and manifest state.
