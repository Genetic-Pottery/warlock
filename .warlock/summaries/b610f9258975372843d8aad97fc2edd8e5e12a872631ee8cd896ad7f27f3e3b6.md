This file (`scoping.rs`) is the module implementing the scope-key workflow for a TUI-driven repository tool ("warlock"), covering everything from a keystroke to a saved `.warlock/pacts.toml` manifest.

**Module-level doc comments** explain the design philosophy: this module is the counterpart to `mod@crate::prompt` (referencing `warlock_tui::ScopePrompt`). It contrasts scope-writing with pacting (`mod@crate::pacting`): a scope change is a single synchronous write on the event loop's thread (no worker thread, channel, or account, unlike a pact run), and it triggers no tree reload since a scope is just a label, not a state/colour change. It also explains that a successful scope write produces no message (silence is intentional), that `validate_scope` is the sole judge of scope validity, and that case-folding (via `to_ascii_lowercase`) happens before validation and storage so `Data-Plane` and `data-plane` are treated as one boundary. An empty field is treated as "clear" rather than invalid.

**Imports**: `std::path::Path`; from `warlock_engine`: `Manifest`, `PactEntry`, `to_manifest_path`, `validate_scope`; from `warlock_tui`: `App`, `Edited`, `ScopeField`, `ScopePrompt`, `Sigils`; plus local `crate::error::Error` and `crate::session::closed_scope`.

**Public-in-crate (`pub(crate)`) functions:**

- `scope_press(app: &mut App, manifest: &Manifest, repo_root: &Path, sigils: &Sigils, in_flight: bool) -> ScopePrompt` — decides what pressing the scope key does. Refuses (returns `ScopePrompt::Closed`) if a run is in flight (via `app.set_pact_refused()`), if `closed_scope` (from `crate::session`) reports the directory's scope isn't held by `sigils`, or if `app.scope_target()` yields no directory (row-level refusal already messaged by `App`). Otherwise resolves the manifest path via `to_manifest_path`, looks up existing scope via `manifest.entry(&module).and_then(PactEntry::scope)`, and returns `ScopePrompt::open(module, scope)`.

- `scope_edit(app: &mut App, manifest: &mut Manifest, repo_root: &Path, prompt: &ScopePrompt, edited: Edited) -> ScopePrompt` — dispatches an `Edited` value (`Edited::Open(field)`, `Edited::Close`, `Edited::Submit`) to update the prompt state, calling `scope_submit` on submit if a field exists via `prompt.field()`.

- `scope_submit(app: &mut App, manifest: &mut Manifest, repo_root: &Path, field: &ScopeField) -> ScopePrompt` — the actual disk-writing function. Lowercases input text, treats empty as `None` (clear), else validates via `validate_scope`; on failure returns `ScopePrompt::Open(field.clone().refused(rule.to_string()))`. Checks `manifest.entry(module)` exists (else calls `no_pact_message` and sets `app.set_message`). Builds a new manifest via `with_scope_on`, saves it (`next.save(repo_root)`), and on success replaces `*manifest = next`; on failure sets an error message via `Error::Manifest`.

- `with_scope_on(manifest: &Manifest, module: &str, scope: Option<&str>) -> Manifest` — rebuilds the manifest via `Manifest::with_entries`, cloning each `PactEntry`, applying `entry.with_scope(scope)` or `entry.without_scope()` only to the matching module, preserving order and other fields (grant, document, timestamp).

**Private function:**

- `no_pact_message(module: &str) -> String` — formats the footer message shown when a scope edit targets a directory absent from the manifest, suggesting pressing `p` to pact it.

**Test module (`#[cfg(test)] mod tests`)** — extensive, using `ratatui::crossterm::event`, `tempfile::TempDir`, and `warlock_engine`/`warlock_tui` test fixtures. Notable private test helpers: `scope_press` (a shadowing wrapper calling `super::scope_press` with wildcard `Sigils::held(["*"])`), constants `HASH`, `AT`, `LAST_KEY`, `ROOT_ROW`, `ENGINE_ROW`, `TUI_ROW`, `CLOSED` (expected refusal message text), and functions `a_repo`, `tree`, `app_on`, `entry`, `pacts`, `scope_on`, `saved`, `field`, `refusal`, `press`. Tests cover: boundary/sigil enforcement (matching, wildcard, empty, unknown sigils), outer-vs-inner scope precedence, in-flight run refusal ordering, opening prompts on current/empty/missing entries, submit behavior (setting, clearing, refusing invalid/list input, case folding), save failures, missing manifest entries, file-write location/cleanliness (`.warlock/pacts.toml`), and full key-by-key integration through `scope_press`/`scope_edit`/`edit_for`.
