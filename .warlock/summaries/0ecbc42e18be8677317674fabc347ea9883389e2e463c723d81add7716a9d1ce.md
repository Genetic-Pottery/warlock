This file (`scoping.rs`) implements the scope-key path in warlock's TUI: everything from a press of `s` to a saved `.warlock/pacts.toml`. It is presented as the complementary half to `warlock_tui::ScopePrompt`, with `pacting.rs` as the sibling to contrast against — a scope write is a single synchronous edit on the event loop's thread, not a threaded "run" with progress and accounts like a pact.

Module-level doc comments lay out the design rationale before any code:
- A scope change is one string written into one manifest entry, so unlike pacting there's no worker thread, channel, progress account, or reload of the tree afterward (a scope changes no directory's colour, so re-walking the repo would be wasted work).
- A successful scope write is silent — no message, no colour — because the only fact worth stating (a `(scope)` label beside the directory) belongs to a different, not-yet-described part of the code; inventing interim wording is treated as worse than saying nothing. The message line existing before the keystroke is preserved untouched across a set or a clear.
- `validate_scope` (from `warlock_engine`) is the sole judge of validity; this module's only job before validation is ASCII-lowercase folding, so `Data-Plane` and `data-plane` are treated as the same boundary.
- An empty submitted field is not a refusal but a deliberate "clear the scope" action; a rule violation reopens the prompt with the refusal text attached, preserving exactly what was typed.

Functions defined, each with detailed doc comments:
- `scope_press(app, manifest, repo_root, sigils, in_flight) -> ScopePrompt`: decides whether pressing `s` opens the prompt. Refuses (returning `Closed`) if a run is in flight (calls `app.set_pact_refused()`, mirroring the wording used elsewhere for a second `p` or `r` mid-run) or if `closed_scope` reports the operator lacks the sigil covering that directory's scope (checked before consulting the target row, mirroring `pact_press`'s ordering). Otherwise reads `app.scope_target()` for the directory (row-level refusals already handled elsewhere), converts it via `to_manifest_path` (erroring out through the shared `Error::Manifest` display if the path can't be spelled relative to the repo root — e.g., a root outside its own repo), then reads the current scope off the manifest entry (not off the row) and opens `ScopePrompt::open`.
- `scope_edit(app, manifest, repo_root, prompt, edited) -> ScopePrompt`: dispatches an `Edited` value (`Open`, `Close`, `Submit`) from the prompt's key-handling to move the prompt state or call `scope_submit`; `Submit` with no field present (unreachable in practice since `press_for` gates on an open prompt) closes the prompt.
- `scope_submit(app, manifest, repo_root, field) -> ScopePrompt`: the actual disk-writing function. Lowercases the typed text; empty means clear (`None`), otherwise validates via `validate_scope`, returning a reopened `ScopePrompt::Open` with `.refused(...)` text on failure. Looks up the manifest entry for the field's directory; if absent (e.g. manifest hand-edited elsewhere since load), sets a message via `no_pact_message` and closes without writing. Otherwise builds a new manifest via `with_scope_on`, calls `.save(repo_root)`, and on failure reports the error and closes without mutating the caller's `manifest`; on success replaces `*manifest` with the new one and closes.
- `with_scope_on(manifest, module, scope) -> Manifest`: rebuilds a `Manifest` (via `Manifest::with_entries`) cloning every entry unchanged except the target module, which gets `.with_scope()` or `.without_scope()` applied. Preserves entry order and other fields (grant hash/timestamp, document). Explicitly shared code used both by the TUI keystroke path and by headless `warlock scope add`/`remove` commands, so both write identically. Silently no-ops if `module` isn't found (callers are expected to check first).
- `no_pact_message(module) -> String`: formats the specific message shown when the directory has no manifest entry at submit time, telling the user to press `p` to pact it first.

The remainder is a large `#[cfg(test)] mod tests` block exercising the whole pipeline without any terminal/network/`claude` dependency, using an in-memory `Tree`/`Manifest`/`App` fixture:
- Helper functions build a temp repo (`a_repo`), a fixed three-node tree (`root` stale-pacted, `crates` unpacted, `crates/engine` fresh-pacted with scope `data-plane`, `crates/tui` stale-pacted unscoped), a matching `Manifest` fixture (`pacts()`), an `App` preloaded with a prior message (`LAST_KEY`) to check it's preserved, and utilities (`scope_on`, `saved`, `field`, `refusal`, `press`) for assertions.
- A local shadow `scope_press` wraps `super::scope_press` with a wildcard `*` sigil for tests not specifically about the boundary feature.
- Tests cover: refusal when the operator's sigil doesn't match the directory's scope (with an exact expected message `CLOSED`); prompt opening when a matching sigil (including wildcard) is held; refusal when holding no sigil (`Sigils::Nothing`) or unknown sigils; unscoped directories staying open regardless of held sigils; inner scopes overriding outer ones (not being "OR"ed); in-flight run refusal taking priority over/instead of the boundary refusal, without touching the message line; repeated presses during a run being idempotent; opening on the manifest's actual current value (not the row); handling of unspellable manifest paths; Esc closing without side effects; opening on empty field for an unscoped or manifest-absent directory; the field tracking manifest state rather than row state across two different manifests.
- Further tests on `scope_submit`: successful set/clear preserving grant/document/order; invariance of run-state/message-line across set and clear; refusal of invalid input (space-containing, comma-list) leaving prompt open with exact refusal text and no disk write; case-folding before validation; save failure (blocking `.warlock` with a plain file) reporting via message and leaving the in-memory manifest unchanged; write path assertions confirming the file lands exactly at `.warlock/pacts.toml` with no stray temp files left behind (atomic rename); directory-with-no-entry writes nothing and returns a message mentioning `.` and `` `p` ``.
- Integration-style tests: `scope_edit` handling typing/abandoning without disk writes; submit with no window open being a no-op; a full simulated keystroke-by-keystroke session (press `s`, type "webx", backspace, Enter) verifying the final manifest and disk state and that run-state/message remain untouched; and a scenario where a refused value can be corrected in-place (backspace + retype) and successfully saved without reopening the window.
