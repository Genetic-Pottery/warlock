This file implements the terminal UI rendering layer for a tool called Warlock, whose screen is laid out as a footer along the bottom, a panel pane on the left, and a bordered tree pane on the right (with header and flattened tree rows). It opens with a module-level doc comment explaining that its central entry point, `draw`, is a pure function of application state and a supplied `Instant`, with no internal clock or terminal globals, which makes it possible to test deterministically against an in-memory buffer. The doc comment also describes the panel's behavior (showing an account of a running or last pact, or a compiled-in ASCII-art "mark" of the program name before any pact has run), the tree area's scrolling window behavior, hit-testing for pointer/mouse clicks, and a quit-confirmation overlay drawn last over everything else.

Its imports bring in standard time types, ratatui primitives (Frame, layout, style, text, widgets), an engine `NodeState` type, and sibling-module items (`Account`, `Line as Entry`, `App`, `Focus`, `Row`, colour helpers, `Answer`, `QuitConfirm`).

A large block of heavily documented constants follows: indentation and guide-drawing glyphs; selection/collapse markers; the compiled-in ASCII-art `MARK` (an 8-line, ~100-column block-character rendering of "WARLOCK") plus its margin constants; header height, panel indent, ellipsis marker; scrollback indicator text/key; the footer's key-help text and mouse-capture key labels, plus a width budget enforced by a compile-time assertion; pacting-mode key text; footer height; tree/panel width-sharing constants; border thickness; pulse timing; and quit-confirmation dialog constants (question text, Yes/No labels with padding, gaps, margins, computed height).

The functional core, each documented with rationale, includes: `keys_line` (assembles footer key-help depending on mouse capture); `draw` (the top-level entry point drawing panel, tree pane, footer, and optional confirmation overlay); an `Areas` struct and `areas` function splitting the screen into panel/tree/footer rects by a documented width-sharing algorithm; `tree_width`; `pane_inner`; `tree_rows_area`; `tree_height`/`panel_height` (used by the app to size its scrolling viewport); a `Hit` enum and `hit_test` mapping a screen point to a hit variant using the same layout as `areas`; `pane_block` (styles a bordered block for focus/dim state); `draw_panel` (draws either the `MARK` or the account's lines, plus a scrollback indicator); `draw_mark`/`mark_area` (draws/positions the ASCII mark centered, only if it fits given margins); `scrollback` (formats the "N more (G)" string); `panel_row` (renders one account line as a styled, truncated line); `truncated` and `display_width` (column-width-aware truncation/measurement, safe on char boundaries); `draw_tree_pane`, `draw_header`, `draw_tree` (draw the tree pane's border/header/rows, applying scroll windowing, selection highlight, and pulse colouring for an in-flight pact directory); `line` (renders one tree row's guides and marker/name spans); `guide_prefixes` (a two-pass algorithm computing per-row guide-glyph prefixes based on ancestor/sibling continuation); `pulse_colour` (computes the stale/fresh pulsing colour for the in-flight directory based on elapsed half-second phases since section start); `draw_footer` (tally line, keys line, message/pact-progress line); `noun` (words a `NodeState` for the footer tally); `draw_confirm`, `answers_line`, `confirm_area`, `confirm_size` (draw and size the quit-confirmation window).

The remainder of the file is a `#[cfg(test)] mod tests` block, large enough to span most of the file, containing constants for various terminal sizes/thresholds, numerous test-only helper functions for constructing fixture apps and inspecting rendered buffers, and dozens of `#[test]` functions. These tests verify, in turn: that tree guide lines are drawn in a fixed colour unaffected by pulse or selection highlighting; correct collapse/expand marker behavior including childless directories; that rows are coloured by `NodeState` and file rows inherit their parent directory's colour; extensive pact pulse/animation timing behavior (in-flight rows alternating stale/fresh on a timed cycle, section-based phase resets, files pulsing in lockstep with their directory); toggling file display and restoring exact prior renders; selection marker/highlight correctness; scrolling-window correctness across all selection positions in a tall fixture, with header/footer staying fixed; `tree_height` edge cases at small terminal heights; detailed footer contents (per-state counts and nouns, exact keys line content, pact-progress and refusal messages, narrow-terminal truncation, Esc wording during a pact, mouse-key wording toggling); empty/root app behavior (blank header/tree, root path naming); layout geometry for `areas`/`tree_width` (percentage/floor rules, invariant sweep across all widths) and exhaustive `hit_test` correctness across pane borders, headers, rows, panel lines, and offscreen points; the idle "mark" watermark's size thresholds, dimming, centering, and permanent disappearance once any account or pact exists; panel account rendering (one row per line, grouped under directory headings, indentation, timestamps, activity formatting, truncation with ellipsis for long/multi-byte/double-width text, live-updating elapsed-time clock, scrollback indicator behavior); focus styling (bold focused border vs. dimmed unfocused border, symmetric under toggling, without affecting tree/footer content); and the quit-confirmation modal window (size derivation from text and margins, centering, bordering, exact question/answer text with no leakage of underlying frame content, pixel-identical rendering outside the window when open vs. closed, default/moved answer highlighting, clamped rendering even at extreme terminal sizes, and the footer's three lines and wording remaining unchanged while the overlay is shown).
