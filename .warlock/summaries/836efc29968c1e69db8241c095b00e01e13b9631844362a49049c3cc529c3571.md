This part contains the entirety of a Rust source file implementing the logic for fitting a directory's contents into a size-bounded request for a model pass, plus its exhaustive test suite. There is no other part.

Structurally it consists of: a long module-level doc comment explaining the design; imports; a public `Fitted`/`fit` entry point; a large set of constants governing budgets (per-file byte cap, chunk byte cap, chunk count ceiling, minimum summary bytes, reserved tokens, estimated account bytes, minimum request bytes); two long prompt string constants (`MAP_PROMPT`, `REDUCE_PROMPT`) used to instruct a model to describe file contents without naming the file; the core gathering function `gather_request` and its helpers (`elided_or_whole`, `trim_to_budget`); the summarization pipeline (`summarise_over_cap`, `demote_to_budget`, `demote_whole_files`, `lift_from_the_cliff`, `list_over_budget`, `report`, `Summarising` struct, `chunk_utf8`, `summarise_file`, `summarising_pass`, `map_request`, `reduce_request`); a disk-backed cache for summaries keyed by content hash (`summary_key`, `summary_dir`, `summary_file_name`, `cached_summary`, `cache_summary`, related constants `SUMMARY_DIR`, `SUMMARY_EXTENSION`, `SUMMARY_KEY_CONTEXT`); directory-walking support (`Found` struct, `walk`, `relative`); byte-accounting helpers (`byte_count`, `file_bytes`, `carried_bytes`); result/error types (`Gathered`, `Problem`, `Omission` enum with variants `TooLarge`, `OverBudget`, `Unreadable`, `NotText`, `TooManyChunks`, `Unsummarised`), with `Display`/`Error` trait implementations for `Omission` and `Problem`; and an `impl Summarising` block with `summary_of`.

The design described: a directory's own files (excluding its own WARLOCK.md) plus immediate children's WARLOCK.md files and the directory's own previous WARLOCK.md are gathered into a request, walking two levels deep via the `ignore` crate with the same rules as elsewhere in the crate (no symlink following, `.warlock/` pruned, `.warlockignore` honored). Two byte caps govern what happens to oversized content: a per-file cap (1 MiB, `PER_FILE_BYTE_CAP`) and a whole-request cap derived from the agent's context window (`request_byte_cap`, based on `BYTES_PER_TOKEN=3`, `RESERVED_TOKENS=40_000`, floored at `MINIMUM_REQUEST_BYTES=64KiB`). Neither cap can fail the fit (never returns an error for being oversized); files degrade through a three-rung ladder: sent whole → summarised (via map-reduce model passes over chunks, cut on line boundaries by `chunk_utf8`, capped at `CHUNK_BYTE_CAP=768KiB` per chunk and `CHUNK_COUNT_CEILING=8` chunks) → listed as name+size only. Test file bodies are elided via a `languages` module for source files (policy independent of budget). Summaries are cached on disk under `.warlock/summaries/`, keyed by content hash only (not path/name/mtime), so renamed/unchanged files are never re-summarised, and the cache is committed to the repo, never evicted. Errors from walking or path encoding are the only fatal (`Error::Walk`, `Error::Path`) cases; everything else becomes a `Problem`/`Omission` (variants: `TooLarge`, `OverBudget`, `Unreadable`, `NotText`, `TooManyChunks`, `Unsummarised`) reported alongside a still-valid request.

The trailing test module exercises: elision of test bodies, unknown-language pass-through, budget scaling with context window, correct byte accounting for elided/summarised/omitted files, trimming/demotion ordering (largest-first, tie-broken by path), never dropping child/previous documents to make budget, ignore-rule compliance, symlink handling, per-file cap boundary behavior, chunking correctness (UTF-8 safety, line-boundary splitting, oversized single lines), the map/reduce prompt pass counting and content forbidding file-name restatement, failure/short-answer handling at each pass, and the on-disk summary cache's key derivation, hit/miss/corruption handling, and file-writing behavior (via a hand-written `Counting` fake agent and various fixture-building helper functions like `document`, `write`, `filler`, `share`, `not_text`, `multibyte_text`, `one_long_line`, `text_of_chunks`, `account`, `summary`, `entry`, `entries`).
