This file implements the machinery that drives a documentation "pact" (or refresh) pass on a worker thread, from keystroke to saved manifest, plus an extensive test module covering that machinery.

It opens with a module-level doc comment explaining the flow — `pact_press`, `spawn_pact`, `apply_progress`, `refresh_press` — and distinguishing cancellation (Esc, via `CancelGuard`, saves whatever finished) from quitting (kills the in-flight `claude` process, leaves the manifest untouched). Imports draw on `warlock_engine` (manifests, trees, pacting, subtree operations, observer traits) and `warlock_tui` (App, Activities, Cancel, ClaudeAgent, Outcome, PactToggle, Run, Section), plus local error/session helpers. Two footer-message constants are defined: `PACT_LOST` (worker died without reporting) and `PACT_CANCELLED` (run stopped by Esc).

Core types: `Running` bundles an in-flight run's event receiver, `CancelGuard`, the requested `Work`, and a pre-toggle snapshot of `App` for rollback. `Work` unifies "Pact" (toggle a subtree via `PactToggle`) and "Refresh" (redo stale directories) as one pipeline, with `path()`, `kind()` (maps to `Run::Pact`/`Run::Refresh`), and `is_cancellable()` (false only for un-pacting, which is instantaneous manifest arithmetic). `CancelGuard` wraps a `Cancel` handle and cancels the worker on any exit path via `Drop`. `PactEvent` enumerates everything a worker reports over its channel — `Starting`, `Doing`, `Summarising`, `Documented` (a finished subtree, triggering an early green repaint), and exactly one terminal `Finished` — with strict ordering guarantees.

Supporting functions: `activity_port` forwards activity reports into the channel as `Doing` events per-run; `Reporting` implements `PactObserver`, checking the cancel flag on `starting` and forwarding `summarising`/`documented` unconditionally, ignoring send failures as meaning the app quit. `spawn_pact` clones state, builds a per-run `ClaudeAgent`, and spawns the worker thread, dropping the join handle. `start_run` combines `CancelGuard::new`, `spawn_pact`, and `Running` construction, used by both pact and refresh key handling. `run_pact` is the worker body: calls `apply_toggle`, rewrites the outcome via `cancelled()` if stopped, and sends one `Finished`. `cancelled` marks an outcome ungranted with the `PACT_CANCELLED` message while leaving the manifest as-is. `pact_press` refuses if a run is in flight, otherwise delegates to `App::toggle_pact` and starts a fresh account only when pacting in (not un-pacting). `refresh_press` mirrors this, always starting an account when it runs. `apply_progress` drains events since the last frame and applies them to update sections/state/colors/rows for `Starting`, `Doing`, `Summarising`, and `Documented`.

The remainder of the file is a large unit-test module (no separate declaration point given, continuing directly from the production code) exercising this machinery in depth:

- Chunked/over-cap file passes report ordered, numbered parts between `Starting` events without affecting the run's granted outcome.
- A `stand_in` helper fakes the `claude` CLI to verify `spawn_pact`'s real port-wiring (activities and a single `Finished` flow through correctly); a missing `claude` binary yields an ungranted run with a one-line message.
- Keypress-driven UI logic (`pact_press`, `refresh_press`) against a bare model: refusal wording while a run is in flight, refusal on file/ignored rows, correct account start/continuation semantics across pact/un-pact/refresh, and "already fresh" refresals.
- Cancellation semantics: descent stops between (not within) directories in reverse-path order; only finished directories are saved/granted; the subtree is never marked fully granted after a cancel; panel/account reflect exactly what finished plus `PACT_CANCELLED`.
- Refresh-specific behavior: only stale directories and ancestors are visited/counted; clean directories keep prior manifest entries; cancelled refreshes behave like cancelled pacts.
- Dropping a `Running` (simulated quit) cancels its guard, avoiding orphaned processes.
- A `a_run_in_flight` fixture builds a minimal panel-testing setup.
- Detailed `apply_progress` rendering tests: ticking clocks per open section, activity lines, cost accumulation without extra lines, frozen older lines, independent per-directory clocks in walk order, and `Finished` closing the run with a summary line and separately-reported reload status (`NOT_REFRESHED`).
- Live recoloring on `Documented` events, and document-row insertion into the displayed tree (correct sort position, idempotence, no-op if directory absent, no node-count change, no reload needed).
- Preservation of reader selection, collapse state, filters, and scroll through a run.
- A channel-dropped run (no outcome) leaves prior lines with frozen clocks, sets `PACT_LOST`, and restores rows to the last known manifest.
- `FRAME`, `recorded`/`recorded_from` (run a real worker and collect its events), and `replay`/`replay_work` (feed recorded events frame-by-frame into `apply_progress`) plus `document_bytes` support full end-to-end tests: per-section "wrote N bytes, $cost" summaries, refusal messages matching the engine's own wording, and cancelled full runs showing partial summaries and "cancelled — $X spent".
- Panel/document-card interaction tests confirm an open document view survives a run untouched (via `swap_card`) across normal finish, cancellation, refusal, and rollback/`PACT_LOST` endings.
- An 8-crate fixture shows a refresh's reported progress and panel sections reflect only directories actually visited, not the whole subtree.
- Tests for a pass reporting no cost ("no cost reported", "(incomplete: ...)") and for total channel loss (`PACT_LOST`, no manifest write, rows revert).
- Post-run tree freshness: newly written documents appear as `PactedFresh` rows since the tree is rebuilt from the just-saved manifest.
- Reload preserves reader state (viewport, collapse, filters, scroll, selection) across a pact.
- Un-pacting reloads via the same mechanism, reverting affected paths to `Unpacted`.
- A failing reload keeps the on-screen tree intact while the run's own successful outcome stands, reporting a one-line `NOT_REFRESHED` message.
- Message precedence: a pact's own message beats a reload failure message in the footer.
- A unix-only test using `chmod` to induce unreadable files during reload: the new tree (with new files) is still adopted, the affected node shown conservatively as `PactedStale`, and the footer reports a hashing problem count ("and N more like it"); permissions are restored afterward.
- A `watching` submodule (doc-commented) tests filesystem-change reaction without a real OS watcher, using `Watching::Off` and direct calls to `WatchPolicy` methods (`accepted`, `owes_reload`, `round`, `caught_up`), plus an `unwatched(scope)` helper building a `Watched` from the real on-disk tree. Its tests cover: watcher-driven reload after the debounce quiet period while preserving reader state; a trigger arriving mid-pact being deferred until the run's own reload, with the owed-reload flag cleared and no double reload even past the reload ceiling; and the one-line "live updates off" note (`NOT_WATCHING`-prefixed) appearing once, never overwriting or being overwritten by a later pact message, and not appearing at all when a real watcher starts successfully.

The tests throughout depend on helpers and types declared elsewhere in the module or crate (`toggle`, `refreshing`, `pact_of`, various fixture builders, `load`, `load_tree`, `state_of`, `Manifest`, `NodeState`, `Toggled`, `Scope`, `Canned` agent, and constants such as `NOT_REFRESHED`, `NOT_WATCHING`, `POLL_INTERVAL`, `QUIET_PERIOD`, `RELOAD_CEILING`, `MINIMUM_DOCUMENT_BYTES`, `DOCUMENT_FILE`). The file ends with the closing of the `watching` submodule and the outer test module.
