This file implements a terminal UI rendering layer built on ratatui, laying out a screen with a bottom footer, a left panel pane, and a bordered right tree pane. It opens with a module doc comment describing this layout and the design principle that drawing is a pure function of application state and a caller-supplied `Instant`, with no access to the terminal, globals, or the system clock, which keeps rendering testable via in-memory buffers. The panel has two states: before any pact has run it shows a compiled-in ASCII/block-art "mark" spelling "WARLOCK"; once a pact has run it shows directory headings with per-line activities and elapsed clocks. The tree pane shows a scrollable window of already-flattened rows, with collapsing state owned by the app rather than the widget. A separate pure function, `hit_test`, maps a screen point to a named UI region for mouse interaction.

Imports draw on standard-library time types, ratatui's widget/layout/style/text types, the engine's `NodeState`, and sibling modules: `account::{Account, Line as Entry}`, `app::{App, Focus, Row}`, and `colour::{FOCUS_COLOUR, GUIDE_COLOUR, colour_for}`.

A block of heavily documented constants follows: glyphs for tree guide lines and indentation (`INDENT`, `GUIDE`, `GUIDE_BRANCH`, `GUIDE_LAST`); row markers for selection/collapse state (`SELECTION_MARKER`, `COLLAPSED_MARKER`, `EXPANDED_MARKER`, `NO_MARKER`); the `MARK` ASCII-art array itself (8 rows, ~104 columns) plus its margin requirements (`MARK_MARGIN`, `MARK_MARGIN_ROWS`); layout constants (`HEADER_HEIGHT`, `PANEL_INDENT`, `ELLIPSIS`, `SCROLLBACK_ARROW`, `FOOTER_HEIGHT`, `TREE_PERCENT`, `TREE_MIN_WIDTH`, `BORDER_THICKNESS`); key-hint strings and a `keys_line(mouse_captured: bool)` function combining them, plus a separate `PACTING_KEYS` set for while a pact is running; and `PULSE_PHASE` (500ms), which governs the alternating colour of the in-flight directory row during a pact.

The core entry point is `draw(frame, &App, Instant)`, which computes an `Areas` struct via `areas()` (splitting the frame into panel/tree/footer rects, with documented rules for proportional width-splitting, a minimum floor, and a narrow-terminal fallback to halving the width) and delegates to `draw_panel`, `draw_tree_pane`, and `draw_footer`. Supporting geometry helpers include `tree_width`, `pane_inner` (strips a pane's border), `tree_rows_area` (strips the tree pane's header), and the public `tree_height`/`panel_height`, which report how many content rows are available given a terminal size, used by the app to compute scroll windows.

A public `Hit` enum (`Offscreen`, `Footer`, `Border`, `TreeHeader`, `TreeRow{offset}`, `TreeBelowRows`, `PanelLine{offset}`) is produced by the public `hit_test(column, row, size)` function, which reuses the `areas()` layout logic to map a point to a region.

Rendering helpers include: `pane_block` (bordered `Block`, styled bold/`FOCUS_COLOUR` when focused, dim otherwise); `draw_panel` (renders either the mark or windowed account lines, with a scrollback indicator in the border title when scrolled back); `draw_mark`/`mark_area` (centers and conditionally draws `MARK`, omitting it when there's insufficient room); `scrollback` (formats a "↓ N more (key)" string); `panel_row` (converts an `Entry` — Directory/Clocked/Summary — into a styled, width-truncated `Line`); `truncated` (column-width-safe truncation with an ellipsis, character-boundary safe); and `display_width` (measures display column width via ratatui's `Span::width()`).

Tree-pane rendering is handled by `draw_tree_pane` (border, header, rows), `draw_header` (bold heading naming the tree), `draw_tree` (slices the app's flattened rows to the visible window, builds `ListItem`s with guide prefixes, markers, collapse state, and pulse-colour overrides for the in-flight row, rendered as a stateful `List` with selection highlighting), `line` (builds one row's styled `Line` from guide prefix and marker/name spans, using `GUIDE_COLOUR` for guides and state or pulse colour for the row itself), `guide_prefixes` (a two-pass algorithm computing per-row indentation/guide strings for a window of rows — a backward pass determining sibling continuation, a forward pass building strings from an open-ancestor stack), and `pulse_colour` (computes the alternating stale/fresh colour for the in-flight directory row from elapsed time and `PULSE_PHASE`).

Footer rendering is handled by `draw_footer` (tally line of counts per `NodeState`, a keys line using either `PACTING_KEYS` or `keys_line()`, and a message line showing pact progress or the last message) and `noun` (maps `NodeState` variants to display words: "unpacted", "stale", "fresh").

The remainder of the file is a `#[cfg(test)] mod tests` block containing no production code, only test infrastructure and `#[test]` functions. It defines constants for terminal dimensions and timing (`MANY`, `WIDTH`, `HEIGHT`, `CHROME_HEIGHT`, `KEYS_WIDTH`, `FILES_HEIGHT`, `FIXTURE_HEIGHT`, `MARK_WIDTH`, `BELOW_MARK_WIDTH`, `MARK_HEIGHT`, `BELOW_MARK_HEIGHT`, `MARK_ROOM_WIDTH`, `MARK_ROOM_HEIGHT`, `STANDARD_WIDTH`, `NARROW_WIDTH`, `PHASE`, `CYCLE`) and many helper functions for building apps/fixtures and inspecting rendered output (`many_rows`, `tall_app`, `at`, `numbered`, `pacting_app`, `panel_area`, `panel_rows`, `panel_bottom_edge`, `rows_area`, `header_area`, `tree_rows`, `tree_row`, `header_text`, `header_and_footer`, `drawn_row`, `render`, `render_at`, `row_text`, `text_in`, `rows_text`, `GUIDE_GLYPHS`, `first_glyph_colour`, `column_of`, `guide_columns`, `row_index`, `highlighted_rows`, `mark_width`, `assert_mark_drawn`, `assert_bare_panel`, `assert_no_mark`).
