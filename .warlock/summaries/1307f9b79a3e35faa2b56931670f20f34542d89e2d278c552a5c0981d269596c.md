This is the complete `ui.rs` source file (part 1 of 1), containing the rendering layer of warlock's terminal UI, plus its test suite.

**Structure and content:**

1. **Module doc comment** — describes the overall frame layout: a footer along the bottom, a panel pane (left) and a bordered tree pane (right) above it, with a composer field cut from the bottom of the panel's column. Explains the panel shows one of three "cards" (account of a running pact, conversation thread, or a document), the tree window scrolling model, hit-testing for pointer clicks, and the quit-confirmation overlay.

2. **Constants** — a large block defining: indentation/guide glyphs for the tree (`GUIDE`, `GUIDE_BRANCH`, `GUIDE_LAST`), selection/collapse markers, the compiled-in ASCII-art `MARK` logo and its margins, header/run-header layout heights, footer key-line labels (movement, fold, pact, refresh, scope, focus, compose, quit, mouse toggle, etc.) and their drop-order priority lists (`KEY_DROP_ORDER`, `PACTING_KEY_DROP_ORDER`) used to shrink the footer on narrow terminals, sizing constants for the quit-confirmation window and the scope/path prompt window (margins, heights, cursor glyph), and border thickness.

3. **Layout functions** — `areas`/`Areas` struct cutting the terminal into panel, composer, tree, footer regions; `split_column` (panel vs composer height); `tree_width`; `pane_inner`; `panel_split` (run-header vs account rows); public sizing/measurement functions used by the app to compute scroll windows: `tree_height`, `panel_height`, `run_header_height`, `composer_height`, `panel_width`.

4. **Hit-testing** — `Hit` enum and `hit_test` function mapping a screen point to a semantic location (footer, border, tree header/row, panel header/line, composer), using the same `areas` layout as drawing.

5. **Drawing functions** — `draw` (top-level entry point), `pane_block`, `draw_panel` (with mark-drawing fallback, run header, scrollback indicator), `draw_run_header`/`run_header_line`/`bar` (progress bar), `draw_mark`/`mark_area`, `draw_composer`, `panel_row`/`truncated`/`display_width` helpers, `draw_tree_pane`, `draw_header`/`header_line` (chrome/sigils), `draw_tree`, `line` (single tree row rendering with scope labels), `guide_prefixes` (tree guide computation), `pulse_colour` (animated in-flight directory highlighting), `draw_footer`/`footer_text_area`/`noun`, `draw_confirm`/`answers_line`/`confirm_area`/`centred`/`confirm_size` (quit dialog), `draw_scope`/`scope_lines`/`scope_size` (shared scope/path prompt window).

6. **Extensive `#[cfg(test)] mod tests`** — a very large suite (the bulk of the file) covering: tree row rendering/indentation/guides/collapse markers/file rows/scope labels, pulse animation timing, footer tally/keys-line layout and truncation at various widths (including drop-order behavior), header composition with sigils, panel content (mark vs account vs document vs thread), run header rendering and scrollback counting, composer sizing/muting/focus-border behavior, hit-test correctness for all regions, and the quit-confirmation and scope/path prompt windows (sizing, centering, clamping on tiny terminals, non-leakage of underlying content, cursor position, refusal messages).

Nothing else is present — this is the entire file's contents, self-contained (no truncation markers, no continuation into further parts).
