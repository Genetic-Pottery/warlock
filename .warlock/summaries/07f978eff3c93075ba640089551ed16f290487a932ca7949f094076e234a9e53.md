This is the full and only part of a Rust source file for a module that decides how a directory's contents are fitted into a request an AI agent pass can be handed, given two byte budgets.

It opens with an extensive module-level doc comment explaining the design: the module owns the question of, given a directory and two byte caps, what the `agent::Request` should contain. It describes the single entry point `fit` (a `pub(crate) fn`), which walks a directory, gathers files and children's `WARLOCK.md` documents, and returns either a `Fitted` result or an `Error`. The documentation lays out a four-step "ladder": gather, describe over-cap files via summarization, fit the whole request to budget, and announce the weight via an `Observer`. It explains the policy that files are never truncated — only sent whole, summarized, or listed by name/size — and that going over either cap is never fatal (surfaced instead as non-fatal `Problem`s). It also describes a persistent summary cache under `.warlock/summaries/`, keyed by content hash (not path/name), used to avoid re-paying for expensive summarization passes across pacts.
