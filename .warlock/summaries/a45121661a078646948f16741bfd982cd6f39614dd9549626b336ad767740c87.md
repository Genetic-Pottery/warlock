This is the complete `main.rs` for warlock's terminal front end binary, presented as a single part.

**Module-level documentation (a long series of doc comments preceding the code):** These describe the binary's role as the "thin, impure shell" around `warlock_tui`, owning terminal lifecycle, working directory, and the event loop. It lists sibling modules and their responsibilities (`input`, `pacting`, `chatting`, `scoping`, `viewing`, `editing`, `writing`, `session`, `terminal`, `error`). The prose explains, in depth: the guarantee that the terminal is always restored (normal quit, error, panic); how the pact key spawns a worker thread and polls a channel without blocking; how the refresh key (`r`) shares the same `Pact`/worker/channel machinery as the pact key so only one run can proceed at a time; how run events populate an `Account`/panel with live timing; why `reload_tree` re-reads the tree after a run, an un-pact, an edit, or a filesystem watch event (via `Watched`/`WatchPolicy`), preserving selection/collapse/filter state; the two ways to stop a run (Esc=cancel vs q/Ctrl-C=quit) via a shared `Cancel`; mouse handling through `TerminalGuard` and `mouse_action`; the quit-confirmation gate (`QuitConfirm`) and `press_for`'s five possible dispositions of a keystroke; the chat composer's special keyboard-capture behavior; the scope prompt (`s` key) as a synchronous, no-reload manifest write; and why Ctrl-C and in-flight-run cases bypass the confirmation gate. It then documents the CLI subcommands (`init`, `config`, `stale`, `fresh`, `check`, `unpact`, `pact`, `refresh`, `scope add`/`remove`) — which don't touch the terminal, which only read vs. write, how the scope boundary is checked before edits, and the full exit-status vocabulary (0 completed, 1 warlock failure, 2 clap malformed input, 3 boundary refusal, 4 partial failures, 130 cancelled via Ctrl-C).

**Imports:** standard library (`io`, `PathBuf`, `ExitCode`, `Duration`, `Instant`), `clap`, `ratatui` crossterm/layout types, `warlock_engine` items (`Agent`, `Manifest`, `Written`, `write_claude_md`), `warlock_tui` items (`App`, `Composer`, `Converses`, `Focus`, `QuitConfirm`, `Run`, `ScopePrompt`, `Wired`, helper functions), and declares all the sibling modules plus a test-only `stubs` module, then imports specific items from each local module.

**Constants:** `POLL_INTERVAL` (100ms, event polling interval), `CREATED`/`UPDATED` strings for `init` output, `CANCELLED` (130, SIGINT-based exit code).

**`Cli` struct and `Command`/`ScopeCommand` enums:** clap derive types defining the full command-line surface — `Init`, `Config`, `Stale{path,json}`, `Fresh{path,json}`, `Check{path,json}`, `Unpact{path}`, `Pact{path}`, `Refresh{path}`, `Scope{command: Add{path,scope}/Remove{path}}` — each documented with rationale for required vs. optional path arguments, absence of a `--force`/`--version` flag, and why `about` is set explicitly with `long_about = None`.

**`fn main() -> ExitCode`:** Parses CLI args first (before touching terminal), installs panic hook only for the no-subcommand (`run()`) path, dispatches each `Command` variant to its handler function, prints `warlock: {error}` on failure, and returns `ExitCode::from(status_for(&outcome))`.

**`fn status_for`:** Maps a `Result<(), Error>` to the numeric exit status (0/1/3/4/130), with extensive doc commentary justifying each number and explaining why `ClosedScopeBelow` stays 1 rather than 3.

**`fn init()`:** Implements `warlock init` — resolves standing/repo root, calls `write_claude_md`, prints whether the file was `created` or `updated`.

**`fn run() -> Result<(), Error>`:** The main interactive loop entry point — loads the tree/manifest, starts the filesystem watcher, enters the terminal guard, constructs a `Session`, and loops: measure size, draw, poll for an event (key or mouse) with `POLL_INTERVAL` timeout, dispatch to `session.press`/`session.point`, then call `session.keep_up()` each round regardless of whether an event arrived.

**`struct Session<S: Screen, P: Wired + Agent, C: Converses>`:** Generic container replacing the eleven loose locals `run` used to thread through functions, holding `app`, `screen`, `scope`, `manifest`, `pact`, `chat`, `confirm`, `prompt`, `document`, `mouse_captured`, `watched`. Documented as generic specifically to allow test doubles at the `Screen`/`Agent`/`Converses` seams.

**`impl<S,P,C> Session<S,P,C>`:** Methods `size`, `draw` (sets viewport/panel dimensions, mouse-capture flag, renders frame), `point` (delegates to `apply_mouse`), `press` (the large match over `Pressed`/`Action` values from `press_for`, handling: leave/quit, confirm-dialog updates, cancel-pact, cancel-turn, focus/selection movement, collapse/pacted-only/files toggles, pact/refresh triggering via `Pact::press`, view-file, edit-file, swap-card, toggle-mouse-capture, open-scope/scope-edit, write-edit, and compose actions), and `keep_up` (drains pact progress via `Pact::keep_up`, feeds watcher state, drains chat turns via `Chat::keep_up`).

**`fn apply_mouse`:** Free function translating a `mouse_action` result into app mutations (select rows, scroll panel, toggle collapse, change focus).

**`mod tests`:** An extensive test module covering: CLI parsing correctness for every subcommand and flag combination (including malformed-invocation and help-text checks), the exit-status vocabulary's distinctness, a `FakeScreen` implementing the `Screen` trait for in-memory testing, helper builders (`session`, `session_over` using a real temp-directory repository, `rounds_until_settled`), and behavioral tests exercising `Session::press` directly: pact key descending a subtree and writing `WARLOCK.md` files, a second press un-pacting, quit key opening confirmation rather than leaving, Ctrl-C leaving immediately, answering "No" keeping the session open, focus-key toggling, mouse-capture toggling reporting through the fake screen, edit key refusing on a directory row without ever suspending the screen, and the scope prompt swallowing keys (including Esc closing it) rather than letting them reach normal key handling.
