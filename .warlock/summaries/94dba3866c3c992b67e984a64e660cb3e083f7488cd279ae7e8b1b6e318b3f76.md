This is a complete Rust module implementing warlock's "composer" — the multi-line draft field at the foot of the panel column — plus its exhaustive test suite. It opens with an extended module doc comment explaining the design: the composer is a buffer editor supporting only append, backspace, newline (Alt+Enter), submit (Enter), and leave (Esc); the cursor is always after the last character so no cursor-position state is tracked; single-letter tree commands (`p`, `r`, `s`, `v`, etc.) must remain typeable as plain text; Shift+Enter is deliberately unbound because terminal support is inconsistent; Ctrl-C is handled upstream by the event loop, not here; and muting (declining input while an answer/run is in flight) is tracked as a passed-through flag rather than decided here.

Key public items:

- `pub const COMPOSER_MAX_ROWS: u16 = 6` — cap on composer height.
- `const CHORD: KeyModifiers` (private) — union of CONTROL, ALT, SUPER, HYPER, META, used to distinguish command chords from typed text.
- `pub struct Composer` with private fields `draft: String` and `muted: bool`, deriving Debug, Clone, Default, PartialEq, Eq, Hash. Its methods:
  - `pub fn new(draft: impl Into<String>) -> Self` — constructs a live (unmuted) composer.
  - `pub const fn set_muted(&mut self, muted: bool)` — sets muted flag, told by the event loop each round.
  - `pub const fn is_muted(&self) -> bool`.
  - `pub fn draft(&self) -> &str`.
  - `pub fn is_submittable(&self) -> bool` — false if draft is empty or whitespace-only (uses `trim().is_empty()`).
  - `pub fn height(&self, width: u16) -> u16` — rows needed, capped at `COMPOSER_MAX_ROWS`.
  - `pub fn window(&self, width: u16) -> Vec<String>` — tail rows that fit within the cap (so cursor row is always visible).
  - `fn rows(&self, width: u16) -> Vec<String>` (private) — splits draft on `\n` and wraps each line via `wrapped` (imported from `crate::wrap`).
- `pub enum Composed` (Debug, Clone, PartialEq, Eq, Hash) with three variants: `Typing(Composer)`, `Leave`, `Submit`.
- `pub fn compose_for(key: KeyEvent, composer: &Composer) -> Composed` — the pure function mapping a key event and current composer to a `Composed` outcome. Handles: non-Press events (no-op), Alt+Enter (insert newline), plain/Shift Enter (submit if submittable, else no-op), Esc (Leave), Backspace (pop last char, or no-op if empty), plain printable Char without chord modifiers/control chars (append), and everything else (no-op/unchanged). Internally uses closures `unchanged` and `typed` (the latter preserving the `muted` flag from the input composer).

It imports `KeyCode, KeyEvent, KeyEventKind, KeyModifiers` from `ratatui::crossterm::event` and `wrapped` from `crate::wrap`.

The `#[cfg(test)] mod tests` section is extensive, containing helper functions `press`, `alt_enter`, `composer`, `after`, `character`, and a `const BINDINGS: [KeyCode; 18]` array of all tree-bound keys plus unbound ones, used to verify the composer swallows every such key as either text or a no-op. Tests cover: default emptiness, muting behavior and persistence across keystrokes, character appending (including no folding/refusal of punctuation/digits), backspace (including multi-byte character safety and newline deletion, and no-op on empty), Alt+Enter newline insertion (never submits), Enter submission rules (submits non-blank, no-ops on blank/whitespace-only), Esc always leaving, all tree bindings being swallowed, ensuring no key besides Enter submits or besides Esc leaves, Ctrl-C being ignored here, chord/control characters not being treated as text, Shift+letter typing normally and Shift+Enter behaving like Enter, releases/repeats being no-ops, absence of cursor-movement/editing keys (Left, Right, Home, End, Delete, Insert, BackTab, Up, Down) having any effect, and thorough height/window arithmetic tests (empty draft, in-width draft, newlines, wrapping, growth up to cap, exceeding cap, tail-window behavior, zero width, and bounds-checking height never zero/never exceeding cap across many drafts and widths).
