This file defines the "agent seam" of the warlock-engine crate: the boundary between the engine's domain logic and the transport that actually talks to a model (the `claude` CLI subprocess), which lives in a separate binary. The engine spawns no processes itself.

Structure and contents:

**Module doc comment**: Explains the design rationale — the engine defines the `Agent` trait and its request/response types; the binary implements the trait by spawning `claude`. Three stated consequences: (1) engine tests need no real `claude`/network/terminal since fakes implement `Agent`; (2) no process type (e.g. `std::process::ExitStatus`) crosses the seam — `Error::Failed` uses a plain `Option<i32>` exit code and a `String` for stderr; (3) `Request` is "transport, not payload" — it carries prompt, directory, the directory's own files, and immediate children's `WARLOCK.md` documents, but not decisions about how that scope was gathered. Also explains why errors are a multi-variant enum rather than one `Io` bucket — each failure mode (missing binary, non-zero exit, empty output, timeout) implies a different caller response.

**`STDERR_EXCERPT`** constant (200): limits how much stderr appears in a one-line `Display`.

**`Agent` trait**: single method `run(&self, request: &Request) -> Result<Response, Error>`. Doc includes a runnable example implementing a `Canned` fake agent. `&self` (not `&mut self`) allows shared/reusable implementations.

**`Request` struct**: private fields `prompt: String`, `directory: PathBuf`, `files: Vec<File>`, `child_documents: Vec<ChildDocument>`. Built via `Request::new(prompt, directory)` (infallible, no validation) plus additive builder methods `with_files` and `with_child_documents` (append, don't replace, callable multiple times). Accessors: `prompt()`, `directory()`, `files()`, `child_documents()`. Notably there is no dedicated slot for the directory's own existing `WARLOCK.md` — it's expected to appear as an ordinary entry in `files()`.

**`File` struct**: represents one file in the request's directory, with `path: String` (forward-slash relative path) and a private `content: Content` enum with three variants:
- `Bytes(Vec<u8>)` — file sent whole (raw bytes, not text, since files may be binary/non-UTF-8).
- `Omitted(u64)` — file listed by size only, contents deliberately left out, never truncated (design principle: no partial/truncated sends, since that invites wrong inferences).
- `Summarised { size: u64, summary: String }` — a name, size, and a prose account of contents written by an earlier pass that read the whole file; explicitly not a truncated excerpt of the file's actual text.

Constructors: `File::present`, `File::omitted`, `File::summarised`. Accessors: `path()`, `bytes()` (Some only for Bytes), `size()` (always answered), `summary()` (Some only for Summarised), `is_omitted()` (true only for Omitted, not Summarised).

**`ChildDocument` struct**: represents one immediate child directory's `WARLOCK.md` text as seen by a parent's pass. Fields `directory: String` (relative, forward slashes) and `text: String`. Only immediate children appear — grandchildren are already summarized transitively. Constructor `ChildDocument::new`, accessors `directory()` and `text()`.

**`Response` struct**: wraps `text: String` — the model's raw, unparsed output. Constructor `new`, accessors `text()` and `into_text()`.

**`Error` enum** (`#[non_exhaustive]`, hand-rolled without an error-handling crate dependency, mirroring other hand-rolled errors in the crate):
- `NotFound { program: String }` — command not on PATH.
- `Failed { code: Option<i32>, stderr: String }` — non-zero exit or killed before setting a code.
- `EmptyOutput` — clean exit but nothing on stdout.
- `TimedOut { after: Duration }` — did not finish in time.
- `Io { source: std::io::Error }` — other I/O failure.

Implements `Display` (single-line messages; `Failed` flattens and excerpts stderr via the `one_line` helper, naming the exit code or noting it was killed) and `std::error::Error` (only `Io` has a `source()`).

**`one_line` helper function**: collapses whitespace runs into single spaces and truncates to `STDERR_EXCERPT` characters (counting chars, not bytes, to avoid breaking multi-byte boundaries), appending `…` if truncated.

**Tests module** (`#[cfg(test)]`): Includes two fake `Agent` implementations — `Canned` (records calls, returns fixed markdown) and `Refuses` (always returns `Error::NotFound`) — used to demonstrate/verify the trait works without any real subprocess. A `every_variant()` helper builds one instance of each `Error` variant for shared property tests. Tests cover: basic run behavior and call recording; running multiple passes through one agent; error propagation; `Request` construction with/without files and child documents; builder append semantics; the three `File` content states and their accessor behavior individually and comparatively; that a directory's own `WARLOCK.md` is just an ordinary file entry, not a special child document; that widening `Request` doesn't break existing `Agent` implementations; `Display` formatting properties for all error variants (single line, named program instead of raw errno, stderr flattening/excerpting for long stderr, timeout duration reporting); and that only `Io` errors expose a `source()`.
