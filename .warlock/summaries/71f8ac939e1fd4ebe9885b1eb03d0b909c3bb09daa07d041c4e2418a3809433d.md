This file implements Warlock's directory-summarisation and pacting pipeline, along with its full test suite.

It begins with the `MAP_PROMPT` string constant, heavily documented with doc comments explaining why it is hard-coded as source (no config file, template, or override) alongside the sibling `PROMPT` and `REDUCE_PROMPT` constants defined elsewhere. The comments explain the prompt's assumptions: it is called once per chunk of a file, sees only that chunk (never other files, a child document, or earlier map answers), is told which part of how many it is, and receives chunks cut on line boundaries by `chunk_utf8` so each is valid UTF-8 even if it splits a function mid-body. Because the model's answer is the only thing that survives (original bytes are read once and discarded), the prompt forbids naming the file (summaries are cached/keyed by content bytes alone, so a renamed-but-unchanged file can reuse a prior summary, and naming the file in the answer would go stale on rename), forbids guessing about unseen parts, and forbids any wrapping of the answer (no preamble, heading, or code fence). The literal `MAP_PROMPT` text carries these same instructions to the model.

The rest of the production code implements: `view_file`, which reads a file for display, truncating honestly at a UTF-8 boundary or erroring with `Unviewable::NotText`; `read_capped`, which bounds reads to `PER_FILE_BYTE_CAP + 1` bytes so oversized files are never fully loaded; and a sequence of budget-management functions — `trim_to_budget` (demotes the biggest files to name-and-size omissions, with no model access, to fit `REQUEST_BYTE_CAP`), `summarise_over_cap` (turns individually-too-large files into cached or freshly map-reduced summaries), and `demote_to_budget` (a three-rung whole-request demotion: shrink to summaries, lift previously-cliffed files back up if they now fit, then demote anything still too big to bare name/size), built on helpers `demote_whole_files`, `lift_from_the_cliff`, `list_over_budget`, and a shared `report` helper enforcing one problem entry per file. A `Summarising<'a>` struct bundles shared context (`directory`, `root`, `agent`, `observer`); its `summary_of` method checks an on-disk cache before paying for passes. `chunk_utf8` splits file bytes into newline-bounded, UTF-8-valid chunks under `CHUNK_BYTE_CAP`, letting a single overlong line become its own oversized chunk, and erroring on non-text. `summarise_file` runs the actual map-reduce over chunks, failing fast on bad passes, skipping reduce for single-chunk files, and announcing each pass via `observer.summarising` with correct part/total counts; `summarising_pass` runs one agent call and demotes to `Omission::Unsummarised` if the answer is too short or errors; `map_request`/`reduce_request` build the prompts (chunks embedded as text, never as `AgentFile`; reduce lists numbered accounts).

A block of cache helpers operates over `<root>/.warlock/summaries/`: `summary_key` (a blake3 keyed hash of file bytes only, independent of path or name — the whole change-detection mechanism), `summary_dir`, `summary_file_name`, `cached_summary` (treats any failure or blank content as a miss), and `cache_summary` (atomic temp-file-then-rename write, with ignorable errors).

Filesystem and accounting helpers follow: `Found`/`walk` (a single ignore-aware, depth-limited walk collecting a directory's own files and its children's `WARLOCK.md` documents into ordered maps), `relative`, `byte_count`, `file_bytes` (budget cost of one `AgentFile`), and `carried_bytes` (total budget cost of a request).

The public API/type section defines: the `Observer` trait (`starting` returning `Pacting`, plus no-op-default `summarising`/`documented` announcements, deliberately without `Send`/`Sync`/`'static` bounds); `Pacting` (`Continue`/`Stop`); `Unwatched` (a no-op `Observer`); `PactedSubtree`, `Pacted`, `Gathered`, `Viewed` (result/data types for subtree pacts, single pacts, gathered requests, and file views); `Unviewable` (`Unreadable`/`NotText`); `Problem` (path plus an `Omission` cause); `Omission` (`TooLarge`, `OverBudget`, `Unreadable`, `NotText`, `TooManyChunks`, `Unsummarised`), each with detailed `Display` messages; `Refusal` (`Agent`, `TooShort`); the top-level `Error` (`Walk`, `Path`, `Refused`, `Write`), each naming its directory; and `Failure` (`Document`, `Record`, `Hash`) for per-directory subtree-pact failures.

The remainder of the file is a large `#[cfg(test)] mod tests` block containing only tests, fixtures, and test doubles — no further production code. It covers, in order: request-gathering (ignore rules, per-file and whole-request byte caps, largest-files-demoted-first budgeting, child documents always carried and never demoted, unreadable files, empty/missing directories); `Problem`/`Omission` Display and `Error::source` checks; prompt-constant content assertions for `MAP_PROMPT` and `REDUCE_PROMPT`; chunking behavior (`chunk_utf8`, cap constants, round-tripping, newline-bounded splits, oversized single lines, non-text rejection, empty and small-file cases); a hand-written `Counting` fake `Agent` and supporting fixtures (`account`, `text_of_chunks`, `somewhere`); `summarise_file` behavior (pass counts for multi- vs single-part files, part/total wording, chunks never sent as `AgentFile`, non-text and too-many-chunks omissions, failing map/reduce passes, too-short answers rejected without a source); `pact_directory` behavior (verbatim writes to `WARLOCK.md`, prompt content, no leftover temp files, hash-invisibility, unwritable-directory and overwrite behavior, agent-refusal and too-short-answer rejection, boundary tests around `MINIMUM_DOCUMENT_BYTES`, untouched documents on rejection).

Further test sections cover a "ladder" of budget-versus-summarisation interactions (over-cap non-text vs. text files, chunk-ceiling files, single-report-not-double for failed summarisation, a five-file "fat directory" fixture demonstrating whole-then-summary-then-name/size fallback, caching cutting repeat costs, tie-breaking by relative path, children's documents always carried whole even when huge); error-handling tests for gather failures and `Error` variant rendering; and summary-cache tests (content-keyed by blake3 hash independent of path/name/depth, portability across clones, cache misses on absent/empty/whitespace/non-text/corrupt/unreadable entries, exactly-one-file writes with no leftover temp, overwrite-not-duplicate on rewrite).

The suite then covers subtree-level pacting: fixtures `repository()`/`project()` for directory-walk tests confirming `pactable_directories` matches `load_tree`'s exclusions (gitignored, hidden, `.warlock`) and children-before-parents ordering; confirmation that the summary cache never affects `subtree_hash` or appears in walks/requests; test doubles `FailsFor`, `Watching`/`Overhearing`, and a `Told`/`Kind`/`Log` mechanism for asserting call ordering; core `pact_subtree` behavior (deepest-first passes, parents receiving only children's finished documents, one shared `granted_at` per run, `.warlockignore` exclusions and malformed-rule failures, omissions not failing the pact, manifest entries outside scope preserved, failed directories withholding grants from themselves and ancestors while siblings keep grants, root stored as `.`, permission failures recorded as non-fatal `Failure::Hash`); observer/cancellation tests (single announcement per directory with position/total, `documented` only on fully completed subtrees, mid-pact cancellation preserving partial writes, `Unwatched` never stopping); summarising-pass announcement ordering tests; un-pacting tests (`unpact_subtree` matching by path segment not string prefix, order/content preservation, idempotence, root un-pacting, no on-disk side effects); and refresh tests (`refreshable()` baseline fixture, refreshing only stale/changed/unpacted directories and their ancestors, skipped entries left byte-identical, unreadable-hash directories still described, all-failing refreshes leaving the manifest unchanged, cancellation and partial-failure grant propagation).

Near the end, helpers `hash_of` and `granted_at_of` read real hashes/timestamps off a repo, feeding `expected_after_the_pact` and `expected_after_the_refresh`, fixtures that build the literal expected TOML manifest text after a pact and after a subsequent refresh (specifying exactly which `[[pact]]` entries keep original timestamps versus which get new ones). The test `a_pact_and_a_refresh_over_a_granted_manifest_write_these_exact_bytes` exercises both fixtures end to end, asserting exact serialized output and entry ordering across a pact followed by a refresh with one changed file.

A further block of scope/sigil regression tests (prefaced with commentary that these guard behavior rather than prove it, since result types have no scope field) uses helpers `scopes()` and `with_scopes()` to confirm that un-pacting drops scopes only within the removed subtree, refreshing leaves every scope untouched regardless of whether a directory was described or skipped, pacting a parent rewrites descendants' hashes/documents/grants without touching scopes, cancellation mid-run leaves scopes unaffected, and a partly-failed run leaves ancestor entries documented-but-ungranted while scopes stay unchanged.

The file closes with tests of `view_file`/`Viewed`/`Unviewable` file-viewing behavior, using helpers `cap()` and `untouched()`: whole reads of ordinary and empty files; exact truncation at `PER_FILE_BYTE_CAP` with `cut` set true and no truncation wording embedded in the text itself; parity between viewed text and the bytes placed in a model request, including at the exact cap boundary; UTF-8-safe cutting that drops a split character rather than substituting a replacement character; non-UTF8 content yielding `Unviewable::NotText` with the underlying UTF-8 error preserved as `source()`; missing files, permission-denied files (unix-only), and directories all yielding `Unviewable::Unreadable` naming the path; and a final test confirming repeated views always re-read from disk rather than caching, by observing different text after an intervening rewrite.
