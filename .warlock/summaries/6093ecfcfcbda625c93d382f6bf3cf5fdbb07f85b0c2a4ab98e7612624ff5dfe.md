This is the complete Rust source for a module implementing the headless `warlock pact <path>` and `warlock refresh <path>` subcommands (a single, complete file, not excerpted).

The file opens with an extensive module-level doc comment explaining the design philosophy: unlike other subcommands in the codebase, `pact` and `refresh` are "spent" operations — they invoke a real language-model process (`claude --print`) per directory, write `WARLOCK.md` files, and save a manifest once at the end. It stresses that this module invents no new logic — `pact` calls `pact_subtree` and `refresh` calls `refresh_subtree` from `warlock_engine`, using the same `ClaudeAgent` the interactive TUI keys (`p`/`r`) use. Documented rules/behaviors include: the scope/boundary check (`Opened`) happens before any spawning, refusing with exit status 3 and no side effects if a scope is closed; progress is printed as plain lines to stdout (via a `Progress` observer) rather than a TUI, showing directory entry/completion and position counts; failures are per-directory, collected in `PactedSubtree::failures`, and reported as one line per failing directory plus a summary count on stderr, yielding exit status 4; the manifest is saved exactly once, after the full descent, regardless of failures; Ctrl-C handling is described in detail — first press latches a `Cancel` to stop gracefully at the next directory boundary (status 130, partial manifest saved), second press exits immediately via `process::exit` with nothing saved; and environment-touching code is isolated to one function (`started`) for testability.

The actual code follows this documentation:

- Imports from `std`, `warlock_engine`, `warlock_tui`, and internal crate modules (`descent`, `edits`, `error`).
- `Progress<W: Write>` struct: implements `pact::Observer`, printing "documenting"/"documented" lines with position/total counters, tracks a `Cancel` handle and root path for naming directories; ignores write failures (broken pipe) intentionally.
- `named()` helper: formats a directory path relative to root, falling back to raw display on non-UTF8 issues.
- `Report` struct and `report()` function: builds a deduplicated, ordered list of failure lines (directory name + flattened one-line error) plus counts, returning `None` if nothing failed; has `onto()` to write lines and `status()` to produce an `Error::Failures`.
- `ran()`: thin wrapper calling `descend` with the opened boundary's target/root/manifest, agent, and observer; returns `PactedSubtree` or `Error::Pact`/`Error::Manifest`.
- `listening()`: installs a `ctrlc` handler creating/returning a `Cancel`; first press latches cancellation, second press force-exits with `CANCELLED` status; returns `Error::Signal` on install failure.
- `ending()`: decides final outcome — `Error::Cancelled` if cancelled, otherwise `Ok(())` or `Error::Failures` based on `report`.
- `started()`: the actual subcommand entry — resolves `Opened` boundary, installs signal handler, builds `ClaudeAgent`, and calls `descended()` with stdout/stderr, propagating errors.
- `Descended<W: Write>` struct: bundles the resulting `PactedSubtree`, `Progress`, optional `Report`, and outcome `Result`; has `#[allow(dead_code)]` since production code only uses `outcome` while tests inspect all fields.
- `descended()`: the core composition function tying together `Progress` creation, `ran()`, `report()`, and `ending()`, ensuring correct ordering (shared `Cancel` between agent and observer, denominator read after descent, manifest saved before evaluating outcome). Returns `Result<Descended<O>, Error>`.
- Public `pact()` and `refresh()` functions: one-liners calling `started()` with `Descent::Pact` or `Descent::Refresh`.

The remainder is a `#[cfg(test)] mod tests` block containing:
- Helper functions: `a_dir()`, `a_repository()` (builds a fake git repo with `alpha`/`beta` subdirs), `write()`, `holding()` (writes sigils), `scoped()` (writes a manifest entry with a scope), `manifest_bytes()`, constant `CLAUDE`.
- `Canned`: a fake `Agent` implementation that records which directories were passed, whether a manifest existed on disk at call time, can be configured to refuse specific directories (simulating missing `claude`), and can trigger a cancel mid-run (`cancelling_at`). Implements `Agent::run` accordingly.
- `document()`: filler text long enough to pass acceptance.
- `named()` test helper delegating to production `named`.
- `Run` struct capturing subtree, agent, stdout lines, stderr lines, report, and outcome, with `ended()` and `stderr()` helper methods.
- `run()`, `run_refusing()`, `run_cancelling()`, and `driven()` — helper functions that construct an `Opened` boundary and invoke the production `descended()` function directly (not re-implementing the composition), varying whether passes are refused or cancelled.
- `written()` and `stored_modules()` utility functions.

Test cases cover: successful full pact run over all directories with single manifest save; correct progress line output/ordering with directory naming; closed-scope boundary refusal leaving the manifest untouched (status 3); an open scope allowing the run through while preserving the scope entry; refresh only redoing stale directories, leaving fresh ones untouched; one directory failing while the rest of the run still gets saved and reported correctly (status 4); all directories failing (simulating no `claude` on PATH) with correct dedup naming and count; cancellation stopping the descent between directories, saving completed work, and reporting via `Error::Cancelled` (status 130) without naming killed passes; a cancellation combined with a failed pass showing the cancel message suppresses the specific failure line; and a Unix-only test simulating an unwritable manifest directory to confirm save failures yield exit status 1 (taking precedence over the failures/cancel reporting), with a root-safety check that skips the assertion if permissions cannot actually block writes.
