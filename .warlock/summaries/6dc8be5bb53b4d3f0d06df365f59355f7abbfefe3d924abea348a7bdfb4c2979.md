This is the entirety (part 1 of 1) of `app.rs`, the front-end state module for Warlock's TUI, together with its extensive unit test suite. Its contents:

**Module doc comment**: Explains the overall design — the tree is flattened into `Row`s for screen display; the app keeps both the full walk and the currently-drawn (filtered) rows; collapsing, a "pacted-only" filter, and a "show files" toggle are all re-flattening operations over the retained whole walk rather than destructive edits. It also describes footer messages, focus across three panes (tree/panel/composer), pointer-driven movement mirroring key-driven movement, an in-flight pact/refresh run tracked as state, and the panel's "account" vs "document" cards with independent scroll/follow windows. Emphasizes the type is UI-framework-free and pure/testable.

**Core types and their documented behavior**:
- `Row`: one flattened line — depth, path, optional document, `NodeState`, child count, file flag, document-row flag, ignored flag, and optional scope. Has constructors `new`/`file` and builder methods (`with_child_count`, `with_ignored`, `with_document_row`, `with_scope`) plus query methods (`has_children`, `is_file`, `is_document`, `is_ignored`).
- `PactToggle`: result of toggling a pact on a directory (path + new pacted bool).
- `Run` enum (`Pact`/`Refresh`) and `InFlight` (private): tracks an in-progress run's directory, position, high-water "reached" mark, total, and kind.
- `RunHeader`: public read-only snapshot for the panel header (run kind, directory label, position, total).
- `Summarising` (private): tracks a chunked-summarization sub-pass within a directory (file, part, parts).
- `Focus` enum (`Tree`/`Panel`/`Composer`) with `next()`, `drives_the_tree()`, `drives_the_panel()`.
- `Sigils` enum (`Nothing`/`Held(Vec<String>)`/`Unknown`) representing what sigils this machine holds, with `held()`, `as_slice()`, `line()` methods for wording the header.
- `Chrome`: holds the header text (path relative to repo root) and `Sigils`; explicitly *not* part of `App` since it's resolved once per session.
- `App`: the main struct — `all_rows`, `rows` (drawn), `collapsible` set, `counts` (StateCounts), `selected`, `scroll_offset`, and three sub-groups: `Viewpoint` (collapsed set, pacted_only, show_files, viewport_height, focus), `Status` (message, in_flight, summarising, pact_refused, mouse_captured), and `Panel` (imported from `crate::panel`, holds account/thread/document cards).

**`App` methods** (very extensively documented) cover: construction (`from_tree`, `from_rows`, `with_collapsed`, `with_counts`), messaging, in-flight run tracking (`set_pact_in_flight`, `set_run_in_flight`, `set_pact_summarising`, `clear_pact_in_flight`, `set_pact_refused`, `is_pacting`, `is_in_flight`, `in_flight_covers`, `pact_line`, `run_header`), panel/account/thread/document management (`start_account`, `write_run`, `show_document`, `refill_document`, `start_turn`, `note`, `record_turn`, `answer_turn`, `end_turn`, `thread`, `swap_card`, mode get/set, account accessors, `restore_from`, panel height/width/scroll accessors), row/view queries (`rows`, `collapsed`, `is_collapsed`, `can_collapse`, `pacted_only`/`toggle_pacted_only`, `show_files`/`toggle_files`, `counts`, `is_empty`, `selected`/`selected_row`, `scroll_offset`, `viewport_height`/`set_viewport_height`, `mouse_captured`/`set_mouse_captured`), focus management (`focus`, `composer_showable`, `toggle_focus`, `set_focus`, `rescue_focus`), movement methods (`select_previous`, `select_next`, `select_page_up/down`, `select_first/last`, `select_row`, `select_next_by`/`select_previous_by`, `scroll_panel_down/up`, private `movement`/`scroll_panel_to`/`page`/`panel_page`/`rescroll`/`reflow`/`moved`/`forget_last_keystroke`), `label_for` (relative path naming), `toggle_collapsed`, `toggle_pact`, `refresh`, `scope_target`, `view_target`, `set_subtree_state`, `insert_file_row` (splices a newly-written document row into the tree mid-run).

**Free functions**: `file_row_position`, `reseat_on` (rebuilds an `App` on a freshly reloaded `Tree` while preserving view state), `walk_of`, `node_rows`, `paint_subtree`, `moves_with_subtree`, `in_subtree`, `drawn_rows`, `pacted_rows`, `index_for`, `scroll_offset_for` (pure scrolling math), and numerous private message-wording functions (`left_on_disk_message`, `pacting_message`, `refreshing_message`, `already_fresh_message`, `unpacted_message`, `unpacted_scope_message`, `directory_view_message`, `undocumented_view_message`, `cut_at_cap_message`, `no_document_message`, `summarising_message`, `already_running_message`, `file_row_message`, `ignored_row_message`), plus `count_mut`.

**Test module** (`#[cfg(test)] mod tests`): a very large suite (likely several hundred tests) covering: row flattening, header/Chrome/Sigils formatting, selection movement and clamping, scroll offset math, file/document row display and toggling, pact/unpact/refresh/scope/view key behavior and refusals (including `.warlockignore` exclusion), subtree state painting, collapsing/expanding and pacted-only filtering interactions, focus cycling and composer visibility rules, panel/account/thread/document card independence (windows, follow flags, wrapping long lines, swapping cards), run-in-flight footer/header wording (pact vs refresh, summarising sub-pass, already-running suffix), pointer-based selection/scrolling parity with keyboard, reseating an app onto a reloaded tree (carrying selection/collapsed set/panel/focus), and inserting a freshly-written document row mid-pact-run at the correct sorted position without disturbing tally, selection, or window.
