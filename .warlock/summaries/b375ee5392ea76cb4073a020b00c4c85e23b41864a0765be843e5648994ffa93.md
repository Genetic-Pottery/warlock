The file implements rendering of a single frame of the "warlock" terminal UI, followed by an extensive test module covering that rendering.

It opens with a module-level doc comment describing the overall screen layout: a footer along the bottom, and above it a panel (left) and a bordered tree pane (right). The panel shows either a compiled-in ASCII/block-art "mark" (dim, centered, shown before any pact has run and disappearing once one starts), or an account of the running/last pact — a heading per directory plus per-line activity with elapsed time. The tree pane is a scrollable window onto flattened rows owned by the app (collapsing, filtering, etc. happen upstream), with guide characters (│├└) drawn per row to show nesting/branching. A `hit_test` function maps pointer clicks to logical screen regions without any pointer-tracking/hover state. An overlay "quit confirm" dialog, and separately a scope-entry prompt dialog, are drawn last, over everything, sourced from state passed in alongside (not stored in) the app.

Imports bring in ratatui pieces, `warlock_engine` types, and sibling modules (`account`, `app`, `colour`, `confirm`, `prompt`).

A large, heavily-documented set of constants governs layout and style: indentation width; guide glyphs; selection/collapse/expand markers; the compiled-in `MARK` ASCII art and its margins; header height/gap; panel indent and ellipsis; scrollback indicator and "live" key; footer key-help text and per-mode key variants (including a compile-time `assert!` enforcing a width budget); footer height; tree/panel sizing (percentage, minimum width, border thickness); pulse-animation timing; and sizing/text constants for both the quit-confirmation dialog and the scope-prompt dialog.

The functions implement:
- `keys_line` for building the footer's key-help text depending on mouse-capture state.
- `draw`, the top-level entry point, which computes layout `Areas`, draws panel/tree/footer, and conditionally overlays the confirm and/or scope dialogs.
- `Areas`/`areas`, `tree_width`, `pane_inner`, `tree_rows_area`, `tree_height`, `panel_height` — layout computation splitting the screen into panel/tree/footer rects with proportional/floor/cap rules, and helpers exposing viewport sizes to the app.
- A `Hit` enum and `hit_test` — pure mapping from a screen point to a logical region (offscreen, footer, border, tree header, a tree row with offset, below the tree rows, or a panel line with offset).
- `pane_block`, `draw_panel`, `draw_mark`/`mark_area`, `scrollback`, `panel_row`, `truncated`, `display_width` — panel drawing: a focus-styled bordered block, the mark artwork placed whole-or-nothing depending on room, a scrollback "N more" indicator, conversion of one account entry into a styled/truncated line, and UTF-8/column-aware truncation and width measurement.
- `draw_tree_pane`, `draw_header`, `header_line`, `draw_tree`, `line`, `guide_prefixes`, `pulse_colour` — tree pane border/header drawing (including a rule for hiding the "sigils held" text when space is short), drawing the visible row window with selection highlighting and pulse-color override for an in-flight pact, building each row's guides+marker/name/scope-label spans, computing guide prefixes via a two-pass algorithm, and computing the pulsing stale/fresh color based on elapsed time.
- `draw_footer`, `noun` — drawing tally/keys/message lines, substituting pacting-specific text while a pact runs, and mapping node state to its footer word.
- `draw_confirm`, `answers_line`, `confirm_area`, `centred`, `confirm_size` — quit-dialog drawing and generic centering/clamping logic shared with the scope prompt, sized from measured text widths.
- `draw_scope`, `scope_lines`, `scope_size` — scope-prompt dialog drawing: heading with bold directory name, typed text with a reversed-space cursor, a broken-rule line, and a dim rules line, sized similarly to the confirm dialog.

The remainder of the file is a test module. It begins with named constants documenting terminal dimensions and thresholds used throughout the tests (standard/narrow/held widths, mark-related widths and heights, pulse phase/cycle timing, scope-label test fixtures, chrome/keys/files heights), and helper functions for building synthetic trees and apps (`many_rows`, `labelled_rows`, `tall_app`, `pacting_app`, `busy_app`), locating and reading rendered regions (panel/tree/header/footer areas and their text, row and glyph lookups by path or column, cursor-cell computation, highlighted-row detection), and rendering into an in-memory buffer through a layered set of `render*` helpers funneling through one actual draw call.

The bulk of the test module is a long sequence of individual tests, covering: tree indentation and guide-character rendering under scrolling, pulsing, and selection; collapse/expand markers and their absence on leaves; row coloring by state and inheritance from parent to file rows; scope-label rendering, coloring, and truncation/omission rules; the pulse animation's timing, synchronization, restart on handover, and reversion when a pact clears; file-row visibility toggling; selection highlighting and marker tracking under scrolling; header/footer stability while the tree scrolls, including viewport-height math at various terminal sizes and safe behavior at zero/insufficient height; footer content (counts, key hints, filter toggling, refusal messages, pacting/progress wording, narrow-terminal truncation, cancel-vs-quit labeling, mouse-capture wording, and a key-width budget check); header content (relative naming, blank header at repo root, combined name+sigils text, unknown sigil handling, and dropping rather than truncating the holding text when space is short); layout math for panel/tree width proportions and minimum-width floor behavior, including an exhaustive bounds check; hit-testing across coordinates and edge cases (zero-height, narrow terminals, offscreen points, out-of-bounds offsets); and the mark's display rules (shown only before any pact, only above a minimum size, never reappearing once an account starts, and unaffected by focus).

The final portion of the test module covers: panel rows (blank when unfilled, elapsed-time advancement between renders with no new activity, ellipsis truncation of over-long lines without spilling into the tree pane); the `truncated`/`display_width` functions across ASCII, accented, and double-width text at every possible width; scrollback behavior (no indicator while following live, an indicator with count and return-key hint when scrolled back, the indicator not consuming an account row, exact restoration on returning to live); `panel_height` measurement matching terminal height minus chrome, including zero-row terminals; focus-border styling differences between tree-focused and panel-focused renders, confirming distinct colors/modifiers and that only borders change on focus switch; a full test harness and suite for the quit-confirmation dialog (sizing from text and margins, centering, exact question/answer layout, no leakage from or into the underlying frame, cell-exact overwrite/restore behavior, highlight starting on "No" and moving to "Yes," clamped drawing on too-small terminals, and unchanged footer wording while open); and a full test harness and suite for the scope-entry prompt (sizing accounting for heading, directory name, field text, cursor, and rules text; correct row ordering of heading/field/rules; a pre-populated field with correctly positioned cursor; a refused submission retaining typed text and showing a refusal reason without moving the field's row; no leakage into or out of the window; cell-exact restoration when closed; and clamped drawing on too-small terminals).
