This is the entirety of `pact.rs`, the module implementing warlock's "pacting" operations — the model-pass writing of `WARLOCK.md` documents and the bookkeeping around them.

**Module-level doc comment (top):** A long prose overview explaining the three stacked operations — `pact_directory` (one directory: gather, fit to budget, run one agent pass, write the document), `pact_subtree` (a whole subtree, children-first, then hash-and-grant), and `refresh_subtree` (same machinery but only over directories `decide_state` calls stale). It explains: the shared `describe_and_grant` core used by both subtree operations; how `.warlockignore` interacts with hashing/pacting; that an accepted response is written verbatim, atomically (via temp file + rename); the two rejection cases (agent error or too-short answer); ordering rules (children before parents, via `pactable_directories`); the two-phase write-then-hash-and-grant design and why (avoiding hashing a directory before its children's documents are written); how hash failures are handled differently pre- vs post-pass (`Failure::Hash`); the `Observer`/cancellation design (progress reporting between directories only, not mid-pass); and finally `unpact_subtree`'s asymmetry — it drops manifest entries/scopes but never deletes documents on disk, plus the scope-boundary rules around it.

**Imports:** standard collections, fs, io, path, ffi, fmt; `ignore::WalkBuilder`; and crate-internal modules (`fitting`, `ignores`, `manifest`, `scope`, and top-level crate items like `Agent`, `Manifest`, `NodeState`, `PactEntry`, `agent`, `decide_state`, `hash`, `subtree_hash`, etc.).

**Constants:** `MANIFEST_DIR` (`.warlock`), `DOCUMENT_FILE` (`WARLOCK.md`), `MINIMUM_DOCUMENT_BYTES` (200, the only rejection-length floor — explicitly no phrase-based heuristics), `PROMPT` (the entire large literal instruction text given to the model for writing a `WARLOCK.md` — covering coverage-of-every-file, behavior description, claim verification with file/function names, handling previous documents, refusing unverifiable negative claims, and staying silent about warlock's own bookkeeping/scopes), and `STAMP` (the fixed `<!-- warlock -->` header prepended to every written document, explained via its own doc comment: constant/dateless so identical documents produce identical bytes).

**Public functions:**
- `pact_subtree(directory, root, manifest, agent, observer) -> Result<PactedSubtree, Error>` — walks `pactable_directories`, calls `describe_and_grant`, then `rewrite`s the manifest. Extensive doc comment with a runnable doctest using a fake `Canned` `Agent`.
- `refresh_subtree(directory, root, manifest, agent, observer) -> Result<PactedSubtree, Error>` — filters to only stale directories via `is_fresh`, then same `describe_and_grant`/`rewrite` pipeline (with empty `directories` slice to `rewrite`, so nothing is dropped). Doctest included.
- `is_fresh` (private helper) — decides freshness via `decide_state`, folding "no manifest path" and "hash failed" both into `false`.
- `pact_directory(directory, root, agent) -> Result<Pacted, Error>` — public one-directory entry point, delegating to `pact_directory_watched` with `Unwatched`.
- `unpact_subtree(directory, root, manifest) -> Result<Manifest, manifest::Error>` — pure manifest edit dropping entries at/below the directory; doctest included.
- `closed_scopes_at_or_below(directory, root, manifest, held) -> Result<Vec<&str>, manifest::Error>` — reports (never enforces) which scopes at/below a directory this machine's held sigils don't open; doctest included.
- `view_file(path) -> Result<Viewed, Unviewable>` — reads a file for human display, capped at `PER_FILE_BYTE_CAP`, never splitting a multi-byte character; doctest included.

**Private helpers:** `describe_and_grant` (the shared two-phase core: phase one writes documents directory-by-direction respecting cancellation, phase two hashes and builds `Outcome`s/grants), `rewrite` (applies `Outcome`s onto a `Manifest`, preserving entry order/fields not owned by a run), `pact_directory_watched` (does the actual fit/run/write for one directory, with observer hooks), `pactable_directories` (crate-private walk producing children-before-parents directory list respecting ignore rules), `stamped` (idempotently prepends `STAMP`), `at_or_below` (segment-wise path prefix test used by both unpact and scope-closure functions), `read_capped` (reads up to cap+1 bytes of a file).

**Types:** `Described` (outcomes/failures/problems bundle from `describe_and_grant`), `Outcome`/`Grant` (per-directory run result, deliberately unable to express a scope field), `Observer` trait (with `starting`, `summarising`, `requesting`, `documented` methods, heavily documented regarding no `Send`/`Sync` requirement and no mid-pass cancellation), `Pacting` enum (`Continue`/`Stop`), `Unwatched` (no-op `Observer` impl), `PactedSubtree` (public result struct: manifest/failures/problems), `Pacted` (result of one directory: document path + problems), `Viewed`/`Unviewable` (view_file's result/error types), `Refusal` (agent-error vs too-short), `Error` (enum: `Walk`, `Path`, `Refused`, `Write`, each naming its directory via `Error::directory()`), `Failure` (enum: `Document`, `Record`, `Hash`, each naming its directory via `Failure::directory()`) — all with `Display`/`std::error::Error` impls.

**Test module (`#[cfg(test)] mod tests`, the bulk of the file):** An extensive suite using hand-written fakes (`Canned`, `Fails`, `Counting`, `FailsFor`, `FailsEveryMap`, `Overheard`/`Overhearing`, `Watching`) rather than any mocking framework or real `claude` invocation. Covers: prompt content assertions (pinning specific required phrases), verbatim/atomic document writing, stamping behavior, rejection thresholds (exact boundary bytes), per-file and whole-request byte-cap "ladder" behavior (sent whole → summarised → listed) including tie-breaking by path, summary caching (`.warlock/summaries/`) hit/miss behavior across renames and fresh clones, child-document propagation to parent passes, ordering guarantees (children before parents), partial-completion/ungranted-entry semantics, hash failures, cancellation via `Observer::Stop` mid-subtree, `Observer` progress announcements (`starting`/`summarising`/`requesting`/`documented`) with exact call-order assertions, `.warlockignore` interaction (excluded directories get no entries/documents/passes, unparsable rules fail the whole pact), manifest read/write round-tripping including exact expected TOML byte-for-byte snapshots (`expected_after_the_pact`, `expected_after_the_refresh`), `unpact_subtree` behavior (siblings sharing prefixes not affected, root un-pact drops everything, idempotency, errors), scope-preservation invariants (un-pacting drops scopes, but pacts/refreshes/cancels/partial-completion never touch scopes), and `view_file` edge cases (cut boundaries, non-UTF8, permissions, directories, exact parity with what a model request carries).
