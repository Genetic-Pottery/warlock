This is the entirety of `writing.rs`, a Rust source module implementing the `/write` command's path proposal and file-writing logic for a TUI tool called warlock (a documentation freshness ledger), plus its accompanying test suites. Since this is the whole file (part 1 of 1), it contains everything: module documentation, implementation, and tests.

**Module-level doc comments** open the file, explaining the design in prose: `/write` opens a field pre-filled with a proposed path (via `proposed_path`) built from a directory, a slug derived from the reply's first `# ` heading, and a sequence number scanned from existing filenames in the target directory. The proposal is only a suggestion in an editable field — nothing is refused at proposal time. The actual write (`write_submit`) is the one destructive-adjacent operation: it resolves the typed path against the repository root, refuses if the path escapes the root or already exists, pulls the document text off the newest conversation turn, checks it against required section headings, and either writes it to disk (creating parent directories as needed) or reports a refusal/failure as a line on the conversation/footer rather than an error.

**Constants**: `WRITE_HEADING`, `BRIEF_PREFIX`, `UNTITLED`, `SLUG_MAX` (60), `ROOT_MODULE` ("."), `NO_PATH`, `NOTHING_TO_WRITE` messages.

**Core functions**:
- `proposed_path`, `write_opened`, `write_edit`, `write_submit` — the prompt lifecycle (open, edit keystrokes, submit).
- `refused` — reopens the field with a rule message.
- `document` / `document_on` — extracts and normalizes (unfences, ensures trailing newline) the reply text from the app's conversation.
- `put` — writes bytes to disk, creating parent dirs.
- `pacted_above`, `directory_of`, `at_or_above` — find the nearest ancestor directory with a manifest pact entry, to report which pact went stale.
- `wrote_line`, `stale_line`, `taken_rule`, `missing_line`, `unreadable_shape_line`, `failure_line` — message formatters for each outcome.
- `unfenced` — strips a wrapping code fence if the entire reply is one fenced block (checking opening/closing markers, backtick/tilde, width).
- `slug_of`, `slugged`, `capped` — title-to-filename slug logic (lowercase, alphanumeric folding, hyphen collapsing, ~60-char cap broken at word boundaries).
- `next_number`, `spelled`, `highest_number_in` — scans a directory for the highest embedded number in any filename and proposes one more, zero-padded to at least 2 digits.
- `opening_fence`, `closes`, `Fence` struct — fence detection helpers for `unfenced`.

**Tests** (three `#[cfg(test)]` modules):
1. `tests` — unit tests for `proposed_path`, `slug_of`, `unfenced`, `next_number` covering slugging rules (case folding, punctuation collapsing, colon handling, length capping, whole-word preservation), fence detection/stripping edge cases, numbering rules (digits anywhere in filenames, directories counted as names, saturating overflow, widening past 99), and directory-parameter behavior — plus a check that proposing writes/creates nothing.
2. `writes` — integration-style tests of `write_submit` using a fake `App`/`Manifest`/tempdir: successful writes with size formatting, verbatim byte writing minus fence/newline handling, refusal on existing path (including directories), stale-pact-line naming logic (nearest ancestor, root case, unrelated prefix ignored), missing-section refusal (single and multiple, ordered per template), template-read-failure handling, disk-failure handling, empty-conversation handling, empty/whitespace path refusal, and path-escapes-root refusal. Includes helper functions (`app_answering`, `field`, `entry`, `pacts`, `notes`, `everything_under`, `document_of`, `shapeless`, `WHOLE` constant).
3. Nested `rounds` submodule — drives the prompt through simulated keystrokes (`edit_for`/`write_edit`) to test the full open→edit→submit cycle, Esc cancellation, refusal-then-retry, and submit-with-no-window-open.
4. Nested `whole` submodule — an end-to-end test driving the entire `/write` flow from composer input through a stubbed agent (`Saying`) answering, to the prompt opening and Enter writing the file, verifying conversation lines and final disk state.

A reader of the whole file needs to know this single file is self-contained (module + all its tests), covering path proposal, document normalization/writing, and staleness reporting for warlock's `/write` feature.
