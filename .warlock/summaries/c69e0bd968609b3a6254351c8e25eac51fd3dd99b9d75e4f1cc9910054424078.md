This file implements the machinery that runs a "pact" (documenting a directory subtree) or a "refresh" (re-documenting only the stale parts of a subtree) on a background worker thread, keeping the TUI's event loop non-blocking, along with an extensive test suite covering that machinery.

The module-level doc comment lays out the design: the pact/refresh keystrokes are the only operations slow enough to need a worker thread; `pact_press` and `refresh_press` decide what a keypress means; `spawn_pact` starts the worker and returns a channel; `apply_progress` is the event-loop side that drains that channel each frame, updates the UI, and does the one final reload. Cancellation (Esc) is distinguished from quitting: Esc lets the worker finish hashing/saving what it completed, while quitting via a dropped `CancelGuard` kills the `claude` subprocess outright — but no half-written state ever exists.

Imports draw from the standard library (paths, mpsc channels, threading, fs/io, Instant), `warlock_engine` (Agent, Manifest, NodeState, PactFailure, PactObserver, PactProblem, PactedSubtree, Pacting, Tree, and functions `pact_subtree`, `refresh_subtree`, `to_manifest_path`, `unpact_subtree`), `warlock_tui` (Activities, Activity, App, Cancel, ClaudeAgent, Outcome, PactToggle, Run, Section), and crate-local `Error`, `one_line`, `Scope`, `reload_tree`.

Two message constants anchor footer wording: `PACT_LOST` (worker thread died without reporting, i.e. panicked) and `PACT_CANCELLED` (reader hit Esc; finished work is still recorded).

**Core types.** `Running` is what the event loop holds for an in-flight run: the event `Receiver<PactEvent>`, a `CancelGuard`, the `Work` describing what's being done, and a pre-run `App` snapshot for restoring on failure. `Work` unifies pact (`Pact(PactToggle)`) and refresh (`Refresh(PathBuf)`) runs, since they share nearly all machinery; it exposes `path()`, `kind()` (mapping to `Run::Pact`/`Run::Refresh`), and `is_cancellable()` (false only for un-pacting, which is instant manifest arithmetic with no cancellable pass). `CancelGuard` is an RAII wrapper around `Cancel` that cancels on drop, guaranteeing no orphaned `claude` process survives any exit path. `PactEvent` enumerates everything the worker reports over the channel — `Starting{directory,position,total}`, `Doing(Activity)`, `Summarising{file,part,parts}`, `Documented{directory}`, `Finished(Result<Toggled,String>)` — with doc comments spelling out strict ordering guarantees (exactly one `Finished`, always last).

**Helper functions and dispatch.** `activity_port` builds a per-run `Activities` port forwarding tool/thinking/cost events into the channel (never shared across runs, to avoid leaking channels). `Reporting` implements `PactObserver`, forwarding `starting`/`summarising`/`documented` calls to channel sends and consulting the `Cancel` handle in `starting` to return `Pacting::Stop` or `Continue`; send failures are silently ignored since a dead receiver just means the app is quitting. `spawn_pact` clones what it needs and spawns a detached thread running `run_pact`, returning a receiver; `start_run` combines `CancelGuard::new()` and `spawn_pact` into a `Running`. `run_pact` is the worker body: it calls `apply_toggle`, rewrites the outcome via `cancelled()` if the work was cancellable and got cancelled, and always sends exactly one `Finished` event. `cancelled()` marks an outcome as not granted and sets its message to `PACT_CANCELLED`, keeping whatever was already saved to disk.

`pact_press` decides what pressing the pact key does: it refuses (setting a UI flag, no message) if a run is already in flight, otherwise delegates to `app.toggle_pact()` and starts a new panel account only for pact-in (not un-pact, which has nothing to account for). `refresh_press` is its twin for the refresh key, always starting an account since a refresh always runs passes.

`apply_progress` is the large event-loop-side function draining all available `PactEvent`s per frame: it opens/closes panel sections per directory, records activity lines, ticks the in-flight progress line, tracks `Summarising` state, live-paints directories green via `Documented`/`set_subtree_state`/`insert_file_row`, and on `Finished` or channel disconnection finalizes the run — applying the new manifest, painting the whole subtree fresh if granted, setting messages, or restoring the pre-run `App` snapshot on failure (`Err`) or worker death (disconnection, using `PACT_LOST`). It always closes the panel account via `close_account` and reloads the tree from disk via `reload_tree`, returning the freshly loaded `Tree` or `None`.

Supporting pieces: `DOCUMENT_FILE` (`"WARLOCK.md"`, the filename each pacted directory's document is written to); `close_account` (closes every open panel section with an outcome via `section_outcome`, marks a cancelled section specially, then finishes the account); `section_outcome` (determines a section's ending — matched failure/refusal, else stats the actual `WARLOCK.md` on disk to report bytes written, else "no document was written" or a read error); `restore` (restores the app to its pre-run snapshot and sets a message, keeping the account as a factual record); `section_label` (relative-path spelling for panel headings, matching the footer's convention).

`Toggled` holds the resulting `manifest`, a `granted` bool, an optional `message`, and `refusals: Vec<Refusal>`. `Refusal` pairs a directory with a one-line failure reason, with a `From<&PactFailure>` impl flattening engine failures into it. `apply_toggle` is the core dispatcher, handling un-pacting (`unpact_subtree`), pacting (`pact_subtree`), and refreshing (`refresh_subtree`), then calling `described()` to build the `Toggled` value and saving the manifest exactly once at the end. `described()` converts the engine's `PactedSubtree` (manifest, failures, problems) into `Toggled`, computing `granted` from empty failures and building the footer message. `pact_message` builds that one-line footer message, quoting the first failure (or first problem if none) in full and counting the rest.

**Tests.** The remainder of the file — the large majority of it — is a `#[cfg(test)]` module. It defines extensive fixtures: a `Canned` fake `Agent` (returns canned documents, can simulate refusals and mid-run cancellation, records call order and activities), a `Scratch` struct for building real temporary on-disk repositories (including a two-crate and an eight-crate/seventeen-directory layout), and many helper functions (`toggle`, `refreshing`, `pact_of`, `load`, `at`, `panel_text`, `nowhere`, `state_of`, `documents`, `run_and_apply`, `events_of`/`events_from`, `fractions`, `announced`, `outcome_of`, `pacted`, `recorded`/`recorded_from`, `replay`/`replay_work`, `document_bytes`, `a_run_in_flight`, `running_over`, `drawn`, `one_directory_with_files`, and a Unix-only `stand_in` that builds a shell one-liner simulating the `claude` CLI's JSON tool-use and result events).

The tests exercise, in depth: granting and single-save behavior; preservation of unrelated manifest entries; failure reporting and message truncation/counting on the footer; un-pacting; out-of-root refusal; unwritable-manifest handling via `chmod`; strict worker event ordering and activity interleaving, including large files chunked into multiple announced passes with unchanged file/part/of-count metadata; a real spawned-process run reporting activity and ending in exactly one `Finished`; a missing-agent-binary failure; keypress handling for pact/refresh (refusing concurrent runs, no-ops on file/ignored rows, accounts started or preserved appropriately); cancellation semantics (reverse-path-order descent, stopping between not mid-directory, saving completed work, fixed `PACT_CANCELLED` message, including a no-failures cancellation that still withholds root freshness); refresh visiting only stale directories with fractions relative to the run; a cancelled refresh with exact panel-text assertions; dropping a `Running` cancelling its token; incremental panel building frame-by-frame with independent per-section clocks; a `Finished` event closing the run and clearing the footer; mid-run greening of a directory on `Documented` while siblings stay stale; file rows for written documents appearing without affecting node counts, deduplicating repeated `Documented` events, and ignoring unknown directories; UI state (selection, collapse, filters) surviving an in-flight run; worker death producing `PACT_LOST` and restoring prior rows; full two-directory runs with exact panel text including per-section tool/thinking/write lines, byte counts, costs, a summary line, and scrolling coverage; per-directory refusal shown in its own section without affecting siblings; a cancelled run's distinct "cancelled — $X spent" line with an exact expected panel; refresh progress counting only visited (stale) directories against the full pacted set, with exact progress-line sequences; a swallowed cost activity producing a "no cost reported" section and an incomplete run total; a mid-run channel closure with no `Finished` event again yielding `PACT_LOST` with no manifest changes and restored rows; newly written documents appearing on screen only via the genuine post-run reload from disk; reader UI state surviving a real reload; un-pacting triggering the same reload path; a reload that fails leaving the prior on-screen tree intact with a `NOT_REFRESHED`-prefixed single-line message; message precedence where the pact's own message wins over the reload's; a `chmod 000`-induced partial reload failure still adopting the new tree while surfacing a problems count; and a node whose hash could not be computed still being colored `PactedStale` with a footer message naming the failure and counting further like it, without wrapping.

The file closes with a nested `watching` submodule testing what the main loop does when files change on disk: the reload a watcher triggers, the reload withheld while a pact is running, and the message shown when there is no watcher at all. It deliberately avoids a real filesystem watcher, standing in `Watching::Off` and driving events by calling `policy.accepted(...)` directly rather than waiting on OS-reported writes. It imports `QUIET_PERIOD`, `RELOAD_CEILING`, `WatchPolicy`, and `Watching` from `warlock_tui`, and defines a helper `unwatched(scope) -> Watched` building a `Watched` with `Watching::Off` and a policy loaded from the tree on disk at that scope. Four tests follow: one confirming a watcher-driven reload (triggered only once the quiet period elapses, not before) preserves selection, collapsed set, pacted-only filter, file-show toggle, and scroll offset while updating node state, noting a header assertion moved elsewhere since reloads don't touch `Chrome`; one confirming that a file change during an in-flight pact produces no automatic reload even past both the quiet period and reload ceiling across many rounds, and that only the run's own end-of-run reload occurs (not a second one from the trigger), verified via a `Running` fixture, a `Finished` event, `apply_progress`, and `watched.caught_up(...)`; one confirming the "live updates are off" footer notice (`NOT_WATCHING`-prefixed, longer than the prefix, no newline) is shown when appropriate but never overwrites an existing run-refusal message, and is absent (`off_note() == None`) when a real watcher starts successfully. The file ends with the closing braces of the `watching` submodule and the outer test module.
