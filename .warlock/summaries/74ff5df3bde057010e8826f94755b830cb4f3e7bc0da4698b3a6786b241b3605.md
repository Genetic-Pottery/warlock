This is the complete, sole part (part 1 of 1) of `app.rs`, the front-end state module for a TUI called Warlock. It comprises extensive doc comments, the implementation code, and a large `#[cfg(test)] mod tests` block at the end. Overall it holds:

**Core purpose**: `App` is the front end's in-memory state for a directory tree "freshness ledger" UI — it flattens an engine `Tree` into a `Vec<Row>` for rendering, tracks selection/scrolling, view filters, a panel with three cards (account/thread/document), a composer, and footer/status messaging. Nothing here touches a terminal or filesystem; it's pure, testable state and logic.

**Key types**:
- `Row` — one flattened tree/file line, carrying path, document, state, children count, file/document/ignored flags, and scope.
- `PactToggle`, `Run`, `InFlight`, `RunHeader`, `Summarising` — describe a pact/refresh run in progress and how it's reported.
- `Focus` (Tree/Panel/Composer) — which pane keys drive.
- `Chrome`, `Sigils` — header line (repo path + held sigils), deliberately kept outside `App` since it never changes per-session.
- `App` struct — nine fields split into three sub-groups by lifetime: `Viewpoint` (collapsed set, pacted-only/show-files flags, viewport height, focus — survives reload), `Status` (message, in-flight run, refusal flag, mouse-captured — short-lived), and `Panel` (three `Card<T>` instances for account/thread/document, with per-card scroll windows, follow flags, mode).
- `Showing`, `Mode`, `Card<T>`, `Shown` trait — panel card management, each with independent scroll/follow state, wrapped-line counting via `rows_of`.

**App impl**: constructors (`from_tree`, `from_rows`, `with_collapsed`, `with_counts`); message/status setters; pact-in-flight lifecycle methods; account/thread/document card management (`start_account`, `write_run`, `show_document`, `refill_document`, `start_turn`, `note`, `record_turn`, `answer_turn`, `end_turn`); card-swapping (`swap_card`) and visibility queries; panel height/width/scroll accessors; row/collapse/pacted-only/show-files view methods; movement methods (select_next/previous/page/first/last, pointer-driven `select_row`/`select_next_by`/`scroll_panel_*`) routed through a shared `movement` helper respecting `Focus`; `reflow`/`rescroll` internals; `toggle_pact`, `refresh`, `scope_target`, `view_target` — the three key handlers with refusal wording; `set_subtree_state`, `insert_file_row` for painting run results onto rows without a full reload.

**Free functions**: `reseat_on` (rebuild an `App` on a fresh `Tree` while preserving view state), `walk_of`, `node_rows`, `paint_subtree`, `moves_with_subtree`, `in_subtree`, `drawn_rows`, `pacted_rows`, `index_for`, `scroll_offset_for`, `panel_offset_for`, `file_row_position`, `count_mut`, and numerous `*_message` functions producing exact footer/refusal wording (e.g. `left_on_disk_message`, `pacting_message`, `already_fresh_message`, `unpacted_message`, `file_row_message`, `ignored_row_message`, `cut_at_cap_message`, `no_document_message`, `summarising_message`, `already_running_message`).

**Test module**: a very large suite (hundreds of tests) covering flattening, selection/scrolling arithmetic, collapse/expand, pacted-only and show-files filters (and their composition), pact/refresh/scope/view key refusals and their exact wording, panel card independence (windows, follow flags, swap cycling), run lifecycle (in-flight, summarising, refusal suffix, run headers), thread/turn handling, mouse-wheel-equivalent pointer methods, `reseat_on` behavior (carrying/discarding fields, selection fallback to nearest ancestor), and `insert_file_row` splicing semantics (ordering, document-row marking, filter/collapse interaction, tally invariance).

A reader of the whole file would need nothing more from elsewhere — this is the entire file, fully self-contained with its tests.
