This is a complete Rust source file (`edits.rs`) implementing the three headless, non-interactive write subcommands of warlock: `warlock unpact <path>`, `warlock scope add <path> <scope>`, and `warlock scope remove <path>`. It consists of an extensive module-level doc comment, the implementation code, and a large embedded test module.

**Module doc comment** explains the design rationale at length:
- These are the first subcommands that mutate `.warlock/pacts.toml`, following the same execution shape as prior read-only subcommands (dispatched before any terminal setup, errors surfaced through `Error` and printed by `main`), but each write is gated by a boundary check.
- Two "doors" enforce the same boundary rule: `closed_scope` (used by the TUI) and `Opened::new` (used here). Both consult `scope_covering` and `scope_opens_to` from `warlock_engine` and never re-implement that logic.
- The boundary must be asked strictly first — before any manifest existence checks — so a closed boundary never leaks information about the manifest's contents.
- Un-pacting asks a *second* boundary question (about the whole subtree reached, via `Reach::HereAndBelow`), after the first has passed, to prevent erasing a descendant's scope by targeting its ancestor.
- Explains `scope_covering`/`scope_opens_to` semantics (nearest scope wins, invalid scope = no scope, unscoped = open to anyone, holding nothing opens nothing scoped), and that `Sigils` come from `warlock config`'s on-disk state.
- Exit codes: boundary refusal = status 3 (permanent, no retry path except obtaining a sigil); other failures = 1. Rationale contrasted with the descendant-boundary refusal, which stays at 1 (documented further in `status_for`).
- Un-pact is described as purely a manifest edit (via `unpact_subtree`/`Manifest::save`) — never touches `WARLOCK.md` files, hashes, or model passes.
- Blast radius discussion: `warlock unpact .` could drop every entry; protected by the second boundary question; success message names every dropped entry that carried a scope for auditability.
- Scope add/remove rules: text is lower-cased then validated via `validate_scope`; folding happens before validation; nothing is trimmed/split; clearing is a separate command (`scope remove`) rather than an empty value to `scope add`; removing a scope that isn't set is treated as success (idempotent).
- Un-pacting a never-pacted repo still succeeds, writing an empty manifest (idempotent behavior, avoids special-casing).

**Code proper:**
- `Opened` struct: holds `repo_root`, `manifest`, `target`, `sigils` (private fields, gate pattern) — the only way to get one is `Opened::new`, which performs the first boundary check via `verdict(...)` and returns `Error::ClosedScope` on failure.
- Accessor methods: `repo_root()`, `manifest()`, `target()`.
- `Opened::unpacted()`: spells the path, checks the second (below-reach) boundary via `verdict` (returns `Error::ClosedScopeBelow` on failure), calls `unpact_subtree`, computes dropped entries by diffing old vs. new manifest, saves, returns a formatted success line.
- `Opened::scoped(scope)`: spells path, folds/validates scope, records prior scope, rebuilds via `with_scope_on`, saves, returns line describing new (and possibly replaced) scope. Errors: `Unspellable`, `Scope`, `NoPact`, `Manifest`.
- `Opened::unscoped()`: same shape but clears the scope; success even if nothing was scoped.
- `Opened::scope_on(module)`: helper returning current scope or `Error::NoPact`.
- `opened(wanted, path)`: free function resolving environment (working dir, repo root, manifest, home/sigils) into an `Opened`, shared by all three subcommands and reused conceptually by `mod running`.
- Public subcommand entry points: `unpact(path)`, `scope_add(path, scope)`, `scope_remove(path)` — each just calls `opened(...)` then the corresponding method, printing `"warlock: {line}"` and returning `Result<(), Error>`.
- Formatting helpers: `unpacted_line(path, dropped)` (pluralizes "entry"/"entries", lists scoped-dropped entries only if any), `scoped_line(module, scope, was)` (notes replacement only if scope changed), `unscoped_line(module, was)` (two cases: had a scope vs. didn't).

**Test module (`#[cfg(test)] mod tests`)** is extensive, using `tempfile` temp dirs for repo/home, building fixture manifests (`a_manifest`, `a_repository`, `a_manifest_of_boundaries_both_ways`, `a_repository_of_boundaries`) and helper wrappers (`unpact`, `scope_add`, `scope_remove`, `stored`, `manifest_bytes`, `holding`, `refusal`) that exercise the production path (`Opened::new` → method). Notable test cases:
- Open boundary drops subtree correctly, leaves documents on disk, correct message and exit status 0.
- Closed boundary refuses with `Error::ClosedScope`, exact message matches `closed_scope_message`, status 3, manifest untouched.
- Machine holding nothing is refused for every scoped directory but allowed for unscoped ones.
- Success line lists every dropped scoped entry (root-level un-pact test).
- Descendant ("below") boundary refusal (`ClosedScopeBelow`), exact message, status 1 (not 3), tested both for a directly-held target with a closed descendant and for an unscoped root with closed descendants; also tested with a machine holding nothing (lists both scopes).
- Singular "entry" wording test; unscoped drop message test.
- Refusal for unspellable/outside-repo paths, before any write, for both unpact and scope writes.
- Un-pacting a never-pacted repo creates an empty manifest file.
- A scope engine would consider invalid (e.g., `"Data Plane!"`) is still named in the dropped-entries message.
- Scope add writes only the scope field, leaves other entries/fields (hash, timestamp, document) untouched.
- Scope add replacing an existing scope reports "was `x`"; re-adding the same scope reports no replacement.
- Case folding happens before validation (`Data-Plane` accepted, folded to lowercase, though raw validate_scope rejects capitals).
- Scope remove clears scope, preserves grant/document fields; removing from an already-unscoped entry is idempotent success with byte-identical file.
- Closed boundary refuses both scope add and remove, same message/status as unpact.
- Ordering test: boundary is checked before checking whether an entry exists in the manifest (avoids leaking manifest shape); confirmed for scope_add, scope_remove, and unpact all following this rule.
- Scope validation refusals (list-like string, capitalized-with-space, empty string, trailing dash) produce exact engine error messages, status 1, and no write.
- No-entry directory refused via `Error::NoPact`, message contains directory name and mention of `p` key.
- Unscoped/no-scope clear line helper tests.
- A parity test (`a_key_press_and_a_shell_prompt_answer_the_same_un_pact_alike`) that builds a TUI `App` panel over the same fixture repository and compares the `p` keypress path (`pressed_p`) against the shell `unpact` path across four scenarios (scope on target, scope only below, scope below but held, unscoped root with closed descendant), asserting both doors return identical `Answer` (WentAhead or Refused with matching sentence, accounting for the panel's relative-path vs. shell's `.` labeling of the root).
