This file implements warlock's terminal UI rendering and its accompanying test suite.

The production code opens with an extensive module-level doc comment describing the frame layout: a footer along the bottom, a panel pane on the left, and a bordered tree pane on the right (header naming the tree, flattened tree rows below). It notes that `draw` is a pure function of frame, app state, and a caller-supplied `Instant` (no internal clock or terminal access); that the panel shows either an "account" of a running/last pact or a compiled-in ASCII/block "mark" (warlock's wordmark) before any pact has run; that the tree window scrolls via the app's own scroll offset and row list; that `hit_test` maps screen coordinates back to logical areas without any app state; and that a "quit confirm" and scope-prompt overlay are drawn on top of everything else when active. Imports bring in ratatui primitives, engine types (`NodeState`, `SCOPE_RULES`), and sibling modules (`account`, `app`, `colour`, `confirm`, `prompt`).

A long, heavily documented block of constants follows, covering: tree-drawing glyphs (indentation, guide characters, selection/collapsed/expanded/no markers); the `MARK` constant, an 8-line ASCII/block-art "WARLOCK" wordmark, plus margin constants controlling when it's drawn; header height/gap constants; panel indentation and ellipsis/truncation constants; the scrollback indicator text and its key; a large set of key-label constants collected into `KEYS` and an ordered `KEY_DROP_ORDER` governing which footer key labels drop first when space is tight; functions `laid_out_keys` and `clipped` (character-boundary-safe truncation) supporting that; `keys_line` for the idle footer; a parallel set of pacting-mode key constants, `PACTING_KEYS`/`PACTING_KEY_DROP_ORDER`, and `pacting_keys_line`; footer height, tree-column width proportion/floor (`TREE_PERCENT`, `TREE_MIN_WIDTH`), and border thickness constants; `PULSE_PHASE` (500ms) governing the stale/fresh colour pulse on the in-flight directory row during a pact; and sizing constants for the quit-confirmation window (question/Yes/No text, margins, computed height) and the scope-prompt window (heading, margins, cursor character, computed height).

`draw` computes panel/tree/footer areas via `areas(screen)`, calls `draw_panel`, `draw_tree_pane`, `draw_footer`, then conditionally overlays `draw_confirm` and/or `draw_scope` (confirm before scope, since only one is ever live). An `Areas` struct and `areas()` implement the split logic: footer taken off the bottom at a fixed height, remainder split into panel/tree by proportion with a floor and a half-width cap (worked out in `tree_width`). Helpers `pane_inner` and `tree_rows_area` follow, plus public `tree_height`, `panel_height`, and `panel_width`, which expose layout measurements to the app for scroll/wrap calculations using the same `areas()` call used for drawing.

A `Hit` enum (`Offscreen`, `Footer`, `Border`, `TreeHeader`, `TreeRow{offset}`, `TreeBelowRows`, `PanelLine{offset}`) represents what a screen point lands on, and `hit_test` implements that mapping purely from column/row/terminal size, reusing `areas`/`pane_inner`/`tree_rows_area`. `pane_block` builds a bordered `Block` styled for focused (bold, `FOCUS_COLOUR`) versus unfocused (dim) panes.

`draw_panel` renders the pane border (with a bottom-right scrollback title if scrolled), then either draws the centred `MARK` via `draw_mark`/`mark_area` (if the panel has no content yet), or renders the app's current panel lines (account or document) as a borderless, non-wrapping `Paragraph`, each line pre-cut to width by `panel_row`. `mark_area` computes centring for the `MARK` art, returning `None` if there isn't room (it is drawn whole or not at all). `scrollback` formats the "N more" indicator string. `panel_row` converts one `Entry` (Directory/Clocked/Summary/Text line) into a styled, width-truncated `Line`. `truncated` and `display_width` are generic, character-boundary-safe, column-aware truncation/measurement helpers used throughout, appending an ellipsis where they cut. `draw_tree_pane` sets up the tree pane's border, splits its inner area into header and rows, and calls `draw_header`, followed by further (unspecified) tree-row drawing logic.

The remainder of the file is a test module. It imports the constants/functions above plus app types (`App`, `Chrome`, `Row`, `Sigils`), account/confirm/prompt types, and a `fixture` module supplying a sample tree. It defines constants for terminal dimensions and thresholds (`MANY`, `WIDTH`/`HEIGHT`, `CHROME_HEIGHT`, `KEYS_WIDTH`, `EIGHTY_COLUMNS`, `FILES_HEIGHT`, `FIXTURE_HEIGHT`, a `WHOLE_FIXTURE` array of the fixture tree's expected lines), mark-sizing constants, pulse-timing constants, and scope-label constants. Helper functions build fixtures and render to a `ratatui` `Buffer`, extracting areas/text/styles for assertions (`many_rows`, `labelled_rows`, `styles_of`, `terminal_width_for`, `tall_app`, `pacting_app`, `panel_area`/`panel_rows`/`panel_bottom_edge`, `rows_area`/`header_area`, `tree_rows`/`tree_row`, `render`/`render_at`/`render_confirm`/`render_scope`/`render_chrome`/`render_windows`, `row_text`/`text_in`/`rows_text`, `first_glyph_colour`, `column_of`/`guide_columns`, `row_index`, `select`, `highlighted_rows`, `mark_width`, `assert_mark_drawn`/`assert_bare_panel`/`assert_no_mark`, and more).

The tests, organised roughly by feature, verify: tree row indentation/guides per depth and scroll position; documents drawn as file rows under their directories; guide colouring independent of row-state colouring; the pulse animation on in-flight rows, including phase reset, steady state, and stopping when the pact ends; collapse markers gated by whether a directory has children; per-node state colouring, with files inheriting their directory's colour; scope labels appended to directory names in the row's colour, shown only on the owning directory, dropped whole rather than ellipsized when too narrow, and unaffected by selection; file-row toggling; selection highlighting exactly one row; scrolling behaviour with a fixed header/footer; height measurement into drawn row counts, including a zero-height case; footer content (tallies by node state, the full keys line, filtering, refusal messages, pact-progress lines, and progressive key-dropping as width shrinks, cutting at character boundaries and differing by pacting/mouse-capture state); footer drawing three undimmed-tally lines when there's room; the mouse-toggle key's wording reflecting the action a press would take; a pact-in-flight footer replacing the keys line entirely; empty-tree and header-naming behaviour, including relative paths, blank roots, a "holding x, y" clause (or "holding unknown"), byte-identical output when holding nothing, and that clause being dropped whole rather than partially truncated when too narrow; header position relative to the first tree row; panel/tree width-sharing including the floor, half-split fallback, and a fuzz test bounding the tree column's width; extensive hit-testing across panes, borders, short/narrow terminals, and a fuzz test bounding returned offsets, plus off-frame points returning `Offscreen`; the panel "mark" watermark appearing only when the panel is otherwise empty, centred and dim, absent when the terminal is one row/column short or generally too narrow, and never returning once any pact activity exists; account rendering with per-directory headings, per-line order, restarting elapsed-time clocks per section, a live clock advancing between frames, and ellipsis-cut (not wrapped) long lines leaving neighbouring border cells untouched; document rendering (via a `viewing_app` helper) wrapping long lines and appending a continuation notice when a read is cut short; a two-card panel (account plus document) drawing only the "showing" card, with `swap_card()` toggling cleanly and reversibly; the scrollback indicator reflecting remaining lines per card, following swaps, and disappearing when live; `truncated`'s column-based (not byte/char-based) cutting across ASCII, accented, and full-width text; scrolled-back panel details (the "N more" message and "back to live" hint appearing only when scrolled, not consuming a row, and exact restoration on return to live); `panel_width`/`panel_height` matching actual rendered dimensions including a zero-height case; focus styling limited to border colour/weight, not content; an extensive suite on the quit-confirmation window (sizing from content plus margins, small and centred, exactly one question and two ordered answers, no leakage of underlying frame content or footer key names, pixel-identical cells outside the window, zero trace once closed, default highlight on "No" moving to "Yes", and clamped-but-drawn behaviour on very small terminals, with the footer unchanged while it's up); and a parallel, equally thorough suite on the scope-assignment prompt window (constant height regardless of content, heading/rules/empty field with cursor at position zero when no scope is carried, pre-filled field with cursor after existing text, a refused submission preserving typed text and showing the refusal reason without moving the field, no leakage or disturbance of non-window cells, zero trace once closed, and clamped-but-drawn behaviour on very small terminals). The test module, and the file, end after these tests.
