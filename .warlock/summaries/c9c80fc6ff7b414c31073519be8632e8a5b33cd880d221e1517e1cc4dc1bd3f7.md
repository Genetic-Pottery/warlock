This is the implementation module for building a `Tree` from a real directory on disk, part of Warlock's engine crate.

**Module documentation (top doc comment):** Explains the design rationale for `load_tree`: the tree is rooted at whatever working directory is given (no privileged root, per the "modular invocation" rule), while the manifest that colours nodes is read from the repository root found by walking upward for the nearest ancestor containing `.git/` (manifest at `<root>/.warlock/pacts.toml`). It defines what constitutes a "node" (every directory reached by the walk, documented or not), how files are attached to their containing node, and how the `ignore` crate's traversal rules (`.gitignore`, hidden files, `.git/`, global excludes) apply, plus the unconditional pruning of `.warlock/` and non-following of symlinks. A significant subsection explains why the repo's own `.warlockignore` file deliberately does *not* prune anything from this particular walk — excluded directories still appear in the tree (as normal, unpacted/gray rows) but are marked via `Node::ignored`, computed by diffing two walks (with and without `.warlockignore` registered). It also describes how state is derived (`Unpacted` if absent from manifest, otherwise hashed and compared via `decide_state`), how hash failures are non-fatal but recorded as `Problem`s and force `PactedStale`, and how invalid scope strings are similarly reported as `Problem`s without correcting the manifest or blocking the load.

**Constants:** `GIT_DIR` (`.git`), `MANIFEST_DIR` (`.warlock`), `DOCUMENT_FILE` (`WARLOCK.md`).

**`load_tree` function:** Public entry point. Takes a working directory, makes it absolute, finds the repository root, loads the manifest (treating "not found" as an empty manifest, other errors as fatal `Error::Manifest`), walks the directory tree, and builds the `Tree` via a `Builder`. Includes a doctest demonstrating a simple crate layout, showing documented vs. undocumented nodes, file listings, and an empty problems list. Documents its error cases: `NoRepositoryRoot`, `Io`, `Manifest`, `Walk`.

**`Loaded` struct:** Pairs the resulting `Tree` with a `Vec<Problem>` — non-fatal issues encountered during load, kept separate from `Tree` because they serve different purposes/lifetimes.

**`Problem` struct and `ProblemCause` enum:** A `Problem` records a `path` and a `cause`. `ProblemCause` has two non-exhaustive variants: `Hash(HashError)` for subtree hashing failures, and `Scope { scope, rule }` for manifest entries whose scope string fails validation (with `ScopeRule` naming which rule was broken). Both implement `Display` and `std::error::Error` (with `source()` delegating appropriately).

**`repository_root` function:** Public helper; finds the nearest ancestor (including the start path itself) containing a `.git` directory (checked as an actual directory, not e.g. a worktree file), returning `None` if none is found.

**`walk` function:** Private; performs one pass over the filesystem using the `ignore` crate to build a `BTreeMap<PathBuf, Directory>`, interleaving directory and file discovery so files are attached to their parent directory as encountered. Sorts each directory's file list afterward, then calls `mark_excluded` to annotate ignored directories. Uses a `BTreeMap` for deterministic parent-before-child, name-ordered iteration.

**`builder` function:** Private; constructs the shared `WalkBuilder` configuration (no symlink following, `require_git(false)`, and a filter excluding `.warlock/` by name), used identically by both the main walk and the `.warlockignore`-aware walk to avoid configuration drift.

**`mark_excluded` function:** Private; determines which directories are excluded by the repository's own `.warlockignore`, by first checking if the walk's root itself is ignored (a walker doesn't apply rules to its own root) and, if not, running a second walk with `.warlockignore` registered as a custom ignore filename and computing the set difference against the first walk's directories. Marks `Directory::ignored` accordingly without removing anything from the map.

**`Directory` struct (private):** Holds `has_document: bool`, `files: Vec<PathBuf>`, and `ignored: bool` — the per-directory facts gathered by the walk passes.

**`Builder` struct (private) and its `impl` block:**
- Holds the `directories` map, `repo_root`, and `manifest`.
- `node()`: recursively constructs a `Node` for a given directory, gathering children first (depth-first), then setting document, files, ignored flag, state, and scope, pushing any `Problem`s encountered along the way.
- `children_of()`: returns direct child directories of a given path in name order, exploiting the sorted `BTreeMap` structure to find a contiguous range and filtering by direct parentage.
- `state_of()`: looks up whether a directory has a manifest entry; if not, returns `Unpacted` without hashing (cost-free for unmanaged directories); if so, computes `subtree_hash` and calls `decide_state`, or on hash failure pushes a `Problem` and returns `PactedStale`. Paths with no valid manifest form are treated as `Unpacted`.
- `scope_of()`: looks up the scope string on a directory's own manifest entry (not inherited from ancestors), validates it via `validate_scope`, and either returns it or records a `Problem` and returns `None`, leaving the manifest bytes unmodified.

**`absolute` function:** Private helper; converts a path to an absolute, lexically-normalized path (resolving `.`/`..` components) without touching the filesystem or following symlinks, so the tree is rooted at exactly the path given.

**`Error` enum:** Public, non-exhaustive, hand-rolled (not using an error-handling crate) with four variants: `NoRepositoryRoot { start }`, `Io { path, source }`, `Manifest { source: ManifestError }`, `Walk { source: ignore::Error }`. Implements `Display` and `std::error::Error` with appropriate `source()` delegation.

**Test module (`#[cfg(test)] mod tests`):** A large suite of unit tests, including numerous helper functions:
- `fixture` / `git_only_fixture`: build temp directories simulating repositories (with or without an existing `.warlock/` directory) with specified subdirectories and `WARLOCK.md`-documented directories.
- `tree_of`: loads a tree and asserts no problems occurred.
- `pact`: writes manifest entries (undoted/ungranted, i.e., stale) for given modules.
- `write_file`: writes a file, creating parent directories.
- `hand_write_manifest` / `hand_write_scoped_manifest`: write raw TOML manifests by hand (simulating a human editor), including ones with granted hashes or with scope strings — needed because the workspace itself provides no API to produce a granted/fresh state or certain invalid scope strings.
- `file_names`, `relative_paths`, `states`: extract/compare data from a loaded `Tree` for assertions.
- `excluding_fixture`: a fixture with a `.warlockignore` excluding `notes/` directories under a pacted `docs/` module.

Test cases cover: document detection creates module nodes while non-documented dirs remain nodes; plain `README.md` documents nothing but is still listed and hashed like any file; full walk of an undocumented repo; rooting the tree at a subdirectory while finding the manifest above it; unpacted-by-default behavior with no manifest or no `.warlock/` at all (cold open); first-pact behavior creating `.warlock/`; skipping ignored/`.git`/`.warlock` directories; `.warlockignore` marking (not pruning) excluded directories, propagating the mark to descendants, handling a load rooted directly at an excluded directory, and confirming edits within excluded content never change colour while edits to covered content do; behavior with no `.warlockignore` rules at all; file listing correctness (sorted, including the document itself, files scoped to their own directory, `is_leaf` semantics); files obeying the same ignore rules as directories; deep nesting; empty-manifest behavior; a manifest entry colouring only its own node and not descendants; hand-written matching grants being fresh until content below changes; (unix-only) unreadable files causing one node to go stale with a recorded `Problem` while leaving the rest correctly coloured, and unpacted nodes never being hashed so unreadable files there cause no problem; (unix-only) symlinked directory cycles being safely handled without infinite recursion or being listed; a full workspace-shaped example test; error cases for paths outside any repository and for a corrupt manifest; scope-related tests confirming a scope lands only on its own node and not elsewhere, absence of entries means no scope, and a comprehensive `NOT_SCOPES` array of seven invalid scope strings (empty, leading digit, trailing hyphen, wildcard, too long, non-ASCII, and wrong case) is tested to ensure each produces a correctly reported `Problem` while leaving state, document, files, and children intact, and that one bad scope doesn't affect other directories' scopes; and finally a check that each `Error` variant's `Display` produces the expected message text.
