This is the complete source of a Rust module (`watch.rs`) implementing filesystem-watching support for a tool called Warlock, split into a substantial module-level doc comment, implementation code, and an extensive test module.

**Module doc comment (top):** Explains the design philosophy of the file: it separates the impure act of hearing about filesystem changes from two pure questions answered as values — (1) which filesystem events are relevant (decided by `NodeSet`, built from the last successful tree walk, with no independent gitignore logic) and (2) when to act on them (decided by `WatchPolicy` via three named constants). It stresses that `Watch` (the impure watcher wrapper) only relays paths and never filters or decides; that no `Instant::now()` is called anywhere in the file (callers supply all instants, enabling deterministic testing); and lists explicitly what is *not* here: no `notify` types leaking out, no actual reload logic, no debouncing elsewhere, no persisted state.

**Constants:**
- `QUIET_PERIOD` (250ms) — debounce period of quiet before reloading.
- `RELOAD_CEILING` (2s) — max time to delay reload despite continuous events.
- `COALESCED_RELOADS` (1) — exactly one extra reload owed for events arriving during an active reload, regardless of count.

Each constant has a detailed doc comment justifying its value and purpose.

**`NodeSet` struct:** Wraps a `HashSet<PathBuf>` of directory paths taken from a `Tree`'s nodes (via `from_tree`). Provides `accepts(path)` — true if the path's immediate parent is a known directory (with a doctest showing acceptance of a docs file and rejection of a `target/debug` path), plus `len()` and `is_empty()`.

**`WatchPolicy` struct:** Holds a `NodeSet` (`watched`), burst-tracking state (`burst_began`, `last_event`), and reload state (`reloading`, `moved_during_reload`). Includes a doctest demonstrating a full cycle: seeing an event, checking `due`, reloading, following a new tree. Methods:
- `new(tree)` — build from a tree, nothing owed.
- `follow(tree)` — replace the filter with a new tree's directories, without touching pending state.
- `watched()` — accessor.
- `saw(path, at)` — record an event, filtered through `NodeSet::accepts`; returns whether accepted.
- `accepted(at)` — record an already-accepted event (used e.g. for the manifest file, which isn't in the walked tree); sets `moved_during_reload` if currently reloading, else updates burst timing.
- `due(now)` — core decision: false while reloading; otherwise true if quiet period elapsed since last event or ceiling elapsed since burst start.
- `reload_started()` — clears burst state, marks `reloading = true`.
- `reload_finished(at)` — clears `reloading`; if something moved during the reload, starts a new burst at `at` (implementing the coalesced-reload rule).
- `owes_reload()` — whether anything is pending (burst or coalesced flag).

**`Watching` enum:** `Live(Watch)` or `Off(String)` (human-readable failure reason), representing the outcome of trying to start a watcher — not a `Result`, since failure is a normal, non-fatal outcome.

**`Watch` struct:** Wraps a `RecommendedWatcher` handle (kept alive, unused directly), an `mpsc::Receiver<PathBuf>` for events, and a `live` bool. Methods:
- `start(root, repo_root)` — sets up a `notify` watcher over `root` recursively, sends every event path (regardless of filtering) through a channel; also attempts to watch the manifest file via `watch_manifest`. Returns `Watching::Live` or `Watching::Off` with the stringified error.
- `drain()` — non-blocking collection of all pending paths from the channel; sets `live = false` on disconnect.
- `live()` — accessor for connection status.
- A custom `Debug` impl that only prints the `live` field (since the watcher handle/channel aren't meaningfully printable).

**`watch_manifest` free function:** Tries to watch the manifest file directly, falls back to watching its parent directory (`.warlock/`) non-recursively, and silently gives up if both fail (failure isn't reported since there's no actionable response).

**Test module (`#[cfg(test)] mod tests`):** Extensive, uses a `walked()` helper building a sample `Tree` (root, `crates/`, `crates/engine/`), and a `drive()` function that simulates an event loop over `WatchPolicy` at 10ms ticks (`TICK_MS`) with configurable simulated reload duration, returning reload timestamps — this lets tests exercise burst timing deterministically without real sleeping. Helper constants `SLACK`, `LONG_AFTER`, and a `gap()` helper for duration assertions. Tests cover:
- `NodeSet::accepts` behavior for walked vs. unwalked directories (including `target/`, `.git/`, near-misses, root path, filesystem root).
- New directories under walked ones being accepted.
- `WatchPolicy::follow` replacing the filter after a reload.
- A simulated single editor save producing exactly one reload after the quiet period.
- Events spaced over a second apart producing two reloads.
- A continuous 10-second event stream reloading at the ceiling rate (asserting 4–6 reloads, timing bounds, and that it isn't behaving like plain debouncing).
- Events arriving during a reload causing exactly one further coalesced reload, with timing checks.
- A thousand events during one reload still producing only one extra reload.
- A reload with nothing moving under it being the final one (no reload owed afterward).
- Rejected events (build artifacts) causing zero reload activity even in bulk (5000 events).
- The `accepted()` escape-hatch path (manifest file) following the same timing rules as `saw`.

A nested `mod live` (with its own `scratch()` helper creating/cleaning up temp directories under `/tmp`, using an atomic counter for uniqueness) contains the only two tests touching a real filesystem/watcher:
- Starting a watcher on a nonexistent root yields `Watching::Off` with a nonempty reason string.
- Starting a watcher on a real (empty, no `.warlock/`) directory yields `Watching::Live`, reports `live() == true`, and an immediate `drain()` is empty without blocking.
