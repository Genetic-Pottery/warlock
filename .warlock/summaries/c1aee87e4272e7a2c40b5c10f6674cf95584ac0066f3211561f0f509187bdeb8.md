This is the complete (and only) part of a Rust source module named `chatting.rs`, which implements the conversational side of a terminal application called warlock. It consists of a large module-level doc comment, implementation code, and an extensive embedded test suite.

**Module doc comment** explains the design: `Chat<C>` is a single struct combining the register (mode), the input field, and conversational turns. It describes five call sites that used to be separate event-loop locals now unified here: the draft field, submitting a message, three slash commands (`/brief`, `/write`, implicitly `/chat`), and the write-confirmation window. It draws a parallel to a `pacting` module's four-part shape (spawn/start/run/apply for background work), noting a "turn" (one `claude` invocation) mirrors a "run" (many) but writes no documents and touches no `Tree`/`Manifest` except that `/brief` and `/write` now read the repository root. It explains the field is muted only during a turn (not during a "pact"/run), and that all turn failures collapse into a single `Ending` enum rather than propagating as errors, using a `CancelGuard` reused from the pacting module.

**Constants**: `TURN_LOST` (message for a worker that panicked without reporting), `BRIEF_COMMAND`/`CHAT_COMMAND`/`WRITE_COMMAND` (display strings for commands), `BRIEF_NOTE`/`CHAT_NOTE` (one-line notices on mode change), `ALREADY_CHATTING`/`NOT_BRIEFING` (refusal lines for redundant/misapplied commands).

**Free functions**:
- `unreadable_template` / `unreadable_briefs` — format refusal lines when `.warlock/brief-template.md` or `.warlock/briefs.toml` exist but can't be read/parsed, quoting the underlying loader errors.
- `brief_asking(root)` — builds the `/brief` instruction from the repo's template or the built-in default.
- `brief_reading(root)` — loads both files needed for `/brief` (template instruction, target directory), stopping at the first failure.

**`Chat<C>` struct** (generic over `C: Converses`, the model-talking seam): fields `agent`, `turn: Option<Chatting>`, `root: PathBuf`, `composer: Composer`, `directory: String` (where a brief would be written), `prompt: ScopePrompt` (the write-confirmation window). Constructors `new`/`with_agent`. Accessors `composer()`, `write_prompt()`, `directory()` (test-only), `answering()`.

**Key methods**:
- `ask`/`say` — start a turn, showing one string on the card and sending another (used for synthesized instructions like `/brief`/`/write`).
- `settle_field` — mutes/unmutes composer based on whether a turn is active.
- `stop` — cancels an in-flight turn (Ctrl-C).
- `keep_up` — drains the turn via `apply_turn`, opens the write window if a document came back.
- `write` — handles keystrokes inside the write-path prompt.
- `compose` — the big dispatcher handling `Composed::Typing`/`Leave`/`Submit`, and within Submit, handles `Submitted::Message`/`Brief`/`Chat`/`Write`/`Refused` cases, each documented at length with cross-references to ordering rules (mode set before/after turn, load before mode, etc.).

**Supporting types**: `Chatting` (turn state: event receiver, `CancelGuard`, `Asked`), `Asked` enum (`Answer` vs `Document`, distinguishing whether the drain hands the answer back to the loop), `TurnEvent` enum (`Doing(Activity)`, `Finished(Result<String, Ending>)`).

**Worker plumbing**: `activity_port` (forwards activity events through the channel), `wired` (attaches cancel/port to an agent clone), `asking` (picks effort/model based on `Mode`, cloning rather than rebuilding the agent to preserve session), `spawn_turn` (spawns detached thread running `run_turn`), `start_turn` (builds a `Chatting` value), `run_turn` (worker body: calls `agent.turn`, classifies errors including cancellation, sends exactly one `Finished` event), `apply_turn` (non-blocking drain loop applying `Doing`/`Finished` events to the `App`, returning the document string only for `Asked::Document` turns that succeeded), `end` (records an ending on both the thread card and footer).

**Test module** (`#[cfg(test)] mod tests`): extensive unit tests using helper functions (`at`, `asking`, `chatting`/`writing`/`turn_for`, `drain`, `rows`, `said`, `clocked`) covering: work lines landing without ending the turn, answers landing and ending turns, `/write` turns handing back documents (success, various failure `Ending`s, dead worker, still-in-flight), ending wording consistency, cancellation preserving prior lines, panicked-worker handling, sequential questions working normally, mode-switching only changing model/effort args (not session/prompt/tools), mode changes being conversation state not new sessions, no-op frames.

A nested `#[cfg(unix)] mod unix` submodule uses `/bin/sh` stand-ins to test the real transport layer end-to-end: successful turns, missing program, non-zero exit, empty output, timeout, pre-cancelled and mid-flight cancellation (verifying the child process is actually killed and the channel closes cleanly), synthesized-turn display/send separation, failed-turn recoverability, and `/write` turn success/failure through the full `Chat` value including window-opening and proposed file paths.

A further nested `mod submitting` tests the `compose`/`Submit` dispatch path specifically: field muting across a turn's full lifecycle, `/write` outside brief mode being refused without cost, `/write` inside brief mode sending a shown-as-command turn, `/brief` behavior with no template (built-in shape), custom template, unreadable template (refusal, recovery), directory settling from `briefs.toml` (default, custom, unreadable/refusing with recovery, refusal preserving prior good directory, re-reading on second `/brief`), two-broken-files precedence, `/brief` re-sent in brief mode, `/chat` leaving mode / no-op in chat mode, verifying mode changes never clear/hide/reorder existing card rows or turns (including with real answers and work lines present), generic refusal handling for malformed slash commands, and ordinary message submission behavior.
