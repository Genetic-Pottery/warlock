This is `ui.rs` in full (the whole file, one part), the rendering module for warlock's terminal UI, built on ratatui. It defines how a single frame is drawn each tick.

**Module structure and top-level function**: The public entry point is `draw(frame, app, chrome, now, confirm, scope, path, composer)`, which lays out and draws the entire screen: a left panel, a right bordered tree column, a composer field under the panel, a full-width footer, and up to three modal windows drawn over everything (quit confirmation, scope prompt, path prompt). It's documented as pure — a function of `app`, `chrome`, `now`, and the window states, with no terminal state of its own.

**Layout**: `Areas` (private struct) holds `panel`, `composer` (`Option<Rect>`), `tree`, `footer`. Built by `areas()`, which cuts off the footer (`FOOTER_HEIGHT` = 3) first, then splits left/right by `tree_width()` (uses `TREE_PERCENT` = 30, `TREE_MIN_WIDTH` = 30), then calls `split_column()` to cut the composer off the bottom of the panel column (using `Composer::height`, `COMPOSER_MIN_HEIGHT` = 4). `pane_inner()` and `pane_block(focused: bool)` (public/private helpers) handle border insets; `BORDER_THICKNESS` = 1.

**Public measurement functions** (used by the app to size its scroll windows before drawing): `tree_height`, `panel_height`, `run_header_height`, `composer_height`, `panel_width` — all measured off the same `areas()` call the frame uses, so scrolling stays in sync with rendering. `composer_on_screen` (pub) and `on_screen` (private) decide whether the composer is drawn, deferring to `App::composer_showable`.

**Hit testing**: public enum `Hit` (`Offscreen`, `Footer`, `Border`, `TreeHeader`, `TreeRow{offset}`, `TreeBelowRows`, `PanelHeader`, `PanelLine{offset}`, `Composer`) and public function `hit_test(column, row, size, composer, header)` mapping a screen point to what's drawn there, for mouse support.

**Drawing functions** (all private except `draw`): `draw_panel` (draws account/thread/document card or `MARK` art when empty, via `mark_area`/`draw_mark`), `draw_run_header`/`run_header_line`/`bar`/`run_word` (progress bar header for pacting/refreshing runs), `draw_composer`, `draw_tree_pane`/`draw_header`/`header_line` (module identity + sigils via `Chrome`), `draw_tree`/`line`/`guide_prefixes` (tree rows with guides, markers `COLLAPSED_MARKER`/`EXPANDED_MARKER`/`NO_MARKER`, scope labels), `pulse_colour` (pacted-row pulsing animation using `PULSE_PHASE` = 500ms), `draw_footer`/`footer_text_area`/`noun`, `draw_confirm`/`answers_line`/`confirm_area`/`confirm_size`/`centred` (quit gate), `draw_scope`/`scope_lines`/`scope_size` (shared window for scope prompt and path prompt, using `SCOPE_HEADING`, `PATH_HEADING`, `PATH_RULES`, `scope::RULES`).

**Key/footer line assembly**: constants `KEYS`, `KEY_DROP_ORDER`, `PACTING_KEYS`, `PACTING_KEY_DROP_ORDER`, and functions `laid_out_keys`, `clipped`, `keys_line`, `pacting_keys_line` implement graceful degradation of the footer's key hints on narrow terminals.

**Text utilities**: `truncated` (ellipsis-cut), `clipped` (no ellipsis), `display_width` (`pub(crate)`, via ratatui `Span::width`), `panel_row` (turns an `account::Line`/`Entry` into a styled ratatui `Line` via `crate::wrap::shape`).

Many public(crate) constants are exported for use elsewhere: `PANEL_INDENT`, `SAID_MARKER`, `NOTE_MARKER`.

A large `#[cfg(test)] mod tests` follows (not detailed further here since it's test-only code), covering layout arithmetic, guides, pulsing, scrolling, footer truncation, mark rendering, composer behavior, hit testing, and the three modal windows.
