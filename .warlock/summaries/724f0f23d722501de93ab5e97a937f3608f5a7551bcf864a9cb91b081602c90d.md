This file implements the front-end application state for a terminal UI (a tree/panel viewer for a tool, Warlock, that manages "pacts" over directory subtrees documented by `WARLOCK.md` files). It opens with an extensive module-level doc comment laying out the design philosophy: the engine's tree is flattened into a list of rows once and kept as `all_rows`, with a filtered/derived `rows` list re-derived whenever collapse state, a "pacted-only" filter, or a "show files" toggle changes; collapsed directories are tracked by path (not row index) so they survive rebuilds; scrolling, focus (tree vs. panel), pointer-driven selection, in-flight pact progress, and an account (a running log/summary of a pact) are all covered before the code itself.

The code begins with imports from the standard library (`Cow`, `BTreeSet`, `Path`/`PathBuf`, `Instant`), from `warlock_engine` (`IntoDocument`, `NodeState`, `StateCounts`, `Tree`, `to_manifest_path`), and locally (`Account`, `Line`).

Core types defined:

- `Row`: one flattened line of the tree display, holding depth, path, an optional `WARLOCK.md` document path, state, child count, and a file/node flag, with constructors (`new`, `file`, `with_child_count`) and accessors (`has_children`, `is_file`).
- `PactToggle`: result of toggling a pact on a directory, holding the path and new pacted state (no document list, since pacting is a subtree operation performed elsewhere).
- `InFlight` (private): tracks an in-progress pact — directory path plus 1-based position/total progress counters, exposed only via `App::is_in_flight`.
- `Summarising` (private): tracks a sub-progress pass over one large file within the in-flight directory — path, part, parts — exposed only through composed message text.
- `Focus`: `Tree` (default) or `Panel`, indicating which pane keyboard/movement input targets, with `other()` and `drives_the_tree()` methods.
- `App`: the main state struct, holding `all_rows`, the derived `rows`, `collapsed`/`collapsible` path sets, `pacted_only`/`show_files` flags, selection index, scroll offset, viewport height, state counts, header, an optional message, optional in-flight/summarising progress, a pact-refused flag, focus, an optional account, panel height/offset/follow flag, and a mouse-captured flag (with a justified `clippy::struct_excessive_bools` allow).

The `impl App` block is extensive and documented, providing:

- Constructors: `from_tree` (flattens a `Tree` into rows), `from_rows` (builds from a raw row list), `with_collapsed`, `with_counts`, `with_scope` (sets header from a relative path).
- Accessors for essentially every field and derived value (header, message, rows, collapsed state, filters, counts, emptiness, selection, scroll/viewport, focus, panel state, account presence, etc.).
- Mutators: message setting, in-flight/summarising pact tracking and clearing, pact-refusal flag, a `pact_line` composer for the footer progress line (including "already running" suffix), account lifecycle (`start_account`, `account_mut`, `take_account_from`), panel/viewport sizing, mouse-capture flag, and focus toggling/setting.
- Movement methods for keyboard navigation (`select_previous/next`, page up/down, first/last) and pointer-driven navigation (`select_row`, `select_next_by`/`select_previous_by`, `scroll_panel_down`/`scroll_panel_up`), dispatched through a shared private `movement` helper based on current `Focus`.
- Private helpers: `scroll_panel_to`, `page`, `panel_page`, `rescroll`, `reflow` (rebuilds `rows`/`collapsible` from `all_rows` under the three active filters), `moved`, `forget_last_keystroke`, `label_for` (relative-path naming for messages).
- `toggle_collapsed`, `toggle_pact` (refuses file rows, returns `Option<PactToggle>`), and `set_subtree_state` (propagates a state across a subtree's rows in both `all_rows` and `rows`, updating the tally via a `count_mut` helper and subtree-membership helpers).

A free function `reseat_on` rebuilds an `App` from a freshly re-read `Tree` while preserving prior view state (selection by path with fallback to nearest surviving ancestor, collapsed set, filters, scroll, focus, message, in-flight pact, account/panel window).

A further set of free functions supports this machinery:

- `node_rows` filters out file rows, keeping only directory/node rows.
- `paint_subtree` sets a state across a whole subtree, files included.
- `in_subtree` performs prefix-based path ancestry checks (avoiding false matches like `crates-old` against `crates`).
- `drawn_rows` performs a single depth-based pass to skip descendants of collapsed nodes and simultaneously computes the "collapsible" path set (rows immediately followed by deeper rows).
- `pacted_rows` filters to pacted nodes plus their ancestors via a single reverse pass tracking a replaced (not lowered) "needed" depth threshold.
- `index_for` finds a row by exact path, falling back to the deepest drawn ancestor, or `None`.
- `scroll_offset_for` computes minimum-movement scrolling for the tree (keeps the window still when possible, clamps, moves just enough otherwise; returns 0 in degenerate cases).
- `panel_offset_for` computes analogous scrolling for the log/output panel, distinguishing "following" (tail) mode from "parked" mode since there's no selection to track.
- Message formatters: `left_on_disk_message`, `pacting_message`, `summarising_message`, `already_running_message`, `file_row_message`.
- `count_mut` maps a `NodeState` to its corresponding mutable field in `StateCounts` via an exhaustive match.

The remainder of the file is a large `#[cfg(test)] mod tests` block containing no production code. It imports test-relevant standard library and engine items along with the parent module's items and `crate::claude::Activity`/`crate::fixture`, then defines an extensive set of fixture and helper functions: constants for scroll testing (`MANY`, `WINDOW`), a `Movement` function-pointer alias, row/tree builders (`three_rows`, `rooted_rows`, `many_rows`, `whole_fixture`, `pacted_fixture`, `whole_fixture_with_files`, `tree_without_the_tui_crate`), a `tally` function that independently recomputes counts to catch drift, selection/scroll helpers (`scrolled_to`, `drawn`, `states`, `app_selecting`, `app_with_files_selecting`, `select`, `selected_path`), a `MOVEMENTS` table of the six movement methods, panel/account helpers (`panel_focused`, `at`, `app_pacting`, `panel_text`), and others.

The tests themselves exhaustively cover: tree flattening into rows (order, depth, state, document, child counts); header/scope naming rules; keyboard selection movement and its boundary behavior; scrolling (window edges, jumps, clamping, degenerate/empty cases, paging, jump-to-first/last, viewport resizing); pact toggling and un-pacting (state transitions, subtree painting, count tallying, "left on disk" messaging); in-flight pact progress line construction and transitions; collapse/expand behavior and its interaction with filters and selection; pacted-only filtering (ancestor retention, selection fallback); file-row display toggling (read-only state/document/children copied from parent directory, refusal to pact a file row); focus management (default focus, toggling, movement keys being inert on the tree when the panel is focused, focus-independence of non-movement actions); panel/account behavior (no panel content before any run, resetting and auto-following on a new account, following new lines, breaking/resuming follow on manual scroll or jump-to-end, `panel_lines_below`, zero-height panel edge cases, direct testing of `panel_offset_for`'s follow/parked windowing); pointer-driven wheel-style scrolling (equivalence to repeated key presses, clamping, focus-independence, interaction with follow mode, message preservation); `set_focus` no-op and mutation semantics; a guarantee that pointer-driven actions never mutate row structure, collapsed set, or counts; and a block of `reseat_on` tests confirming that account/panel state carries over, rows/states/tally refresh from a new tree, selection is preserved by path or falls back appropriately, collapsed sets and view flags survive, and — critically — re-seating on an unchanged tree leaves the entire `App` state byte-for-byte identical, even when the existing scroll offset differs from what a fresh top-down rebuild would produce.
