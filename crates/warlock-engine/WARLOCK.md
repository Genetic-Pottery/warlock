# warlock-engine

The core domain library crate of Warlock — the one place that owns the state vocabulary, the tree of work, the on-disk manifest, the subtree hash, the staleness decision, the loader, the model-pass seam, and the pacting operation itself. This directory is a thin crate root: `Cargo.toml` and `README.md`, with every implementation file living in the single child directory `src/`.

## What's here

- **`Cargo.toml`** declares the crate's dependencies and, in its comments, states the architectural rule directly: no TUI, terminal, HTTP, or Anthropic dependency belongs here, because the dependency edge runs TUI → engine and never back. Dependencies are `blake3`, `ignore`, `serde`, `toml`, with `serde_test` and `tempfile` as dev-dependencies only. Lints come from the workspace root, not local configuration.
- **`README.md`** is the authoritative design account of the crate — not background reading but the argued source of truth for decisions the code implements. It covers the three-state vocabulary (`Unpacted` / `PactedStale` / `PactedFresh`, deliberately with no fourth "unknown" state, because unjudged *is* stale), the pure tree shape and its file-listing-versus-children distinction, the `.warlock/pacts.toml` manifest format with its atomic write-then-rename discipline, the exact inputs and exclusions of the subtree hash (an unreadable file is a hard error, never a silent skip — a skip would hash like a deletion and could manufacture a false green), the pure `decide_state` truth table, the loader's rules for what counts as a node versus a documented module, the `Agent` seam (defined here, implemented nowhere in this crate — implementing it means spawning `claude` as a subprocess, which belongs to the binary on the far side), and the pact operation, which is the only code path in the crate that ever grants a `granted_hash`.

## How it fits together

All implementation lives in `src/`, which documents itself: `lib.rs` is the module index and re-export surface, whose doc comments are the precise current description of every public item. `state.rs` holds the closed three-state enum. `tree.rs` is the pure tree shape, plus loader-set `ignored` and `scope` fields on each node. `manifest.rs` is the on-disk manifest and its write-temp-then-rename idiom. `hash.rs` is the subtree hash. `ignores.rs` handles `.warlockignore`. `decide.rs` is the pure staleness decision. `load.rs` is the real-directory loader. `agent.rs` is the model-pass seam, defined but deliberately not implemented. `pact.rs` (large, and only known here from a prior summary rather than a full read) does the actual pacting work. `scope.rs` and `sigils.rs` supply the scope/sigil vocabulary — judged but not enforced anywhere in this crate. `claude_md.rs` maintains a delimited, splice-in-place block inside `CLAUDE.md`. `clock.rs` is a dependency-free RFC 3339 timestamp helper.

## What a reader has to know before changing anything

- **The dependency direction is architecture, not convention.** No terminal, TUI, or subprocess-spawning dependency belongs here, even transitively, even for a test — the crate must stay usable headless. `Cargo.toml`'s comment on this is a constraint, not a suggestion.
- **This crate commits to exactly one on-disk format: the manifest.** `Tree`/`Node` derive serde for a caller's convenience but commit to no format of their own.
- **The three-state model and the never-skip-a-hash-failure rule are closed design decisions**, argued at length in `README.md` and restated in `src`'s own document. Treat a proposal to add a fourth state, or to tolerate a silently-skipped unreadable file, as a design regression, not a simplification.
- **Freshness is granted in exactly one place** — inside the pact/refresh path in `src/pact.rs`, after every document in a subtree has been written. There is currently no other way back to green; a stale subtree can only be re-pacted from scratch.
- **Nothing in this crate enforces a scope boundary.** `scope.rs` and `sigils.rs` only say what a valid scope or sigil string looks like and what a person holds; nothing here checks a sigil against a scope and blocks or refuses anything. `claude_md.rs`'s generated text says so explicitly, and a test pins that promise — don't let a future change quietly turn scope into enforcement without updating that.
- **Read `README.md` before `src/lib.rs`'s doc comments, not instead of them.** The README explains why the crate is shaped this way; the source doc comments are the precise, current what.
- **`src/pact.rs` was too large to read in full for this document.** What's said about it here comes from a prior summary, not from its own text — open it directly before relying on any specifics beyond what's already documented.

This directory is pacted, and per project convention the code is authoritative wherever it and this document disagree — note the gap rather than trusting either side silently.
