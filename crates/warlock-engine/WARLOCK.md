# warlock-engine

The core domain library crate of Warlock. This directory is the crate root — packaging and top-level document only — with every line of implementation living in the single child directory `src/`. It owns the state vocabulary, the tree of work, the on-disk manifest, the briefs setting, the subtree hash and the staleness decision it feeds, the ignore vocabulary, the loader that colours a real directory, the seam a model pass runs through, the pact operation that writes documents and grants freshness, and the scope/sigil vocabulary a caller judges a boundary with.

## What's here

- **`Cargo.toml`** (912 bytes) — the dependency list: `blake3`, `ignore`, `serde` (with the `derive` feature), `toml` as regular dependencies; `serde_test` and `tempfile` as dev-dependencies only, the former to round-trip `Node`/`Tree` through serde's own token stream independent of any on-disk format, the latter to give manifest tests a throwaway directory. Its own comments state the rule the crate is built around: no TUI, terminal, HTTP, or Anthropic dependency belongs here, because the dependency edge runs TUI → engine and never back. Lints come from `[lints] workspace = true` rather than being set per-crate, and `version`/`edition`/`rust-version`/`license`/`repository` are all `.workspace = true` rather than restated here.

- **`README.md`** (~30.7KB) — a long, argued design document explaining why the crate is shaped the way it is: the three-state model and why there is deliberately no fourth "unknown" state, the tree's files-vs-children distinction, the manifest's on-disk format and atomic-write discipline, the subtree hash's exact inputs and deliberate exclusions, why an unreadable file is a hard error rather than a silent skip, the `decide_state` truth table, the loader's rules for nodes vs. documented modules, the `Agent` seam (defined here, implemented nowhere in this crate), and the pact operation as (in the README's telling) the sole place a `granted_hash` is ever written.

  The README predates most of what `src/`'s own document now reports: it does not mention `briefs.rs`, `ignores.rs`, `scope.rs`, `sigils.rs`, `claude_md.rs`, `clock.rs`, `fitting.rs`, or `languages.rs` at all, and its account of the loader (files pruned when `.warlockignore`d, no `Node::scope`) is superseded by `src/`'s document, which reports that `load.rs` *keeps* `.warlockignore`d directories and marks them via `Node::ignored`, and that `Node` carries its own `scope` field. Where the two disagree, treat `src/`'s document — and, underneath that, the source files it names — as current; read the README for the argument behind the closed decisions (three states, hard-fail on an unreadable file, TOML manifest as an escape hatch), not for the present shape of the module list.

## How it fits together

All implementation is under `src/`, which is flat — seventeen files, no subdirectories — and documents itself starting from `lib.rs`'s module list and re-exports. Per `src/`'s own document, the dependency shape inside it runs roughly bottom-up: `state.rs` and `tree.rs` are pure data shapes with no filesystem access; `manifest.rs`, `hash.rs`, `ignores.rs` and `clock.rs` are low-level I/O and hashing primitives; `decide.rs` combines a manifest entry with a hash into a `NodeState`; `load.rs` uses all of that to build a `Tree` for display, reporting non-fatal failures as `Problem`s (called `LoadProblem` in the README, `Problem` in `src/`'s document — the source, not sent here, settles the current name). Separately, `languages.rs` and `fitting.rs` build the request sent to a model through `agent.rs`'s `Agent`/`Request` seam, and `pact.rs` sits at the top of that stack, driving `fitting::fit`, calling `Agent::run`, writing `WARLOCK.md`, and updating the manifest via `hash.rs`/`decide.rs`. `scope.rs` and `sigils.rs` are a largely independent pair — repository-side boundary versus machine-side key — that `pact.rs` and `load.rs` both consult but neither enforces on its own; `briefs.rs` and `claude_md.rs` are self-contained single-file features outside the pact/hash/tree machinery entirely.

The shape worth carrying up to this level: a hash is the mechanical trigger, a model pass is the judgement, a human can always read and hand-edit the result, and scopes/sigils are a second, independent vocabulary that this crate defines and judges — matching a held sigil against a scope via `scope_opens_to` in `scope.rs` — while the refusal that follows an unfavourable answer belongs to the caller, never to this crate. `src/`'s document is explicit that `pact.rs`'s `closed_scopes_at_or_below` *reports* which scopes a set of held sigils doesn't open and enforces nothing itself.

## What a reader has to know before changing anything

- **The dependency edge runs TUI → engine, never back.** No terminal, TUI, or subprocess-spawning dependency belongs here, even transitively or in a test — this crate must stay usable headless, and `Cargo.toml`'s comments say so explicitly, and `lib.rs` restates it (per `src/`'s document).
- **The manifest (`.warlock/pacts.toml`) is the one on-disk format this crate commits to.** `Node`/`Tree` derive serde for a caller's convenience but commit to no format of their own; the round-trip proof for that lives in `serde_test`, listed as a dev-dependency in `Cargo.toml`.
- **The three-state model and the never-silently-skip-a-hash-failure rule are closed design decisions**, argued at length in `README.md` and reaffirmed by `src/`'s document (`state.rs`'s `NodeState`, `hash.rs`'s `Error::Read`). Treat a proposal to add a fourth state, or to tolerate a silently-skipped unreadable file, as a design regression rather than a simplification.
- **Freshness is granted inside `pact.rs`'s `pact_subtree`** (per `src/`'s document), after documents in a subtree are written, hashing and granting per directory rather than per file — `refresh_subtree` narrows first to whatever `decide_state` finds stale. Check this against `pact.rs` itself before relying on the exact mechanics, since that file was summarised rather than sent whole to the pass that wrote `src/`'s document, and is by far the largest file in this crate (327,383 bytes, per `src/`'s listing).
- **This crate judges a scope boundary; it never refuses one.** `scope.rs` validates a scope or sigil string and judges the match (`scope_covering`, `scope_opens_to`); `pact.rs`'s `closed_scopes_at_or_below` asks that question of everything under a target — but nothing in this crate blocks or refuses on the answer. The refusal is left entirely to a caller.
- **A previous document is a claim, not evidence.** `agent.rs`'s `Request` (per `src/`'s document) carries a directory's prior `WARLOCK.md` in a slot kept separate from its files, so a pass is told to check an old claim against the files rather than trust it — the same posture this document itself asks a reader to take toward the README above.
- **Sigils and scopes never cross territory.** Per `src/`'s document, `sigils.rs` stores sigils under the caller's home directory (`<home>/.warlock/<project>/config.toml`), never inside the repository; `scope.rs`'s scopes are repo-committed, stored in the manifest, never outside one.
- **Read `README.md` for the argument, `src/`'s document and the source for the current what.** The README is accurate about the decisions it argues for (three states, TOML as escape hatch, hash inputs and exclusions) but out of date about the module list and some of the loader's and tree's current fields; `src/`'s own document, and the seventeen files it names one by one, are the place to check anything before relying on it.
