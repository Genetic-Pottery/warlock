## Structure

- lib.rs — crate root: declares the engine's modules and re-exports their public types and functions as the single public API surface
- load.rs — load_tree walks the repo from a working dir, builds the Tree/Node graph against the Manifest, hashing subtrees and reporting Problem/Error for stale hashes or bad scopes
- tree.rs — Node and Tree: the ledger's directory node (path, document, state, scope, children, files) and depth-first Tree::walk, find, counts via StateCounts
- decide.rs — decide_state() compares a PactEntry's granted hash against a computed hash, returning NodeState::Unpacted, PactedFresh, or PactedStale.
- pact.rs — pact_subtree, refresh_subtree and pact_directory walk, describe, grant and record directories into the manifest, emitting Event/Pacting, Pacted, Repaired and Failure/Error outcomes.
- fitting.rs — Snapshot takes a directory walk and assembles/fills per-file lines and synthesis via Pacting agents, caching unchanged lines by hash
- document.rs — Fills, checks, mends and renders .warlock.md's Fill/Entry schema (purpose, files, directories, structure) via Slot/Defect, Evidence and fallback text.
- fill.rs — Generic validation/repair for schema-filled JSON answers: Defect, Accepted, settle (reask loop), mend (auto-rewrite), parse, line, fit helpers
- route.rs — resolve_route()/route_facts() combine scope, manifest ScopeRecord, bound key and sigil state into a Route or RouteFacts, erroring via Error::{Unscoped,Unrecorded,Unbound,Dangling,Path,Sigils,Keys}.
- filing.rs — resolve_filing() matches held sigils against manifest `[[scope]]` records to pick a Target/Destination for filing, with Error variants for boardless, unsigiled, unmatched, unrecorded, several or unknown scopes
- drafting.rs — Draft fill schema: Draft/Fill types, check/mend/plan logic, DRAFTING_PROMPT and drafting_instructions() that cut one brief slice into DRAFTS_PER_SLICE tickets.
- splitting.rs — Fill schema and mend logic cutting a ticket into ordered Subtask entries (goal, depends_on, definition_of_done, likely_files, test_plan, notes); number() topologically orders and IDs them, split_instructions() builds the split prompt.
