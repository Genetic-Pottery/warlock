# src

The warlock-engine crate root: the freshness-tracking engine that walks a repo tree, builds and validates .warlock.md directory documents, hashes and pacts directories, resolves scopes and sigils, and drives drafting, splitting and pull-run state for sub-tasks.

## Structure

- lib.rs — crate root: declares the engine's modules and re-exports their public types and functions as the single public API surface
- load.rs — Builds a Tree by walking the repo from a start dir to its root, pairing each directory with manifest state via load_tree, state_of and scope_of, and collecting Problems.
- pact.rs — pact_subtree/refresh_subtree drive directory describing, carry/line-hash reuse, grant and manifest rewrite; Pacted, PactedSubtree, Event, Pacting, Failure, Error, Refusal, Repaired types.
- document.rs — Defines Fill, Entry, Expected, Evidence and Described plus prompts/validation/render/mend logic that builds and repairs .warlock.md directory documents from model answers.
- fill.rs — Validates and repairs LLM JSON fills: Defect enum, accept/settle (Reask::Any/Cut retry policy), Schema trait, and mend() for defect auto-rewrite.
- fitting.rs — Snapshot takes a directory walk and builds per-file/synthesis agent requests; Assembled/Synthesised carry results, Problem/Omission report too-large or unreadable files, PER_FILE_BYTE_CAP=1MiB.
- walk.rs — Filesystem walking honouring ignores: subtree_files, pactable_directories, and own() collecting a directory's files and child .warlock.md documents.
- route.rs — resolve_route and route_facts resolve a path to its covering Scope, ScopeRecord, bound key and open posture, returning Route or RouteFacts; Error covers unscoped, unrecorded, unbound and dangling-key cases.
- filing.rs — resolve_filing picks a held-sigil-matched ScopeRecord and bound key to build a Target/Destination, or an Error naming why filing failed
- drafting.rs — Fill/Draft schema and mending for cutting one brief slice into tickets: Draft{title,body,blocked_by,blocks}, check(), mend(), drafting_instructions(), stub_answer().
- splitting.rs — Defines the ticket-splitting Fill schema (Subtask with goal/depends_on/definition_of_done/likely_files/test_plan/notes), its check/mend logic, number() ordering subtasks via topological sort with Cycle detection, SPLIT_PROMPT, and stub_answer().
- pulls.rs — PullRun and PullSubtask state for a pull run, with RunStatus/SubtaskStatus, JSON state.json persistence, manifest.md and brief rendering, and held_runs/resume for recovery.
