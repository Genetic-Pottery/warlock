# src

This is `warlock-engine`'s source directory: the crate's `lib.rs` and every module it declares. It is a library only — no `main.rs`, no binary target — and it is deliberately inert with respect to the outside world in one specific sense that recurs across every file here: it opens no sockets and spawns no subprocesses. `lib.rs` states this explicitly, and `agent.rs` is the seam that keeps it true even though a pact is written by a model — the trait is defined here, the subprocess that actually runs `claude` lives in a binary crate elsewhere.

The directory has no subdirectories of its own to summarise; everything below is flat, seventeen files.

## What is here, file by file

**`lib.rs`** (15,800 bytes) — the crate root. Declares every module (`agent`, `briefs`, `claude_md`, `clock`, `decide`, `fitting`, `hash`, `ignores` and `languages` as private, `load`, `manifest`, `pact`, `scope`, `sigils`, `state`, `tree` as public) and re-exports the public surface with one doc comment per item, so this file alone is close to an index of the whole crate's API. It states the crate's two non-negotiable properties: the TUI depends on the engine and never the reverse, and the engine touches the filesystem (manifest, tree walk, hashing) but never the network or a subprocess.

**`agent.rs`** (48,596 bytes) — the port through which the engine reaches a model without ever running one itself. Defines the `Agent` trait (one method, `run`, plus `context_tokens` with a default of `DEFAULT_CONTEXT_TOKENS` = 128,000), `Request` (a prompt, a directory, the directory's own `File`s, its children's `WARLOCK.md` documents as `ChildDocument`, and its own previous document, kept in a *separate* field from `files` rather than as one of them — the doc comment explains this at length: a file is evidence, a previous document is a claim, and conflating them let a false claim survive indefinitely across passes), `File` (present/omitted/elided/summarised — four states, reached through `File::present`, `File::omitted`, `File::elided`, `File::summarised`), `Response`, and `Error` (`NotFound`, `Failed`, `EmptyOutput`, `TimedOut`, `Io`). No process type — no `ExitStatus` — crosses this seam; `Error::Failed` carries a plain exit code and stderr string instead.

**`briefs.rs`** (21,752 bytes) — reads `.warlock/briefs.toml`, the one setting for where a repository wants prose briefs written. `briefs_path` locates the file beside the manifest; `load_briefs` returns the configured directory or `DEFAULT_BRIEF_DIRECTORY` ("docs") if the file or key is absent — absence is the default, not an error, but malformed content (`Error::Syntax`), an absolute path (`Error::AbsoluteDirectory`), or a `..` component (`Error::ParentDirectory`) are refused loudly. `check_relative` does the path-shape check by walking `Component`s, with no canonicalisation. This module only reads; it never creates the brief directory or writes anything.

**`claude_md.rs`** (44,982 bytes) — writes `<root>/CLAUDE.md`, the orientation file for an agent that wanders into a warlock-managed repository. Owns only a delimited block inside that file (`BEGIN`/`END` HTML-comment markers), never the whole file: `splice` finds and replaces the block in place, or appends it if absent, leaving every byte outside the markers untouched, which is what makes a second `warlock init` a byte-identical no-op. `BODY` is the fixed text (what warlock is, the three colours, what editing a document costs, scopes and sigils). `write_claude_md` does the actual write via the crate's one write idiom (temp file + `write_and_sync` + rename, borrowed from `manifest.rs`'s `temp_file_name`/`write_and_sync`), returning `Written::Created` or `Written::Updated`. `Error` covers `Read`, `NotText`, and `Write`. This module writes exactly one file and nothing else — no manifest, no pact, no model call.

**`clock.rs`** (15,763 bytes) — hand-rolled RFC 3339 UTC timestamp generation, with no date/time dependency. `now_rfc3339` is the public entry point (total and infallible, even for a pre-epoch clock); `rfc3339_from_unix_seconds` and `civil_from_days` (Howard Hinnant's algorithm) do the calendar arithmetic. Used solely to stamp `granted_at` on a `PactEntry` grant; nothing anywhere parses the string back.

**`decide.rs`** (11,206 bytes) — the staleness verdict itself, `decide_state(entry: Option<&PactEntry>, computed_hash: &str) -> NodeState`. Pure and total: no manifest entry is `Unpacted`; an entry with no grant, or a grant whose hash doesn't match, is `PactedStale`; a matching grant is `PactedFresh`. The doc comment is explicit that "never judged" and "judged against something else" are deliberately the same answer — there is no fourth "unknown" state. This is the one function that combines what `hash.rs` computes with what `manifest.rs` stored.

**`fitting.rs`** (184,049 bytes, summarised only — its contents were not sent whole) — per the summary: builds a `Request` for one directory within a model's context budget. Gathers the directory's own files (minus its own `WARLOCK.md`), immediate children's `WARLOCK.md`s, and the directory's previous document; degrades oversized files through a three-rung ladder (whole → elided/summarised via a map-reduce prompt pass → name-and-size only) governed by a per-file byte cap (`PER_FILE_BYTE_CAP`, 1 MiB) and a whole-request cap derived from the agent's context window. Summaries are cached on disk under `.warlock/summaries/`, keyed by content hash. Exposes `fit`, `Fitted`, `Gathered`, `Problem`/`Omission` (re-exported from `lib.rs` as `Omission`, `Problem`). Since this file's contents were summarised rather than sent, treat specifics of its internal function names as reported rather than directly checked here.

**`hash.rs`** (31,946 bytes) — `subtree_hash(dir) -> Result<String, Error>`, the mechanical trigger half of the freshness model. Blake3-based (domain-separated via `HASH_CONTEXT`), walking with the `ignore` crate under the same rules as `load.rs` (`.gitignore`, `.warlockignore` via `ignores::is_ignored` and `files_under`, `.warlock/` pruned, no symlink following), hashing sorted relative-path-then-bytes pairs so two clones at different absolute paths agree. An unreadable file is a hard `Error::Read`, never silently skipped — skipping it would hash exactly like deleting it, which could produce a false-fresh result.

**`ignores.rs`** (5,278 bytes) — everything to do with `.warlockignore`, gitignore-syntax exclusions honored via the `ignore` crate's `add_custom_ignore_filename`. Exposes `FILENAME` (the constant `".warlockignore"`, crate-private) and `is_ignored(path) -> Result<bool, ignore::Error>` (crate-private), which answers whether a directory is itself excluded by rules above it — needed because a walker never applies its own rules to the root it's given, so a directory selected directly (by manifest entry or keypress) needs this separate one-deep-walk-of-the-parent check (`walk_one_deep`).

**`languages.rs`** (24,185 bytes) — the per-language table behind `fitting.rs`'s elision rung: which bytes of a source file (test bodies) a documenter doesn't need. `Language` rows live in a static `TABLE`, found by extension via `language_of`; each row says where tests live (`test_suffixes`/`test_prefixes` for file-per-test languages like Go/Python, or `blocks: &[Block]` for inline ones like Rust's `#[cfg(test)] mod tests` and Zig's `test "..." { }`) and what a kept declaration line looks like (`declarations`). Currently covers Rust, Zig, Go, TS/JS, Python, Ruby, Java/Kotlin/C#/Swift, and Elixir. `elide(path, text) -> Option<Elided>` is the entry point; an unrecognised extension or an unterminated block returns `None` rather than guessing — delimiters are matched at column zero rather than by real parsing, which is a stated, deliberate limitation. This is the module that produces the `File::elided` variant's `kept` text used elsewhere (`agent.rs`, `pact.rs`).

**`load.rs`** (74,320 bytes) — builds a `Tree` from a real directory: `load_tree(working_dir) -> Result<Loaded, Error>`. `Loaded` bundles the coloured `Tree` with non-fatal `problems: Vec<Problem>` (each a `ProblemCause::Hash` or `ProblemCause::Scope`). `repository_root` walks upward for the nearest `.git/`; the manifest is read from there while the tree is rooted at `working_dir` itself — there is no privileged root. Every directory the walk (`walk`, `builder`) reaches becomes a `Node` whether or not it holds a `WARLOCK.md`; files ride along on their directory via `Node::files`. `.warlockignore`'d directories are *not* pruned here (unlike every other consumer of the rule) — they keep their row and are instead marked via `Node::ignored` (`mark_excluded`), specifically so a reader can see what warlock is choosing not to cover. `Builder::state_of` and `Builder::scope_of` do the per-node colouring and scope lookup, reporting failures into `problems` rather than failing the whole load.

**`manifest.rs`** (63,300 bytes) — the in-memory shape of `.warlock/pacts.toml` and its I/O. `Manifest` (a `version` plus ordered `Vec<PactEntry>`) with `Manifest::load`/`Manifest::save` (atomic write via `temp_file_name` + `write_and_sync` + `fs::rename`, the idiom `claude_md.rs` reuses), `to_toml_string`/`from_toml_str`. `PactEntry` holds `module`, `document`, optional `scope`, optional `granted_hash`/`granted_at` — all private, reached via constructors (`PactEntry::new`, crate-private `PactEntry::stored`) and builders (`with_grant`, `without_grant`, `with_scope`, `without_scope`) and the crate-private `overwrite_run_fields`, which is written to touch only the fields a pact *run* owns, deliberately leaving `scope` (a person's field) untouched by any automated run. Also hosts `to_manifest_path`/`from_manifest_path` (the relative, forward-slash, `"."`-for-root path convention every other module in this crate relies on), `manifest_path`, and the shared `temp_file_name`/`write_and_sync` helpers. `SCHEMA_VERSION` = 1, checked before any entry is parsed.

**`pact.rs`** (326,604 bytes, summarised only — its contents were not sent whole) — per the summary, the largest file in this directory by a wide margin, and the operational core: `pact_directory` (one directory: gather via `fitting`, run one `Agent` pass, write `WARLOCK.md` atomically, minimum-length check via `MINIMUM_DOCUMENT_BYTES`), `pact_subtree` (children-first document pass, then a second hash-and-grant phase), `refresh_subtree` (same machinery restricted to directories `decide_state`/`is_fresh` calls stale, re-exported as `refresh_subtree`), and `unpact_subtree` (manifest-only removal, deliberately never touching files on disk, dropping any scope along with the entry). Also hosts the `Observer` trait for progress/cancellation (`Pacting::Continue`/`Stop`), `closed_scopes_at_or_below`, and `view_file`/`Viewed`/`Unviewable` for reading a file capped at `PER_FILE_BYTE_CAP` without pacting anything. Holds the full fixed `PROMPT` text sent to the model. Because this file arrived as a summary, its internal function names above should be treated as reported by an earlier pass, not independently confirmed here — check `pact.rs` directly for anything load-bearing.

**`scope.rs`** (36,980 bytes) — what a scope string may be, and the two questions built on that: `validate_scope` (1–24 chars, ASCII lowercase/digit/`-`/`_`, must start with a letter, must not end with a separator; returns `Result<(), Rule>` with one named `Rule` variant per failure) and `validate_sigil` (everything `validate_scope` accepts, plus the wildcard `*`, refused as a scope but accepted as a sigil — the asymmetry is argued at length in the module doc). `scope_covering(path, root, manifest)` walks a path's manifest-relative ancestors (`at_or_above`, segment-wise not textual) to find the nearest directory carrying a *valid* scope, stepping over invalid ones (`valid_scope_on`, `valid_scope`) rather than erroring. `scope_opens_to(covering, held)` is the separate membership test — any one held sigil (or the wildcard) opens a scope; an unscoped directory is open to anyone; holding zero sigils opens nothing scoped. This module judges and answers only; it never refuses anything itself — callers do that.

**`sigils.rs`** (32,931 bytes) — the machine-local counterpart to `scope.rs`: sigils held by an operator, stored at `<home>/.warlock/<project>/config.toml`, never inside the repository. `project_directory(root)` derives a directory name from the canonicalised repo path (readable name + 16 hex chars of a blake3 digest, domain-separated via `PROJECT_CONTEXT`), so two checkouts of the same repository get separate sigil stores. `sigils_path`, `load_sigils` (missing file is `Error::NotFound`, not an empty set — same absent-vs-empty distinction as `Manifest::load`), `save_sigils` (atomic write, same idiom as `manifest.rs`). Home directory is always a caller-supplied parameter; nothing here reads `HOME` from the environment.

**`state.rs`** (3,943 bytes) — the three-state vocabulary itself: `NodeState` enum (`Unpacted`, `PactedStale`, `PactedFresh`), `NodeState::ALL` for exhaustive iteration, and `NodeState::is_pacted`. Deliberately no fourth "unknown" variant — the smallest file in this directory, and purely declarative.

**`tree.rs`** (35,718 bytes) — the tree's shape, decoupled from how it's built (`load.rs` builds it; this just defines it). `Node` (`path`, `document`, `state`, `ignored`, `scope`, `children`, `files` — all public fields, no protected invariant), built via `Node::new` plus builders `with_children`/`with_files`/`with_ignored`/`with_scope`; `IntoDocument` lets `Node::new` accept a path, `Option<PathBuf>`, `&str`, etc. uniformly. `Tree` (owns a root `Node`) with `walk` (`DepthFirst` iterator, parents before children), `counts` (`StateCounts`, one field per `NodeState` so no state can be missed), and `find`. Both `Node.scope` and `Node.ignored` are stated explicitly to be this node's *own* fact, never inherited — the different question of which scope covers a path from above is `scope.rs`'s `scope_covering`.

## How the pieces fit together

Read top-down, the dependency shape is: `state.rs` and `tree.rs` define the vocabulary and shape with no logic in them; `manifest.rs` and `hash.rs`/`ignores.rs` independently produce the two inputs `decide.rs`'s `decide_state` compares to yield a `NodeState`; `load.rs` drives all four of those to build a live `Tree` from a real directory, reporting non-fatal failures as `Problem`s rather than aborting. `scope.rs` and `sigils.rs` are a matched pair on either side of the repository boundary — scopes committed in the manifest, sigils held per-machine outside it — joined only by the membership test `scope_opens_to`; neither module enforces anything, they only answer.

Separately, `agent.rs` defines the model-calling seam that `fitting.rs` (gathering and budget-fitting a request) and `languages.rs` (elision policy, one ingredient `fitting.rs` uses) feed into, and `pact.rs` is where all of that comes together into the actual write-a-document and grant-a-hash operations, which is also where `clock.rs`'s timestamps and `manifest.rs`'s `PactEntry::with_grant` get used. `briefs.rs` and `claude_md.rs` are smaller, standalone scaffolding features (where a repository wants prose written, and what orientation gets left in `CLAUDE.md`) that read or write beside the manifest without touching pacting itself.

Because `fitting.rs` and `pact.rs` — the two largest files here by a wide margin — arrived only as summaries rather than full text, anyone changing budget behavior, the elision/summarisation ladder, or any of the pact/refresh/unpact operations should open those two files directly before relying on the descriptions above.
