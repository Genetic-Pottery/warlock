# src

The warlock-engine crate's core: models the repo as a Tree of pacted/unpacted modules, hashes and views files, drives agents to fill and validate WARLOCK.md content, and enforces scope/sigil boundaries for pulls, drafting and splitting.

## Structure

- lib.rs: Crate root declaring engine submodules and re-exporting Agent, decide_state, load_tree, Manifest, pulls, Route, Tree.
- load.rs builds the module Tree by walking the repo and reading the pact manifest via load_tree.
- tree.rs defines the Node and Tree types that load.rs populates and pact.rs/route.rs walk.
- decide.rs's decide_state maps a manifest PactEntry plus a computed hash to the state.rs NodeState enum.
- hash.rs computes subtree_hash, file_hash and line_hash, which decide.rs and pact.rs consume for freshness checks.
- pact.rs pacts and refreshes subtrees into manifest.rs PactEntry grants using hash.rs and walk.rs.
- manifest.rs persists Manifest, PactEntry and ScopeRecord to pacts.toml, read by route.rs and filing.rs.
- route.rs resolves a path to a Route using manifest.rs ScopeRecord data and scope.rs's scope_opens_to.
- filing.rs's resolve_filing picks a ScopeRecord for a held sigil, using sigils.rs's held_sigils.
- fitting.rs builds directory requests and drives agent.rs's Agent to produce document.rs's Fill and Described content.
- document.rs's render/mend build WARLOCK.md content from Fill, validated against Expected and Evidence.
- pulls.rs's PullRun and PullSubtask drive drafting.rs, splitting.rs and working.rs through an agent-run pull.
