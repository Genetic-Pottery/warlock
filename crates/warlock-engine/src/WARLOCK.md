# src

This is `warlock-engine`'s source directory: the whole domain crate, flat, with no subdirectories of its own. It has no dependency on the TUI or on any terminal library — the dependency edge runs TUI → engine, never back — and nothing here opens a socket or spawns a process. What it does do is read and write `.warlock/pacts.toml`, walk directories, hash files, and shape a request to send to a model.

Read `lib.rs` first. It is the module list and the re-export surface, and its doc comments are the authoritative one-line description of every public item — treat it as the index, not as boilerplate to skip past.

## How the pieces fit

The design this crate implements: a hash is the mechanical trigger, a model pass is the judgement, and a human can always read and hand-edit the result. Scopes and sigils are a second, independent vocabulary layered on top: a scope is a repo-committed fact about a directory, a sigil is a machine-local fact about a person, and nothing in this workspace yet matches one against the other.

- **`state.rs`** — the three-value vocabulary (`Unpacted` / `PactedStale` / `PactedFresh`). No fourth "unknown" state exists anywhere in the crate; unjudged *is* stale.
- **`tree.rs`** — pure shape: `Tree`, `Node`, depth-first walking, state tallying. A node also carries a stored, loader-set `ignored` flag (repository-excluded content is still shown, gray, with a reason), a stored `scope` (this directory's own, never an inherited one), and a `files` listing that is never hashed and never counts as a child.
- **`manifest.rs`** — the on-disk record, `.warlock/pacts.toml`: one `PactEntry` per pacted module, holding a directory, its document path, an optional scope, and an optional granted hash + timestamp. Paths are stored root-relative with forward slashes so two clones at different absolute paths (or on different OSes) produce byte-identical files. A stored scope is preserved exactly as written — never validated or normalized here, so that belongs to `scope.rs`. An absent grant is represented by an absent key, never a sentinel. Owns the one write idiom used everywhere else too: temp file in the same directory, synced, then renamed over the target.
- **`hash.rs`** — `subtree_hash`: one digest over every file at and below a directory (sorted relative paths, `.gitignore`/`.warlockignore`/`.warlock/`/symlinks excluded the same way everywhere), used as the trigger for staleness. An unreadable file is a hard error here, never a skip, because skipping would hash exactly like a deletion and could manufacture a false-fresh result. A directory the repository excludes hashes as an empty one, even if selected directly.
- **`ignores.rs`** — `.warlockignore`: ordinary gitignore syntax, read via the `ignore` crate at every level, giving repository authors a way to keep content (notebooks, image folders) out of both the walk and the hash without touching git. Also answers the one question a walk can't ask of its own root: "is *this* directory itself excluded?"
- **`decide.rs`** — `decide_state`: the small pure function combining a `PactEntry` (or its absence) with a freshly computed hash into one of the three states. The only place the four-row truth table is spelled out; two of those rows collapse into "never judged and judged-against-something-else are the same answer: stale."
- **`load.rs`** (summarised) — `load_tree`: builds a real `Tree` from a real directory, rooted wherever it's invoked, while finding the manifest by walking upward to the nearest `.git/`. Every directory reached by the walk becomes a node, documented or not; a missing manifest means "never pacted," not an error. Hash failures and invalid stored scopes during load are non-fatal, downgraded to a recorded `Problem` rather than a load failure.
- **`agent.rs`** — the seam to a model. Defines the `Agent` trait, `Request`/`Response`, and the file vocabulary (`present` / `omitted` / `summarised`) but implements nothing: running `claude` as a subprocess is the binary's job. This split is what lets every test here run with a hand-written fake and no network, no terminal, no `claude` binary. `Error` deliberately carries no process type across the seam (exit code as `Option<i32>`, stderr as `String`), and has a distinct vocabulary for "not found" vs "refused" vs "empty" vs "timed out."
- **`pact.rs`** (very large; summarised, not fully read) — the actual work of pacting: gathering a directory's request, demoting oversized files through a sent → summarised → listed-only ladder under two byte caps (per-file, then whole-request), running one agent pass, writing `WARLOCK.md` atomically, and — for a whole subtree — writing children before parents and only then hashing and granting. A disk-backed, content-keyed summary cache under `.warlock/summaries/` avoids re-summarising unchanged oversized files. Also handles refreshing (redescribe only stale directories, preserving scopes and untouched entries) and un-pacting (dropping manifest entries — and with them their scopes — without touching files on disk; the only operation that can lose a scope). Because this file was too large to read in full, its behavior here is described from a prior summary, not from its own text — don't quote from that summary as if it were the file's actual prose or code.
- **`scope.rs`** — the one place in the workspace that judges whether a string is a valid scope (`validate_scope`) or sigil (`validate_sigil`, everything a scope accepts plus the wildcard `*`). Judges only, never normalizes or folds case — that's the caller's job, done before this is asked. Also `scope_covering`: the nearest valid scope at or above a path, segment-wise (not textual-prefix) and stepping straight over any invalid scope as if it weren't written. Nothing here matches a scope against a sigil; that enforcement doesn't exist anywhere in this workspace yet.
- **`sigils.rs`** — the other half of the scope/sigil split: machine-local sigils read from and written to `<home>/.warlock/<project>/config.toml`, never inside the repository. The home directory is always a caller-supplied parameter, never read from `HOME`. `project_directory` derives a per-checkout directory name from a hashed canonical path, so two clones of the same repo hold sigils separately. A missing config file is `Error::NotFound`, distinct from an empty set. Stores strings unvalidated, exactly as `manifest.rs` does for scopes.
- **`claude_md.rs`** — writes `<root>/CLAUDE.md` (not `AGENTS.md`; deliberately renamed because `CLAUDE.md` is loaded automatically by Claude Code sessions and `AGENTS.md` is not): a delimited, splice-in-place block (`<!-- warlock:begin -->` … `<!-- warlock:end -->`) covering what warlock is, the three colours, and — as of this pass — scopes and sigils too, ending with the instruction to check scope boundaries before touching anything and to say plainly, never block, when work crosses one the operator doesn't hold. Everything outside the markers is somebody else's text and is preserved byte for byte; running it twice is a no-op on the bytes; an unterminated block (interrupted mid-write) is re-ended rather than doubled. It writes exactly this one file — no manifest, no `.warlockignore`, no document, no model pass — because `warlock init` must not silently enrol a repository in anything. Deliberately carries no guidance on *writing* a `WARLOCK.md`, because a pacting pass runs headless and never reads this file; that guidance lives only in `pact.rs`'s prompts.
- **`clock.rs`** — `now_rfc3339`: a hand-rolled, dependency-free RFC 3339 UTC timestamp generator, used only for the `granted_at` field. Exists to avoid pulling in a date/time crate for something nothing else in the workspace parses back; a pre-epoch clock produces a pre-epoch timestamp rather than panicking or lying.

## Before changing anything here

- **The state model is closed by design.** Don't add a fourth state or an "unknown" variant — unjudged-and-stale is the point, not a gap to fill.
- **Freshness is granted in exactly one place**: inside `pact_subtree` (and `refresh_subtree`, which shares the same core), after every document in a subtree has been written. Nothing else writes a `granted_hash`, and a stale directory stays stale until repacted or refreshed.
- **Hashing must never skip an unreadable file.** If you touch `hash.rs`, preserve the "error, not silent omission" behavior; it's what prevents a false-green.
- **The `Agent` seam must stay process-free.** `agent.rs` and everything upstream of it (tests included) must never need a real `claude` binary, network, or terminal. If tempted to add such a dependency to a test, use the fake pattern already established instead.
- **Manifest paths are always root-relative, forward-slash, portable.** Any path handling added elsewhere in this crate should go through `to_manifest_path`/`from_manifest_path` rather than reinventing normalization.
- **A file too large to send is described, never truncated.** The ladder in `pact.rs` (whole → summarised → name-and-size) is the only vocabulary for "this content didn't make it into the request." A summary is prose *about* a file, never a substitute for its bytes, and `File::bytes()` must keep answering `None` for it.
- **`.warlockignore` is real content, not metadata.** It's read like any other ignore file (nested, negatable, anchorable) but it is *also* an ordinary hashed file itself, so editing the rules restales twice over — deliberately.
- **`CLAUDE.md` is owned in part, not in whole.** `claude_md.rs` may only ever touch the text between its own markers; an unterminated block (a save interrupted mid-write) must be re-ended, never doubled.
- **A scope is judged, never normalized, at the point it is stored.** `scope.rs` only says yes or no; case-folding and trimming belong strictly to whatever UI takes the string from a person, before it ever reaches `manifest.rs` or `sigils.rs`. Don't add normalization inside either storage layer.
- **`scope_covering` returns at most one scope, nearest wins.** An outer scope is a default for what has said nothing below it, never a second gate a change must also satisfy — don't build accumulating or "needs both" logic on top of it.
- **Sigils never live inside a repository, and scopes never live outside one.** `sigils.rs` takes `home` as a parameter and touches only files under it; `manifest.rs`/`scope.rs` touch only the committed manifest. Don't let either module cross into the other's territory.
- **Nothing in this crate enforces a scope boundary.** `scope.rs` and `sigils.rs` only say what a string is and what is held; no code here — or anywhere else in the workspace — checks a sigil against a scope and blocks or refuses anything. `claude_md.rs`'s own body says so explicitly, and a test pins that promise. Don't add enforcement here without also fixing that document and its test.
- **`pact.rs` and `load.rs` were read via prior summaries here, not in full.** Don't assume implementation details beyond what's stated above without opening the files yourself.
