# src

This is `warlock_tui`'s library crate: the terminal front end's pure core, plus the one binary (`main.rs`) that turns it into a running program, plus the two modal gates (confirm-on-quit, scope prompt) and the session/pact/scoping plumbing that sit in front of both. Everything except `claude.rs`, `terminal.rs`, `watch.rs`'s watcher handle, and `config.rs`'s stdin prompt is data and functions over data — no terminal, no clock read internally, no process spawned — which is what lets the whole UI be tested against in-memory buffers and hand-driven instants.

## What is here

- **`lib.rs`** — the crate's manifest of what it exports and why; read it first for the shape of the whole thing. States the one real architectural rule: TUI depends on `warlock_engine`, never the reverse.
- **`app.rs`** — `App`, the front end's state: a flattened, filtered, scrollable view over the engine's `Tree`, plus `reseat_on` for carrying that view across a freshly reloaded tree by path rather than by row index. Also `Chrome` (the fixed, per-session header line), `Row`, `Focus`, `Sigils`, `PactToggle`, `Run`.
- **`account.rs`** — `Account`, the running record of one pact: sections per directory, clocked lines per thing a pass did. Holds no clock of its own; every clock is computed against an `Instant` handed in by the caller.
- **`claude.rs`** — the *only* place in the codebase that spawns a child process. Runs the `claude` CLI as the engine's `Agent` implementation, with a documented multi-thread arrangement (writer/reader/waiter threads) to avoid pipe deadlocks and make a running child killable from another thread via `Cancel`.
- **`colour.rs`** — the fixed, hand-picked mapping from `NodeState` (and focus/guide lines) to terminal colours. Deliberately indexed (not theme-respecting) colours, because on this screen colour *is* the message.
- **`confirm.rs`** — the quit-confirmation gate: `QuitConfirm`/`Answer`/`Answered`, and the pure `answer_for` that says what one key does to it. Deliberately *not* a field on `App` — answering No must leave the app byte-for-byte as it was. Ctrl-C is explicitly out of scope here; it must be answered by the event loop before this mode is consulted.
- **`prompt.rs`** — the scope-entry field's sibling gate: `ScopePrompt`/`ScopeField`/`Edited`, and the pure `edit_for` that says what one key does to a field being typed into. No line-editing beyond append/backspace/submit/close — the cursor is always at the end. Judges nothing about whether typed text is a valid scope; that is the engine's `validate_scope`'s job alone.
- **`scoping.rs`** — the binary-side glue for the scope key, from keystroke to saved manifest: `scope_press` (what pressing `s` opens, gated the same way `pact_press` is), `scope_edit` (what a keystroke inside the open field does), and `scope_submit` (folds, judges via the engine, and writes `.warlock/pacts.toml` on the event loop's own thread — no worker, no reload, since a scope is one string on one manifest entry, not a model pass).
- **`ui.rs`** — pure rendering: `draw` builds one frame from an `App`, an `Account`, an `Instant`, a `QuitConfirm`, and now a `ScopePrompt` too (drawn last, over everything else, when open); `hit_test` maps a screen point back to a named region for mouse input.
- **`watch.rs`** — filesystem-watching split into an impure handle (`Watch`, wraps `notify`) and two pure decision types: `NodeSet` (which paths are Warlock's business — exactly the last walk's directories) and `WatchPolicy` (when a reload is owed — debounce + ceiling + one coalesced reload).
- **`error.rs`** — `Error`, the binary's whole error vocabulary; every variant renders as one line via `one_line`, because `main` prints exactly one line to a restored terminal. Shared by `main`, `pacting`, `session`, `config`, and `scoping`, not duplicated per subcommand.
- **`fixture.rs`** — test-only, hand-written `Tree` values (`tree`, `tree_after_a_run`) that `app.rs` and `ui.rs` tests assert exact output against. Not a loader or a fallback; never reachable outside `#[cfg(test)]`.
- **`main.rs`** — the binary. Owns the terminal's lifecycle, argument dispatch (`init`/`config`/`-h`/`--help`/anything else refused), the event loop, and nothing else. Long module doc explains the concurrency shape: a pact runs on a worker thread, progress arrives over a channel drained once per poll round, and the loop never blocks on it — plus how the quit-confirmation and scope-prompt gates sit in front of Esc/`q`/`s`, and how mouse capture is toggled and threaded through every frame.
- **`input.rs`** — pure translation from raw crossterm key/mouse events to `Action`/`MouseAction` enums, plus `press_for`, which layers the quit-confirmation gate (via `confirm.rs`) in front of `action_for`, and `mouse_action`, which goes inert entirely while either modal gate is open. No terminal I/O anywhere in this file.
- **`pacting.rs`** — orchestrates a pact/refresh run: spawns the worker thread, drives the engine's `pact_subtree`/`refresh_subtree`/`unpact_subtree`, translates worker events into `Account` updates, and reloads the tree from disk exactly once at the end.
- **`session.rs`** — `Scope` (root + repo root + `Chrome`, resolved once at startup), `reload_tree` (the *only* place the tree is re-read, and only from the event loop's thread), `Watched` (glues `Watch`/`WatchPolicy` to the loop), `sigils_held`/`sigils_under` (reads what this machine holds for the header, once, tolerating a broken config as `Sigils::Unknown` rather than failing the session), and manifest loading.
- **`config.rs`** — `warlock config`: the second subcommand, dispatched before any terminal setup. Prints what sigils this machine holds for the resolved repository, reads one line from stdin in cooked mode (so Ctrl-C/EOF behave like an ordinary shell prompt), and writes the machine-local sigil config under the home directory — never inside the repository. `home_directory()` here is the crate's one point where `HOME`/`USERPROFILE` becomes a path.
- **`terminal.rs`** — `TerminalGuard` and `install_panic_hook`: the one guaranteed spelling of "restore the terminal," run on every exit path including a panic. The guard also owns mouse-capture setup/teardown, since a terminal left reporting its mouse after warlock exits is the same class of mess as raw mode left on.

## What a reader has to know before changing anything

**The purity boundary is the whole design.** Only `claude.rs` spawns a process; only `main.rs`/`terminal.rs`/`watch.rs`'s `Watch`/`config.rs`'s stdin touch a real terminal, clock, OS watcher handle, or interactive stdin. Everything else — `App`, `Account`, `ui::draw`, `colour_for`, `WatchPolicy`, `confirm::answer_for`, `prompt::edit_for`, `input`'s translation functions, `scoping`'s pure decision functions — is a pure function of its arguments, including the current instant, which is *always* passed in rather than read via `Instant::now()` inside these modules. This is what lets minutes-long pacts and multi-second debounce windows be tested in microseconds. Don't reach for a clock or a terminal call inside these files; thread the value through instead.

**Two clocks, one rule.** Both `Account`'s per-line clocks and `WatchPolicy`'s debounce/ceiling timers follow the same discipline: freeze on the next event, tick against `now` only while still "live." Understand `account.rs`'s doc comment on this before touching either.

**Rows vs. tree.** `App` keeps `all_rows` (everything) and `rows` (filtered/collapsed view), rebuilt by `reflow` whenever filters or collapse state change; collapsed state is tracked by *path*, not row index, so it survives a rebuild. `reseat_on` is the one path for putting a view back onto a newly-loaded tree — selection, collapse, filters, and scroll all carry across by path with ancestor fallback. The header (`Chrome`) is deliberately *not* part of what a reload carries — it's fixed at session start on `Scope` and handed to `draw` separately, because neither the tree's identity nor the held sigils can change while warlock runs.

**Footer/panel messaging has one precedence rule**, enforced by `session::note`: a housekeeping line (reload failure, watcher-off notice) never overwrites whatever a pact run already said, because the pact's outcome is the news and everything else is bookkeeping.

**Three things — cancel, quit, and now two modal gates — layer on top of Esc/`q`/`s`.** Esc cancels a pact when one is running (worker finishes writing/hashing/saving what's already done); with nothing running, Esc and `q` open the quit confirmation, and only answering Yes actually quits. `s` opens the scope prompt instead, gated identically to a pact keypress (refused, not silently ignored, when a run is already in flight). Both gates are deliberately bypassed by Ctrl-C, which always leaves immediately — it's a key event in raw mode, not a signal, so it must be caught before either gate would swallow it as an inert character-with-modifier — and any key press while a pact is in flight suppresses the quit gate entirely. All exit paths route through one `Cancel`, dropped via `CancelGuard`, so every exit — including a panic — takes the child process down with it.

**Neither modal gate is a field on `App`, and that's load-bearing.** Answering No on the quit confirmation, or Esc on the scope prompt, must leave the app byte-for-byte as it was — the cheapest way to guarantee that is for `App` to never have heard the question was asked, rather than carefully restoring every touched field.

**A scope is not a pact.** `scoping.rs`'s `scope_submit` runs synchronously on the event loop's own thread between two frames — no worker thread, no channel, no account, no reload — because it is one string written into one manifest entry, unlike a pact which is minutes of model passes. It also deliberately triggers no reload: a scope changes no directory's state or colour, so re-walking the whole repository afterward would be wasted work.

**Colours are fixed and few on purpose**: exactly three state colours plus a focus colour plus a guide colour, all indexed rather than theme-respecting, all asserted pairwise-distinct in `colour.rs`'s tests. Adding a `NodeState` variant will fail `colour_for`'s exhaustive match at compile time — that's intentional; don't add a fallback arm.

**Mouse capture is toggleable at the `m` key**, and it's a fact this thread keeps about the terminal (not the app) because `App` copies get taken and restored around a pact run — a source of truth for "is the terminal reporting its mouse" has to survive that. `App` is handed a copy of it every frame purely so the footer can name the key by what pressing it will do next.

**Scopes vs. sigils, and where each is judged.** `scope.rs`/`config.rs` both defer to the engine's `validate_scope`/`validate_sigil` for what a legal string looks like — no length constant or character predicate is duplicated in this crate. `config.rs` folds typed text to lowercase before judging it (`Data-Plane` and `data-plane` are one holding); `scoping.rs` does the identical fold for the same reason, in the same place a person supplies a string.

**This is not an IDE.** No prompt box, no free-text input beyond the two narrow, purpose-built fields (scope text, sigil line); the panel is a freshness ledger (facts about what a pass did), not a chat transcript or a dashboard — no tokens, no turn counts shown, deliberately.
