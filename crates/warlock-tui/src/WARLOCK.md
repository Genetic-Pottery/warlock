# src

This is `warlock-tui`'s implementation directory: the crate `warlock_tui`, a front-end library that is deliberately terminal-free (`lib.rs`'s "minus the terminal"), plus the binary `warlock` in `main.rs` and its sibling modules that own the terminal, the CLI and the impure edges. Two build targets live here side by side — a library crate (`lib.rs` and everything it declares as a module) and a binary crate (`main.rs` and the modules it privately declares: `boundary`, `chatting`, `check`, `config`, `descent`, `editing`, `edits`, `error`, `input`, `pacting`, `query`, `running`, `scoping`, `session`, `standing`, `stubs`, `terminal`, `viewing`, `writing`) — and both are covered below.

## The library half (`warlock_tui`, declared from `lib.rs`)

`lib.rs` is the crate root: a long module-doc explaining the whole architecture (state as pure data and functions over it, terminal I/O confined to two agent modules) and then `mod` declarations plus a large curated set of `pub use` re-exports, each with its own doc comment, that make up the crate's public surface. It declares (and partly re-exports from): `account`, `app`, `claude`, `colour`, `composer`, `confirm`, `panel`, `prompt`, `submission`, `template`, `thread`, `ui`, `watch`, `wrap`, and — test-only — `fixture`.

- **`account.rs`** — `Account`, the record one pact run keeps of itself: a `Section` per directory, clocked `Line`s of what a pass was seen doing, an `Outcome` per section (`Wrote`/`Refused`/`Cancelled`), and a self-contained ticking-clock model (`Log`) shared with `thread.rs`. Also exports `size` (bytes formatted as `934 bytes`/`1.8 KB`) and `money`.
- **`app.rs`** — the largest single piece of front-end state: `App` (the flattened tree, selection, scroll, focus, panel and status), `Row`, `Chrome` (header line data), `Viewpoint`/`Status` (private), `Focus`, `Sigils`, `PactToggle`, `Run`, `RunHeader`, and the free function `reseat_on` that carries a view across a freshly-loaded tree. Pure state/logic only, no rendering.
- **`claude.rs`** — the transport layer: runs the `claude` CLI as a child process. Defines `ClaudeAgent` (implements the engine's `Agent` port for pact passes) and `ChatAgent` (implements `Converses` for chat turns), `Cancel`, `Activity`/`Activities`, the `Wired`/`Converses` traits, and a private `stream` submodule parsing `stream-json` output.
- **`colour.rs`** — `colour_for(NodeState) -> Color`: the one place the three state colours (and the focus/guide colours) are pinned as indexed terminal colours rather than theme-relative ones.
- **`composer.rs`** — `Composer` (the multi-line draft buffer at the foot of the panel: the draft, a byte-offset cursor `at`/`cursor`, the width it was last drawn at, and the muting), `Composed`, `compose_for` (the pure key-to-outcome function, including the six keys that move the cursor), the private `place`/`offset_at` maps between a byte offset and the (row, column) cell it is drawn at, and `COMPOSER_MAX_ROWS`.
- **`confirm.rs`** — the quit-confirmation gate: `Answer`, `QuitConfirm`, `Answered`, `answer_for`, deliberately kept off `App` so answering No leaves the app untouched.
- **`fixture.rs`** — test-only (`#[cfg(test)]`), private: two hand-written `Tree` fixtures (`tree()` and `tree_after_a_run()`) that the crate's own UI/app tests draw and walk against, so those tests need no real repository on disk.
- **`panel.rs`** — `Panel`, the right-hand pane's three cards (`account`, `thread`, `document`), `Showing`, `Mode` (Chat/Brief), the private `Card<T>`/`Shown` scrolling machinery, and `panel_offset_for`.
- **`prompt.rs`** — the scope prompt: `ScopeField`, `ScopePrompt`, `Edited`, `edit_for` — the same shape as `confirm.rs`, for typing a scope rather than answering yes/no.
- **`submission.rs`** — `Submitted` and `submitted_for`: what a submitted composer draft turns out to be (`/brief`, `/write`, `/chat`, a plain `Message`, or `Refused` with one explanatory line).
- **`template.rs`** — `DEFAULT_TEMPLATE` (the compiled-in brief shape), `brief_template` (reads `.warlock/brief-template.md` fresh on every call, falling back to the default), its `Error`, and `missing_sections` (checks a written document against a template's `## ` headings).
- **`thread.rs`** — `Thread`, the panel's conversation card: an ordered sequence of `Turn`s and warlock's own unclocked `Entry::Note`s, `Ending` (how a turn failed to answer), and `ending_for` mapping the engine's `agent::Error` onto it.
- **`ui.rs`** — the ratatui rendering module: the `draw` entry point, layout (`Areas`, `areas()`), all the `draw_*` functions for panel/tree/footer/composer and the three modal windows, hit-testing (`Hit`, `hit_test`), and the measurement functions (`tree_height`, `panel_height`, `panel_width`, `run_header_height`, `composer_height`) the app uses to size its own scroll windows before a frame is drawn.
- **`watch.rs`** — filesystem watching split into pure and impure halves: `NodeSet` (which paths matter, from the last tree walk) and `WatchPolicy` (when to reload, debounce/ceiling/coalescing) are pure; `Watch`/`Watching` own the real OS watcher handle.
- **`wrap.rs`** — `wrapped` and `rows`: breaking one panel line into as many rows as a given width needs, plus the `Shape`/`shape` description shared between wrapping and drawing so the two never disagree about where a line breaks.

## The binary half (`warlock`, declared from `main.rs`)

`main.rs` is the binary's entry point: `Cli`/`Command`/`ScopeCommand` (clap parsing), `main`, `status_for` (the exit-code table), `init` (the `warlock init` subcommand), `run` (the interactive event loop, built around a generic `Session<S: Screen, P, C>`), and `apply_mouse`. It dispatches to the sibling modules below rather than doing their work itself.

- **`boundary.rs`** — the one place "may this operator act here" is decided: `Reach` (`Here`/`HereAndBelow`), `Verdict` (`Open`/`Closed`/`ClosedBelow`), `verdict()`, and the shared wording functions `closed_scope_message`/`blocking_scopes_message`, called by both the panel (`session.rs`'s `closed_scope`) and the shell (`edits.rs`).
- **`chatting.rs`** — the chat/brief conversation state machine: `Chat<C>`, `Chatting`, `Asked`, `TurnEvent`, `spawn_turn`/`start_turn`/`run_turn`/`apply_turn` (the same spawn/start/run/apply shape as `pacting.rs`), and the `/brief`, `/chat`, `/write` command handling inside `Chat::compose`.
- **`check.rs`** — `warlock check <path>`: prints which scope covers a path, what this machine holds, and whether they meet, via `Checked`/`checked`/`checked_onto`, reusing the engine's `scope_covering`/`scope_opens_to` and nothing else.
- **`colour.rs` (crate root's `colour` — not present here as a binary module; already covered above under the library)** — n/a.
- **`config.rs`** — `warlock config`: the one-line-in, one-file-out prompt for sigils, via `configure`/`prompted`, `sigils_in` (the sole parser/validator entry), `Held`, and `preamble`/`holding` for the printed text.
- **`confirm.rs` (library)** — n/a, already covered above.
- **`descent.rs`** — `Descent` (`Pact`/`Refresh`/`Unpact`) and `descend()`: the single shared middle between the panel's worker-thread runs and the shell's `warlock pact`/`refresh`, guaranteeing one engine call and exactly one manifest save; also `carry_on` (reads a `Cancel` into the engine's `Pacting` verdict).
- **`editing.rs`** — the `e` keystroke: `edit_press`, `edit_target`, `editor_command` (parses `$EDITOR`), `run_editor` (spawns it), and `came_back` (reconciles tree/document card afterward).
- **`edits.rs`** — the headless writes `warlock unpact`, `warlock scope add`, `warlock scope remove`: the gate type `Opened` (cannot be built without the boundary check passing), `opened()`, `unpact`/`scope_add`/`scope_remove`, and the success-line formatters.
- **`error.rs`** — `Error`, the binary's whole error vocabulary reaching `main`, and `one_line` (the multi-line-to-one-line flattener every `Display` impl relies on).
- **`input.rs`** — pure keyboard/mouse translation: `Action`, `action_for`, `Pressed`, `press_for` (the gate ordering Ctrl-C, quit confirm, scope/write prompts, composer, then ordinary keys), `MouseAction`, `mouse_action`.
- **`pacting.rs`** — the pact/refresh key machinery: `Pact<P>`, `Running`, `Work`, `CancelGuard`, `PactEvent`, `Reporting` (the engine's `pact::Observer`), `Toggled`, and the worker-thread orchestration (`spawn_pact`, `run_pact`, `pact_press`, `refresh_press`, `drain`).
- **`panel.rs` (library)** — n/a, already covered above.
- **`prompt.rs` (library)** — n/a, already covered above.
- **`query.rs`** — `warlock stale`/`warlock fresh`: `Listing`, `list`, `listed_onto`, `state_word` (warlock's own vocabulary, deliberately not the engine's), and the shared `envelope`/`write_object`/`spelled` helpers also used by `check.rs`.
- **`running.rs`** — the headless `warlock pact`/`warlock refresh`: `Progress` (a `pact::Observer` printing plain lines), `Report` (failure summary), `listening` (Ctrl-C handling with `ctrlc`), `started`/`descended`/`ran`, and the public `pact`/`refresh` entry points.
- **`scoping.rs`** — the `s` key: `scope_press`, `scope_edit`, `scope_submit` (the actual manifest write), and `with_scope_on` (rebuilds a `Manifest` with one entry's scope changed).
- **`session.rs`** — `Scope` (the two roots + `Chrome` a session was loaded with), `Watched` (ties the library's `Watch`/`WatchPolicy` to the event loop's thread), `reload_tree`, `note` (footer precedence), `closed_scope` (the one place `p`/`r`/`s` ask the "here" boundary question), `sigils_held`/`sigils_under`, `load_manifest`, `load_app`.
- **`standing.rs`** — `Standing`: the shared prologue every subcommand opens with (working directory, repository root, manifest, home), the `FOR_*` tail constants for `Error::NoRepository`'s sentence, and the only two places in the binary that read `std::env`.
- **`stubs.rs`** — test-only in effect (used only by test code, though not itself gated): `Passing` and `Saying`, in-memory stand-ins for `ClaudeAgent`/`ChatAgent` that answer instantly with a fixed document/sentence, for tests that are not about the model transport itself.
- **`terminal.rs`** — the terminal lifecycle: the `Screen` trait (the seam between the real terminal and test doubles), `TerminalGuard` (raw mode + alternate screen + mouse capture, restored on `Drop`), `install_panic_hook`, and `restore_terminal`/`take_terminal` as the single spellings of teardown/setup.
- **`viewing.rs`** — the `v` key: `view_press`, the smallest of the three key modules — one capped read on the event loop's own thread, no worker, no write, no reload.
- **`writing.rs`** — the `/write` command's two halves: proposing a path (`proposed_path`, `slug_of`, `unfenced`, `next_number` and their private helpers — never fails, never writes) and actually writing (`write_opened`, `write_edit`, `write_submit`, `put`), plus the refusal/success line formatters (`wrote_line`, `stale_line`, `taken_rule`, `missing_line`, `failure_line`, etc.).
