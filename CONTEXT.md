## Vocabulary
- **Scope:** Any directory can be given a scope. A scope is associated with a team in Linear, and it covers its directory and everything below it, unless a nearer scope takes over. AI works only inside a scope, and only on a machine where that scope is open. A directory no scope covers is closed to every AI session. The TUI draws a covered directory green and an uncovered one grey.
- **Open / closed:** Whether AI can work in a scope on this machine. The open scopes are a local list in the warlock config, `open = [...]`, which a user changes freely with `warlock open` and `warlock close`. Every scope is closed until opened. Scopes are not a hard gate, they are a guardrail to keep the AI from running away in a team setting, and they can easily be side stepped because in real life there are many situations where you need to go around them. The final human gate is always a human reviewed PR so this method stays sane.
- **/brief:** Starts a conversation with warlock where you ideate a large portion of work. Warlock pushes back on your assumptions, and once the model says it has enough, warlock asks whether to write the brief to a chosen directory. Say no and keep talking; ask for it in your own words and the question comes back.
- **/push:** Pushes the written .md brief file to Linear as a Linear Project.
- **/draft:** Pulls a Linear Project and begins to cut it up into Linear Issues, if there are any open questions about the ticket the AI will prompt the user for more details.
- **/pull:** Pull an individual ticket which must has a customizable label meaning warlock can pull it, it must be assigned to the user, it must not be blocked by other tickets, once work begins it can be recovered from failure states, also work must be scoped to directories whose scopes are open on the user's machine.
