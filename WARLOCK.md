# warlock

The repository root: the top-level Rust workspace for Warlock — the freshness-ledger tool described in `README.md` — plus its licence, formatting policy, and the `CLAUDE.md` that defines how warlock's own vocabulary (pacts, freshness colours, scopes and sigils) is meant to be read and honoured while working in this codebase. All executable code lives one level down, under `crates/`, whose two members are `warlock-engine` (headless domain library) and `warlock-tui` (terminal front end and the only place a `claude` subprocess is spawned) — a dependency edge running one direction only, TUI → engine, never back.

## What is here

- **`README.md`** — the pitch and mental model: pacts, the fresh/stale/unpacted tree, the conversation-first workflow (talk the change through, get a brief and tickets, work a ticket, refresh to go from yellow back to green), the full key-bind reference for the TUI, and an explicit list of what Warlock is *not* — not autonomous, not a project generator, not an editor, and never a writer of a project's own `README.md`. Read this before opening `crates/`; it is the intent the code has to satisfy.
- **`Cargo.toml`** — the workspace manifest. Declares the two members and centralises `[workspace.package]`, `[workspace.lints]`, and `[workspace.dependencies]` so both crates inherit one set of rules instead of each declaring its own. This is where the project's hard rules live in enforceable form: `unsafe_code = "deny"` (no `unsafe` anywhere in Warlock), `missing_docs` / `unreachable_pub` / `missing_debug_implementations` all warn, `clippy::pedantic` runs as a group, `dbg_macro` warns. Every dependency entry carries a comment justifying its inclusion — a new shared dependency added without one is a review flag.
- **`Cargo.lock`** (54KB) — generated, workspace-wide; not hand-edited.
- **`rustfmt.toml`** — deliberately close to rustfmt defaults, pinned to `edition = "2024"` / `style_edition = "2024"` and `newline_style = "Unix"` for reproducible formatting across machines and CI; nothing nightly-only, since the local toolchain is Rust from nixpkgs stable with no rustup shims.
- **`LICENSE`** — Apache-2.0, standard text.
- **`CLAUDE.md`** — the project instructions this session was given, reproduced verbatim inside `warlock:begin`/`warlock:end` markers. It doubles as spec (what warlock's own product does: pacts, scopes, sigils, the three colours) and as operating instructions for whoever — human or model — works in this repo.

## What a reader has to know before changing anything

- **There is no code at this level.** Anything behavioural belongs under `crates/`. Changes made directly here are workspace wiring, licensing, or top-level policy only.
- **The three CI checks in `README.md`'s Contributing section are the whole gate**, and run locally exactly as they run in CI: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- **Lint changes belong in this `Cargo.toml`, not in a crate.** If a lint fires and feels wrong, the workspace-level lint table is the first place to look; any new `allow` anywhere in the tree must carry a comment saying why.
- **This project treats its own `README.md` as sacred** — per the "not a squatter" promise in `README.md` itself, Warlock the tool never writes to a project's `README.md`. Extend the same care when editing this one: it is authored prose, not a generated artifact, a different kind of change from editing a `WARLOCK.md`.
- **No scope/sigil enforcement exists yet anywhere in the tree.** The vocabulary in `CLAUDE.md` is defined and partially wired (the TUI can write a scope), but nothing currently checks a held sigil against a directory's scope and blocks or warns on a mismatch. Both `crates/` and its children's documents state this independently — trust it over assuming it has since landed.
- **This directory carries no scope of its own**, so ordinary sigil rules apply: work here is open unless a nearer pact below it says otherwise.
- **A stale node stays stale until repacted or refreshed**, and `p` (whole subtree) versus `r` (only the already-stale members of one pacted subtree) are different operations — check which one a given change actually needs.
- **Consult `crates/WARLOCK.md`** before making any change that isn't purely workspace-level wiring: it summarizes `warlock-engine` (headless domain library — freshness model, manifest format, hashing, model-pass seam, pact/refresh/un-pact operations) and `warlock-tui` (terminal front end, sole spawner of the `claude` subprocess) and the one-directional dependency edge between them.
